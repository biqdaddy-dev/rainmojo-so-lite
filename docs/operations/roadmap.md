## ขอบเขตของไฟล์นี้

`rainmojo-so-lite` เป็นโปรเจกต์ลูกของ `daddy-plugins` มี Git ของตัวเองและ remote สาธารณะของตัวเองที่
`biqdaddy-dev/rainmojo-so-lite` แผนงานนี้ครอบคลุม **เฉพาะงานของปลั๊กอินนี้** (สกิล, agent, สคริปต์, CI และ release
ของรุ่น Lite) งานระดับร่มอยู่ที่แผนงานของร่มและใช้รหัส `DP-`

รหัสงานของไฟล์นี้ใช้ `LITE-` เริ่มที่ `LITE-001` (เจ้าของสั่ง 2026-10-31) เพราะรหัส `DP-` ที่ยืมจากร่มชนกันข้าม repo
Dev Timeline ของ daddydock แยกงานตาม repo ไม่ใช่ตามคำนำหน้า (`DEV_TIMELINE_PLAN.md` ข้อ 3 และ 4)

งานเก่าของปลั๊กอินนี้ที่ใช้รหัส `DP-` (DP-001, DP-002, DP-015, DP-016, DP-017, DP-021) อยู่ใน PR เดิม, CHANGELOG
และ git log ปล่อยไว้ตามเดิม ไม่ไล่เลขใหม่

## ป้ายสถานะ

| ป้าย | ความหมาย | เงื่อนไขที่จะอยู่สถานะนี้ได้ |
|---|---|---|
| 🟢 | **เสร็จแล้ว** | ต้องมีคอมมิตหรือหลักฐานที่ตรวจสอบได้ และย้ายลงคลัง |
| 🔵 | **กำลังทำ** | ต้องมีวันที่เริ่มแบบ `YYYY-MM-DD` และห้ามค้างเกิน 14 วัน |
| 🟡 | **อยู่ในคิว** | ตัดสินแล้วว่าจะทำ รอลงมือตามลำดับ |
| ⚪ | **ยังไม่เริ่ม** | รับเข้ามาแล้ว ยังไม่จัดคิว |
| 🔴 | **ติดปัญหา** | ต้องระบุว่าติดอะไร |
| 🟣 | **รอตัดสินใจ** | ต้องเขียนคำถามที่รอคำตอบให้ชัด |

> ชม. (แผน) = ชั่วโมงทำงานจริงที่ประเมินไว้ (6 ชม. = 1 วันทำงาน), `-` = ยังไม่ประเมิน
> `เริ่ม (แผน)` / `เสร็จ (แผน)` เป็น `YYYY-MM-DD` ทุกแถว งานด่วนวันเดียวใส่วันนี้ทั้งสองช่อง
> งานด่วนที่ดันงานอื่นให้เลื่อนวันที่ของแถวที่ถูกดันในคอมมิตเดียวกัน (เจ้าของสั่ง 2026-10-30)
> Gantt ของ daddydock Dev Timeline อ่านสองคอลัมน์นี้ แถวที่ไม่มีวันที่ Dev Timeline ต้องเดาจากชั่วโมง

คอลัมน์ **หมวด** (ตาม DDK-481 ของ daddydock, เจ้าของสั่ง 2026-10-17) = ส่วนของปลั๊กอินที่งานนั้นอยู่
อยู่ต่อจาก `ID` ในทุกตารางของแผนงานและคลัง Dev Timeline ใช้กรองและจัดกลุ่มงาน ใช้ชื่อตามรายการนี้
สะกดเหมือนเดิมทุกครั้ง และเพิ่มชื่อใหม่เมื่อมีงานแบบใหม่จริงเท่านั้น:
`ci`, `skills`, `agents`, `content production`, `release`;
`-` = ไม่มีหมวด (เลี่ยงไว้) หมวดเรียงบน Dev Timeline ตามแถวแรกของหมวดนั้นในไฟล์นี้
ย้ายแถวลงคลังให้ย้ายหมวดไปด้วย
