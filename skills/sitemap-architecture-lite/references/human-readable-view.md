### ไม่กระทบ SEO

**ไม่มีอะไรเปลี่ยนเลยทั้งเรื่องการค้นพบ การ crawl การส่งไฟล์ และการเก็บเข้าดัชนี**
บอทไม่เคยรัน stylesheet อยู่แล้ว มันดึงไฟล์ แยกวิเคราะห์ XML แล้วอ่าน `<loc>` กับ `<lastmod>`
**สิ่งเดียวที่เปลี่ยนคือภาพที่คนเห็นตอนเปิดไฟล์ในแท็บเบราว์เซอร์** จากตารางสวยกลายเป็น XML ดิบ
Search Console ยังรับไฟล์เดิมต่อไป เพราะมันคือไฟล์เดิมจริง ๆ

**บอกความหนักแน่นของข้ออ้างนี้ให้ตรง** เพราะลูกค้าอาจเถียง
ไม่มีเสิร์ชเอนจินเจ้าไหนเคยเขียนประโยคว่าตัวเองไม่สนใจ `<?xml-stylesheet?>`
**ห้ามอ้างว่ามี** ข้ออ้างนี้ยืนบนข้อเท็จจริงต้นทางสองข้อแทน

1. **XML 1.0 นิยาม processing instruction ว่าเป็นคำสั่งถึงโปรแกรมที่มาอ่าน** ไม่ใช่เนื้อหาของเอกสาร
   โปรแกรมที่ไม่ได้ทำตามคำสั่งนั้นก็ข้ามไป เอกสารยังถูกต้องและเนื้อ element ไม่เปลี่ยน
2. **ทั้งหน้าภาพรวม sitemap และหน้าวิธีสร้างและส่ง sitemap ของ Google และโปรโตคอล sitemaps.org
   ไม่พูดถึงการแต่งหน้าตา XSL หรือภาพในเบราว์เซอร์เลยแม้แต่ที่เดียว** ข้อกำหนดของโปรโตคอลคือเข้ารหัส UTF-8
   มี node ราก `<urlset>` ที่ประกาศ namespace และมี `<loc>` ในทุก `<url>`
   แล้วระบุว่าแท็กอื่นทั้งหมดเป็นของไม่บังคับ **ไม่มีข้อกำหนดเรื่องหน้าตาให้ทำผิดได้ตั้งแต่ต้น**

นี่คือการเถียงจากสเปกที่หนักแน่น ไม่ใช่คำรับรองจากเจ้าของผลิตภัณฑ์ **ให้พูดแบบนั้น**

### เราเก็บคำสั่ง stylesheet กับไฟล์ xsl ไว้

คนที่ได้ยินว่า "Chrome จะฆ่า XSLT" จะมาขอให้ถอดบรรทัด `<?xml-stylesheet?>` ออกจาก sitemap
**อย่าถอด**

- **คำสั่งที่เบราว์เซอร์ไม่รองรับมันเฉย ๆ** เอกสารยังเป็น XML ที่ถูกต้อง
  บอทอ่านได้เนื้อหาเหมือนเดิมทุกไบต์ และไม่มีอะไร error
- **เบราว์เซอร์ที่ยังแปลงให้ ก็ยังเรนเดอร์ตารางให้อ่าน** และจะยังทำต่อไปจนแต่ละเอนจินถอดของตัวเอง
- ถอดออกต้องเสียทั้งการแก้ การ deploy และการแก้เทสต์ แล้วได้หน้าตาที่แย่ลงเร็วกว่าที่ควร
  **ไม่มีอะไรได้มาแลก**

บรรทัดนั้นค่อยถอดวันที่เอนจินตัวสุดท้ายเลิกรองรับแล้วไฟล์กลายเป็นของเกินจริง ๆ ไม่ใช่วันนี้
**สิ่งที่เปลี่ยนวันนี้คือวิธีที่เราขายมัน** stylesheet คือ**ของเสริมที่รู้วันหมดอายุแล้ว**
ไม่ใช่คำตอบของคำถามว่า "จะทำให้ sitemap อ่านรู้เรื่องได้ยังไง"
**เลิกยกมันเป็นแผนเรื่องความอ่านง่าย**

`assets/sitemap.xsl` ในสกิลนี้ยังพร้อมเอาไปวางได้เลย มันแยกทางตามชื่อ node ราก
ไฟล์เดียวจึงเรนเดอร์ได้ทั้งสองแบบ คือ `<sitemapindex>` เป็นตารางสองคอลัมน์
และ `<urlset>` เป็นตารางสามคอลัมน์ที่นับจำนวนภาษาสำรองให้ด้วย **คัดลอก เปลี่ยนสี แล้วเอาไปเสิร์ฟ
โดยรู้ไว้ว่ามันจะเลิกเรนเดอร์บน Chrome ตั้งแต่ 17 พฤศจิกายน 2026**

**สองอย่างในไฟล์นั้นตั้งใจทำ**

- **ไม่มี script ในไฟล์** ฟีเจอร์ที่ทุกคนอยากเพิ่มคือกดหัวตารางเพื่อเรียงลำดับ
  และวิธีที่ทุกคนนึกถึงคือใส่ `<script>` ลงไปตรง ๆ **บนเว็บที่ตั้ง Content-Security-Policy
  โดยไม่ได้อนุญาต `script-src 'unsafe-inline'` สคริปต์นั้นจะถูกบล็อกเงียบ ๆ
  แล้วหัวตารางก็จะกดไม่ติกเฉย ๆ โดยไม่มีอะไรขึ้นใน console ให้คนที่มารับช่วงต่อเห็น**
  ไฟล์ที่ให้มาจึงใช้ CSS ล้วน เพื่อให้ทำงานได้ภายใต้ CSP ที่เข้มงวด
  ถ้าการเรียงลำดับสำคัญกว่าเรื่องนั้น ให้ใส่สคริปต์เพิ่มเอง **แล้วเขียนหมายเหตุไว้ข้างที่ตั้ง CSP
  ว่าสองอย่างนี้ผูกกันอยู่**
- **ไม่ดึง CSS ฟอนต์ หรือรูปจากข้างนอกเลย** เพราะ stylesheet ต้องเรนเดอร์ให้ถูก
  ตอนที่มีคนเปิด URL ที่ทำไว้ให้บอทตรง ๆ ซึ่งบ่อยครั้งอยู่คนละบริบทกับหน้าเว็บปกติของแอป

**เสิร์ฟด้วย content type ที่ระบุชัดว่า `text/xsl` หรือ `application/xslt+xml`**
โฮสต์แบบไฟล์นิ่งเดาชนิดไฟล์ `.xsl` ผิดบ่อยมาก แล้วการแปลงก็พังเงียบ ๆ
เพราะแบบนี้การเสิร์ฟผ่าน route handler จึงดีกว่าวางเป็นไฟล์นิ่ง
**แต่ให้จำกัดเวลาที่ลงกับเรื่องนี้** เพราะผลตอบแทนหมดวันที่เบราว์เซอร์เลิกรัน XSLT
ถ้าโฮสต์ดื้อ ให้ไปทำหน้า HTML sitemap แทน

### คำตอบที่อยู่ยาว คือหน้า HTML sitemap จริง ๆ

**นี่คือของที่เราแนะนำ** ไม่ใช่ไฟล์ XML ที่แต่งหน้า แต่เป็น
**หน้าเว็บ HTML ธรรมดาที่ URL ของตัวเอง ลิสต์หน้าของเว็บออกมาเป็นลิงก์จริง**
มันอยู่รอดทุกการเปลี่ยนของเบราว์เซอร์เพราะไม่มีอะไรฉลาดอยู่ในนั้น
**มันพาลิงก์ภายในได้ ซึ่ง XML sitemap ทำไม่ได้** เพราะ `<loc>` เป็นสตริงในไฟล์ข้อมูล ไม่ใช่ลิงก์
และไม่ส่งสัญญาณลิงก์ภายในให้ใครเลย และมันมีประโยชน์กับคนที่เข้ามาจากการค้นหา
ซึ่งไฟล์ XML ดิบไม่เคยมี

- **อยู่ที่ไหน** URL ของตัวเองที่นิ่งและติดดัชนีได้ เช่น `/sitemap` หรือ `/site-index`
  **ห้ามอยู่ที่ `/sitemap.xml`** ซึ่งเป็นที่ของไฟล์ XML ตอบ 200 ตั้ง canonical ชี้ตัวเอง
  ไม่ตั้ง `noindex` และมีลิงก์จาก footer ทุกหน้า
- **ลิสต์อะไร** หน้าที่คนควรไปถึงได้ **โดยถามจากฟังก์ชันตัดสินความเป็นสาธารณะตัวเดียวกับที่
  XML sitemap เรียก** ฟังก์ชันเดียวตัดสินว่าอะไรเป็นสาธารณะ แล้วผลลัพธ์ทั้งสองฝั่งถามตัวนั้น
  **สองคิวรีจะเพี้ยนจากกัน แล้วความเพี้ยนจะโผล่มาเป็นหน้าฉบับร่างบนหน้าสาธารณะ**
  แล้วหักสิ่งที่ไม่มีคนอยากอ่านออก คือหน้าที่แบ่งหน้าของคลังเก่า หน้าแท็กและหน้าตัวกรองทุกการผสม
  หน้าหมวดหมู่บางที่ไม่มีเนื้อหาของตัวเอง และทุกอย่างที่ XML sitemap ตัดออกไปแล้ว
  เพราะ `noindex` หรือเพราะ canonical ชี้ไปที่อื่น
- **จัดกลุ่มยังไง** ตามประเภทเนื้อหาของเว็บนั้นเอง ใต้หัวข้อที่คนเข้าเว็บจำได้
  เรียงลำดับเหมือนที่เมนูหลักเรียง ในกลุ่มหนึ่งให้เรียงด้วยอะไรที่คนเดาได้
  เช่นตามตัวอักษรสำหรับเนื้อหาอ้างอิง หรือใหม่สุดก่อนสำหรับอะไรที่เรียงตามเวลา
  **เว็บหลายภาษาให้แยกหนึ่งหน้าต่อหนึ่งภาษา** แต่ละหน้าลิสต์ URL ของภาษานั้น
  และทำ hreflang อ้างกันครบทั้งวงระหว่างหน้าพวกนั้น **ห้ามปนหลายภาษาในรายการเดียว**
- **ใหญ่ได้แค่ไหน** เมื่อกลุ่มหนึ่งยาวเกินสองหน้าจอ **ให้ลิงก์ไปหน้ารวมของกลุ่มนั้น
  แทนที่จะยัด URL ทุกตัวลงไป** หน้าที่มีลิงก์ 3,000 ตัวคือกำแพงที่ไม่มีใครอ่าน
  และยังเกลี่ยค่าลิงก์ภายในที่มันมีออกไป 3,000 ทาง
  ถ้าทั้งเว็บยัดลงหน้าเดียวที่คนกวาดตาดูไหวไม่ได้ ก็ให้แยกเป็นหนึ่งหน้าต่อหนึ่งประเภทเนื้อหา
- **เมื่อไหร่ที่คุ้มทำ** เมื่อเมนูและลิงก์ภายในยังไปไม่ถึงทุกหน้าในสองสามคลิก
  เมื่อมีเนื้อหาประเภทที่เสี่ยงกำพร้า คือไปถึงได้ทางหน้ารวมที่แบ่งหน้าหายไปเรื่อย ๆ อย่างเดียว
  เมื่อเว็บใหญ่พอที่ไม่มีใครในทีมบอกจากความจำได้ว่าเผยแพร่อะไรไปแล้ว
  **เมื่อไหร่ที่ไม่คุ้ม** เว็บโบรชัวร์สิบสองหน้าที่ footer ลิสต์ทุกหน้าอยู่แล้ว
  ตรงนั้นมันคือเมนูซ้ำซ้อน **ให้บอกตรง ๆ ว่าไม่ต้องทำ ดีกว่าส่งของที่ไม่มีใครต้องการ**
- **เกี่ยวกันยังไงกับ XML sitemap** **มีทั้งคู่ และไม่มีตัวไหนแทนตัวไหน**
  XML sitemap คือสัญญากับเครื่อง ที่ส่งใน Search Console และเขียนไว้ใน `robots.txt`
  หน้า HTML มีไว้ให้คน และมีไว้ให้กราฟลิงก์ภายใน หน้า HTML เองก็เป็น URL หนึ่ง
  **จึงต้องอยู่ใน XML sitemap ด้วย** แต่ทางกลับกันไม่จริง
  **ห้ามเอาลิงก์ `sitemap.xml` ไปวางให้คนเห็นบนเว็บ** ลิงก์นั้นคือทางที่ทำให้คนเข้าเว็บ
  ไปจบลงที่การนั่งมอง XML ดิบแล้วแจ้งว่าเว็บพัง **HTML มีไว้ให้คน XML มีไว้ให้เครื่อง
  และทางเชื่อมระหว่างสองอย่างคือ Search Console ไม่ใช่แท็ก a**

### ถ้าลูกค้าอยากให้ภาพ XML ที่แต่งไว้ยังทำงานต่อ

**มีสี่ทาง ทุกทางมีอยู่จริงและไม่มีทางไหนฟรี**

- **แปลงฝั่งเซิร์ฟเวอร์ แล้วเสิร์ฟ HTML ที่ URL ของตัวเอง** รันการแปลงฝั่งเซิร์ฟเวอร์
  พ่น HTML ออกมา แล้วเผยแพร่ที่ URL ที่สอง เช่น `/sitemap-view`
  **ตัว XML ที่ `/sitemap.xml` คงเดิมเป๊ะ ๆ สำหรับทุกคนที่ขอ**
  วิธีนี้ต้องใช้ route handler ไม่ใช่ไฟล์นิ่ง และ**เป็นรูปแบบฝั่งเซิร์ฟเวอร์แบบเดียวที่เราแนะนำ**
  เพราะผลลัพธ์ที่คนอ่านได้ไปอยู่ที่ที่อยู่ของมันเอง ซึ่งก็คือหน้า HTML sitemap ข้างบนนั่นเอง
  เพียงแต่สร้างจากข้อมูล sitemap แทนที่จะสร้างจากโมเดลเนื้อหา
- **ใช้ CSS stylesheet แทน XSLT** `<?xml-stylesheet type="text/css"?>` ยังทำงานได้
  เพราะเบราว์เซอร์ถอด XSLT ไม่ได้ถอด CSS บน XML **นี่คือทางที่ Yoast เลือกใช้บน WordPress**
  ลูกค้าจะเคยเห็นและจะถามถึง มันถูกและเป็นการลดคุณภาพจริง ๆ ด้วย
  **เพราะ CSS สร้างลิงก์ไม่ได้** ทุก URL จะกลายเป็นข้อความที่กดไม่ได้
  และอะไรที่คำนวณขึ้นมา เช่นจำนวน URL หรือลิงก์กลับไปหน้า index จะหายไป
  **เป็นการประทังเวลา ไม่ใช่แผน**
- **ส่วนขยายของ Chrome** Chrome ขึ้นแถบเตือนพร้อมลิงก์ไปหาส่วนขยายที่เอา polyfill ของ XSLT
  มาใช้กับหน้า XML ดิบ **วิธีนี้แก้ภาพให้คนที่ติดตั้งคนเดียว ไม่แก้ให้คนอื่นเลย**
  เหมาะจะแนะนำทีมที่ต้องตรวจ sitemap ทุกวัน ใช้เป็นการตัดสินใจระดับเว็บไม่ได้
- **Origin Trial หรือ Enterprise Policy** ทั้งคู่มีจริงและทั้งคู่ชั่วคราว
  Origin Trial ให้เว็บเสิร์ฟโทเคนเพื่อใช้ XSLT ต่อหลัง Chrome 158
  Enterprise Policy ให้องค์กรที่คุมเครื่องพนักงานใช้ต่อ **ทั้งคู่หมดอายุที่ Chrome 176
  วันที่ 17 สิงหาคม 2027** มันซื้อเวลา ไม่ใช่จุดหมาย และสำหรับ sitemap
  มันคือการต่อท่อเยอะมากเพื่อยืดอายุตารางสวยไว้อีกเก้าเดือน

### ห้ามทำ

- **ห้ามเปลี่ยนไบต์ที่บอทอ่าน เพื่อแก้ปัญหาเรื่องการแสดงผล** XML คือสัญญา
- **ห้ามแทรก `<script>` ของ polyfill ลงใน sitemap** polyfill ทำงานด้วยการเติม `<script>`
  หนึ่งตัวเป็นลูกของ node ราก ซึ่งเป็นวิธีที่มีเอกสารรองรับและสมเหตุสมผลสำหรับฟีด RSS
  schema ของ sitemap ยอมให้มี element จาก namespace อื่นก่อน `<url>` ตัวแรกได้จริง
  จึงไม่ถึงกับผิดสเปกตรง ๆ
  **แต่มันก็ยังเป็นการเปลี่ยนไบต์ที่บอททุกตัวอ่าน เพื่อหน้าตาที่คนดูอย่างเดียว ซึ่งคือการแลกที่สกิลนี้ห้าม**
  และช่องยกเว้นนั้นตั้ง `processContents="strict"` ตัวตรวจที่หา declaration ของ element `script`
  ของ XHTML ไม่เจอก็จะฟ้อง **หน้าตาที่คนอ่านได้ควรไปอยู่ที่ URL ของมันเอง**
- **ห้ามให้ sitemap เปลี่ยนไปตาม user agent** ไม่แยกทางด้วย User-Agent
  ไม่ทำเคสพิเศษตามชื่อบอท ไม่เสิร์ฟ HTML ให้เบราว์เซอร์แล้วเสิร์ฟ XML ให้บอทที่ URL เดียวกัน
  **นั่นคือ cloaking ทั้งโดยกลไกและโดยรูปลักษณ์** และมันพังคุณสมบัติข้อเดียวที่ทำให้ sitemap
  ตรวจสอบย้อนได้ คือสิ่งที่เราดึงมาดูต้องเป็นสิ่งเดียวกับที่บอทได้รับ
- **ห้ามหนีไปใช้ header `Accept` เป็นช่องว่างด้วย** มันดูมีหลักการ
  **แต่เราไม่ได้คุมและไล่ครบไม่ได้ว่าบอทแต่ละตัวส่ง header `Accept` มาว่าอะไร**
  Google มีเอกสารเรื่อง `Accept-Encoding` ของบอทตัวเอง แต่ไม่มีเอกสารค่า `Accept` เลย
  จึงไม่มีใครรับประกันได้ว่าบอททุกตัวชอบ XML บอทตัวไหนที่จัด `text/html` ไว้เหนือ XML
  จะได้หน้า HTML ไปแทน sitemap **สอง URL หนึ่งรูปแบบต่อหนึ่ง URL**
