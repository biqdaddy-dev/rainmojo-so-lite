# วางโครง sitemap

**sitemap เป็นทั้งสัญญากับเครื่องจักรและเป็นหน้าจอไว้ไล่หาปัญหาในเวลาเดียวกัน**
โค้ดสร้าง sitemap ส่วนใหญ่ถูกเขียนครั้งเดียว แล้วโตเกินสิ่งที่มันถูกออกแบบมารองรับ
สุดท้ายกลายเป็นไฟล์ที่ไม่มีใครอยากเปิด มาตรฐานนี้ทำให้ทั้งสองหน้าที่ยังทำงานอยู่
คือบอทได้ไฟล์ที่ถูกสเปก คนได้ของที่เปิดอ่านได้

## ตัดสินรูปทรงก่อนเขียนโค้ด

**การแยกไฟล์ไม่ได้ดีกว่าโดยอัตโนมัติ** ตอบสี่ข้อนี้ก่อน เพราะคำตอบกำหนดทุกอย่างที่เหลือ

1. **มีกี่ URL วันนี้ และอีกหนึ่งปีจะมีกี่ URL** ถ้าหลักร้อยต้น ๆ การใช้ `<urlset>` ไฟล์เดียวคือคำตอบที่ซื่อสัตย์และง่ายกว่า
   การแยกไฟล์เริ่มคุ้มเมื่อไฟล์เดียวเริ่มดึงช้า สร้างใหม่ช้า หรือใหญ่จนกวาดตาดูไม่ไหว
2. **ประเภทเนื้อหาตามธรรมชาติของเว็บนี้คืออะไร** ประเภทที่เปลี่ยนคนละจังหวะกันคือประเภทที่คุ้มจะแยก
   เพราะนั่นคือจุดที่การสร้างใหม่แค่บางส่วนได้ผลตอบแทน
3. **เว็บนี้มีหลายภาษาไหม** ถ้ามี ภาษาคือแกนแยกที่สอง และ hreflang กลายเป็นของบังคับ ไม่ใช่ของแถม
4. **sitemap ของเว็บนี้เป็นคำประกาศว่าอะไรได้รับอนุมัติให้เป็นสาธารณะหรือเปล่า**
   บางระบบถือว่า sitemap คือรายการอนุญาตแบบเป๊ะ ๆ อะไรที่หลุดเข้าไปคือการเผยแพร่ผิดพลาด
   **ถ้าใช่ สัญญาข้อนี้ใหญ่กว่าความสะดวกทุกข้อในเอกสารนี้** ดูหัวข้อกับดักความถูกต้องข้างล่าง

ถ้าข้อ 1 ตอบว่า "เล็กและจะเล็กต่อไป" ให้ทำเฉพาะส่วนที่ได้ผลตอบแทนตอนนี้ คือ hreflang กับ stylesheet
แต่**ให้เขียนตัวสร้าง XML ที่ใช้ร่วมกันไว้ตั้งแต่แรก** วันที่จะแยกไฟล์จะได้เป็นการแก้ค่าตั้ง ไม่ใช่การเขียนใหม่
ลำดับแบบนี้มักเป็นคำตอบที่ถูก เพราะไฟล์ index ที่ทำเร็วเกินไปแล้วชี้ไปที่ไฟล์ย่อยไฟล์เดียวที่มี 8 URL
คือของที่มีแต่ต้นทุน

## หน้าไหนควรอยู่ใน sitemap

**sitemap คือรายการหน้าที่เราอยากให้ถูกเก็บเข้าดัชนี ไม่ใช่รายการหน้าทั้งหมดที่มีอยู่**
หน้าที่ตั้ง noindex ไว้ หน้าที่ตั้ง canonical ชี้ไปหน้าอื่น หน้าหมวดหมู่หรือแท็กที่ไม่มีเนื้อหาของตัวเอง
และหน้าที่ทำไว้ใช้ภายใน **ห้ามใส่** การใส่หน้าที่ noindex ลงใน sitemap คือการส่งสัญญาณขัดกันสองทาง
ให้ตัดสินเรื่องนี้ให้จบก่อนแล้วค่อยสร้างไฟล์ **ห้ามให้ตัวสร้าง sitemap เป็นคนตัดสินเองว่าอะไรควรติดดัชนี**

## เหตุผลที่แยกไฟล์ เมื่อถึงเวลาแยก

- **เพดานต่อไฟล์** โปรโตคอลกำหนดเพดานตายตัวไว้ที่ **50,000 URL และ 50 MB แบบไม่บีบอัด ต่อหนึ่งไฟล์**
  **ให้ตั้งเพดานของตัวเองไว้ต่ำกว่าเพดานโปรโตคอลมาก ๆ** เพื่อให้ทุกไฟล์ยังดึงเร็วและแยกวิเคราะห์เร็ว
  เลือกตัวเลขที่เปิดในแท็บเบราว์เซอร์แล้วยังไหว แล้วเขียนตัวเลขนั้นลงในเอกสารของเว็บนั้น
- **ประหยัดการ crawl** บอทที่สนใจเนื้อหาประเภทเดียว ดึงไฟล์เล็กไฟล์เดียวซ้ำ
  แทนที่จะไล่อ่านรายการ URL ทั้งก้อนเพื่อหาว่า `lastmod` ไหนเปลี่ยน
- **สร้างใหม่แค่บางส่วน** เนื้อหาประเภทเดียวเปลี่ยน ก็สร้างไฟล์เดียวใหม่
  ไฟล์เดียวก้อนใหญ่บังคับให้สร้างใหม่ทั้งก้อนทุกครั้งที่มีอะไรเปลี่ยน
- **คนอ่านรู้เรื่อง** การแยกตามประเภททำให้คำถามว่า "เว็บเราถูกเก็บดัชนีถูกต้องไหม"
  กลายเป็นตารางเล็ก ๆ ที่กวาดตาดูได้ **ข้อนี้มักเป็นเหตุผลจริงที่ทำให้คนเปิดโค้ด sitemap ตั้งแต่แรก**

## โครงไฟล์

**หนึ่ง index บวกหนึ่งไฟล์ย่อยต่อหนึ่งประเภทเนื้อหาต่อหนึ่งภาษา**
แบ่งหน้าเพิ่มก็ต่อเมื่อไฟล์นั้นจะเกินเพดานที่ตั้งไว้

```
sitemap.xml                  <- ตัว index ลิสต์ไฟล์ย่อยทุกไฟล์
sitemaps/pages-th.xml        <- หน้าคงที่และหน้าสองภาษา ฝั่งไทย
sitemaps/pages-en.xml
sitemaps/services-th.xml
sitemaps/services-en.xml
sitemaps/services-th-2.xml   <- โผล่ต่อเมื่อเกินเพดานเท่านั้น
```

กฎที่สำคัญ

- ประเภทและภาษาเป็นแกนแยกทั้งคู่ เมื่อเว็บมีหลายภาษา
- ท้ายชื่อไฟล์ที่แบ่งหน้าใช้ `-2` `-3` ต่อเมื่อจำเป็น **ไฟล์แรกไม่มีเลขต่อท้าย**
  URL เดิมที่มีอยู่แล้วจะได้ยังเปิดได้
- **ตัว index ใช้ path เดิมคือ `/sitemap.xml`** URL ที่เคยส่งไปให้ Search Console
  และบรรทัด Sitemap ที่มีอยู่แล้วใน `robots.txt` จะได้ยังทำงานต่อ
  ข้อนี้แหละที่ทำให้ย้ายโครงได้จบในการแก้ครั้งเดียวอย่างปลอดภัย

## รูป XML

### ตัว index

```xml
<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="/sitemap.xsl"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://example.com/sitemaps/services-th.xml</loc>
    <lastmod>2026-08-12T16:49:33+00:00</lastmod>
  </sitemap>
</sitemapindex>
```

มีแค่ `<loc>` กับ `<lastmod>` **โปรโตคอลไม่มีช่องสำหรับจำนวน URL**

### ไฟล์ย่อย

ประกาศ namespace `xhtml` ทุกครั้งที่รายการในไฟล์มีภาษาสำรอง

```xml
<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="/sitemap.xsl"?>
<urlset
  xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
  xmlns:xhtml="http://www.w3.org/1999/xhtml">
  <url>
    <loc>https://example.com/services/accounting</loc>
    <xhtml:link rel="alternate" hreflang="th"
      href="https://example.com/services/accounting" />
    <xhtml:link rel="alternate" hreflang="en"
      href="https://example.com/en/services/accounting" />
    <xhtml:link rel="alternate" hreflang="x-default"
      href="https://example.com/services/accounting" />
    <lastmod>2026-08-12T16:49:33+00:00</lastmod>
  </url>
</urlset>
```

**hreflang ต้องอ้างกันครบทั้งวง** ทุกกลุ่มภาษาสำรองต้องลิสต์ทุกภาษารวมทั้งภาษาของตัวเอง
และกลุ่มชุดเดียวกันนั้นต้องปรากฏบนรายการของสมาชิกทุกตัว
**การประกาศทางเดียวแย่กว่าไม่ประกาศเลย เพราะเครื่องมือค้นหาจะทิ้งทั้งกลุ่ม**
ถ้าโค้ดเดิมพ่น hreflang ใน `<head>` ของ HTML อยู่แล้ว **ให้เรียกตัวคำนวณตัวเดิมนั้นมาใช้ซ้ำ
ห้ามเขียนตัวที่สอง** ไม่งั้นสองที่จะค่อย ๆ ไม่ตรงกัน

**ตัด `<priority>` กับ `<changefreq>` ออก** Google ประกาศไว้เองว่าไม่อ่านทั้งสองช่อง
ตัดออกแล้วไฟล์เล็กลงและหมดช่องที่ไม่มีใครใช้ไปหนึ่งช่อง

### รายการวิดีโอ

ประกาศ `xmlns:video="http://www.google.com/schemas/sitemap-video/1.1"` บน `<urlset>`
ของไฟล์ที่มีรายการวิดีโอ **และประกาศเฉพาะไฟล์นั้น**
หนึ่ง `<video:video>` ต่อหนึ่งวิดีโอ วางซ้อนอยู่ในรายการของหน้าที่วางวิดีโอนั้น
**`<loc>` ยังเป็นหน้าที่คนดู ไม่ใช่ไฟล์สื่อ**

```xml
<url>
  <loc>https://example.com/videos/accounting-basics</loc>
  <video:video>
    <video:thumbnail_loc>https://example.com/thumbs/accounting-basics.jpg</video:thumbnail_loc>
    <video:title>Accounting basics in 10 minutes</video:title>
    <video:description>Double-entry explained for first-time founders.</video:description>
    <video:content_loc>https://example.com/media/accounting-basics.mp4</video:content_loc>
    <video:player_loc>https://example.com/embed/accounting-basics</video:player_loc>
  </video:video>
  <lastmod>2026-08-12T16:49:33+00:00</lastmod>
</url>
```

กฎของแต่ละช่อง **ให้ตัวสร้างตรวจทุกข้อก่อนเขียนไฟล์ รายการที่ผิดจะได้ทำให้ build ล้ม
แทนที่จะหลุดขึ้นเว็บไป**

- **ต้องมีต่อหนึ่งรายการ** `video:thumbnail_loc`, `video:title`, `video:description`
  และอย่างน้อยหนึ่งอย่างระหว่าง `video:content_loc` ซึ่งเป็น URL ไฟล์สื่อจริง
  กับ `video:player_loc` ซึ่งเป็น URL ตัวเล่นที่ฝังได้ **มีทั้งคู่ให้ใส่ทั้งคู่**
- `video:title` ตรงกับชื่อวิดีโอบนหน้าที่วางมันไว้ `video:description` ตรงกับคำอธิบายวิดีโอบนหน้านั้น
  และยาวไม่เกิน 2,048 ตัวอักษร
- **`video:content_loc` และ `video:player_loc` ห้ามเท่ากับ URL ของหน้าใน `<loc>`**
  ทั้งคู่ต้องวิ่งไปถึงไฟล์ที่ดึงได้จริงและคนละตัวกับหน้าที่คนดู ไม่งั้นบอทดึงไฟล์สื่อไม่ได้
- `video:thumbnail_loc` ต้องเป็นภาพปกตัวเดียวกับที่ markup บนหน้าประกาศไว้
  **ให้คำนวณทั้งสองที่จากฟังก์ชันเดียวกัน** ด้วยเหตุผลเดียวกับ hreflang
- **ถ้าวิดีโอเป็นเนื้อหาประเภทหนึ่งของเว็บจริง ๆ ให้แยกไฟล์ย่อยของมันเอง** เช่น `sitemaps/videos-th.xml`
  ภายใต้กฎการแยกและเพดานเดียวกัน namespace วิดีโอจะได้อยู่เฉพาะที่ที่ใช้จริง
  ส่วนวิดีโอตัวเดียวบนหน้าธรรมดา ให้อยู่ในรายการของหน้านั้นตามปกติ

ข้อกำหนดของตัววิดีโอเอง เช่นภาพปกและข้อที่ทำให้ถูกตัดสิทธิ์ อยู่ที่ `seo-video-lite`

## XSL stylesheet

คำสั่ง `<?xml-stylesheet?>` บอกให้ **เบราว์เซอร์** รัน XSLT ฝั่งผู้ใช้ก่อนวาดหน้า
**บอทไม่สนใจมันเลยและอ่าน XML ข้างใต้ตรง ๆ** ไฟล์เดียวจึงเป็นทั้งของที่เครื่องอ่านได้และคนอ่านได้
และการแต่งหน้าตาไม่เปลี่ยนสิ่งที่บอทได้รับแม้แต่นิดเดียว

`assets/sitemap.xsl` ในสกิลนี้พร้อมเอาไปวางได้เลย มันแยกทางตามชื่อ node ราก
ไฟล์เดียวจึงเรนเดอร์ได้ทั้งสองแบบ คือ `<sitemapindex>` เป็นตารางสองคอลัมน์
และ `<urlset>` เป็นตารางสามคอลัมน์ที่นับจำนวนภาษาสำรองให้ด้วย **คัดลอก เปลี่ยนสี แล้วเอาไปเสิร์ฟ**

**สองอย่างในไฟล์นั้นตั้งใจทำ**

- **ไม่มี script ในไฟล์** ฟีเจอร์ที่ทุกคนอยากเพิ่มคือกดหัวตารางเพื่อเรียงลำดับ
  และวิธีที่ทุกคนนึกถึงคือใส่ `<script>` ลงไปตรง ๆ **บนเว็บที่ตั้ง Content-Security-Policy
  โดยไม่ได้อนุญาต `script-src 'unsafe-inline'` สคริปต์นั้นจะถูกบล็อกเงียบ ๆ
  แล้วหัวตารางก็จะกดไม่ติกเฉย ๆ โดยไม่มีอะไรขึ้นใน console ให้คนที่มารับช่วงต่อเห็น**
  ไฟล์ที่ให้มาจึงใช้ CSS ล้วน เพื่อให้ทำงานได้ภายใต้ CSP ที่เข้มงวด
  ถ้าการเรียงลำดับสำคัญกว่าเรื่องนั้น ให้ใส่สคริปต์เพิ่มเอง **แล้วเขียนหมายเหตุไว้ข้างที่ตั้ง CSP
  ว่าสองอย่างนี้ผูกกันอยู่**
- **ไม่ดึง CSS ฟอนต์ หรือรูปจากข้างนอกเลย** เพราะ stylesheet ต้องเรนเดอร์ให้ถูก
  ตอนที่มีคนเปิด URL ที่ทำไว้ให้บอทตรง ๆ ซึ่งบ่อยครั้งอยู่คนละบริบทกับหน้าเว็บปกติของแอป

**เสิร์ฟด้วย content type ที่ระบุชัดว่า `text/xsl` หรือ `application/xslt+xml`**
โฮสต์แบบไฟล์นิ่งเดาชนิดไฟล์ `.xsl` ผิดบ่อยมาก แล้วการแปลงก็พังเงียบ ๆ
เพราะแบบนี้การเสิร์ฟผ่าน route handler จึงดีกว่าวางเป็นไฟล์นิ่ง

## กับดักความถูกต้อง

**กลุ่มนี้คือกลุ่มที่กินเวลาจริง ตรวจทุกข้อก่อนส่ง**

- **สัญญาว่าเป็นรายการอนุญาต** ถ้า sitemap คือคำประกาศว่า URL ชุดนี้เท่านั้นที่ได้รับอนุมัติให้เป็นสาธารณะ
  **การแยกไฟล์ต้องไม่กลายเป็นแหล่งความจริงที่สองที่หลวมกว่าเดิม**
  ให้มีฟังก์ชันเดียวที่ตัดสินว่าอะไรเป็นสาธารณะ แล้วให้ไฟล์ย่อยทุกไฟล์เรียกฟังก์ชันนั้น
  **ไฟล์ย่อยที่เขียน query ของตัวเอง คือที่ที่วันหนึ่งฉบับร่าง หน้าที่ถูกถอนไปแล้ว
  หรือ URL ของลูกค้าอีกรายจะโผล่มา**
- **ห้ามเชื่อ `Host` header ที่วิ่งเข้ามาเพื่อประกอบ URL เต็ม** ให้ใช้ origin ที่ตั้งค่าไว้ของเว็บนั้น
  **URL ที่ประกอบจาก Host คือวิธีที่ระบบหนึ่งไปประกาศชื่อโฮสต์ของอีกระบบหนึ่ง
  และมันผ่านการทดสอบในเครื่องทุกครั้ง**
- **`robots.txt` ชี้ไปที่ตัว index อย่างเดียว ห้ามชี้ไปที่ไฟล์ย่อยรายไฟล์**
  เรื่อง robots ทั้งไฟล์ให้ดูที่ `aiso-crawlers-lite`
- **ตรวจ XML ดิบด้วยการยิง HTTP ธรรมดา ไม่ใช่ดูแค่ในแท็บเบราว์เซอร์**
  **หน้าจอในเบราว์เซอร์สวยสมบูรณ์ได้ทั้งที่ XML ข้างใต้พัง** เพราะการแปลงทำงานบนต้นไม้ที่ถูก parse แล้ว
  ซึ่งเป็นคนละอย่างกับที่บอทเห็น
- **เทียบก่อนลบ sitemap เดิม** เอารายการ URL ทั้งหมดที่ไฟล์เก่าพ่นออกมา
  ไปเทียบกับผลรวมของไฟล์ย่อยชุดใหม่ ยืนยันว่าไม่มีอะไรหายและไม่มีอะไรซ้ำ
  **ให้ลบของเก่าในการแก้ครั้งเดียวกับที่ต่อ route ใหม่ จะได้ไม่มีช่วงที่มี sitemap สองชุดพูดไม่ตรงกัน**
- **แก้ test ในการแก้ครั้งเดียวกัน** test ตัวไหนที่อ่านไฟล์ sitemap เดิมจาก path
  หรือตรวจกับเอกสารแบนไฟล์เดียว **มันจะยังผ่านอยู่ทั้งที่ไม่ได้ทดสอบอะไรเลย**
  และไฟล์ test ใหม่ไม่ได้ปกป้องอะไรเลยจนกว่าจะถูกเรียกในสคริปต์ที่ CI รันจริง
- **`lastmod` ต้องพูดความจริง** เวลาที่เปลี่ยนทุกครั้งที่ build **สอนให้บอทเลิกสนใจช่องนี้**
  ถ้ายังไม่มีระบบติดตามการแก้รายรายการ ให้ใช้เวลาสแนปช็อตเดียวที่ซื่อสัตย์แล้วบอกไว้ตรง ๆ
  ดีกว่าแต่งความละเอียดรายบรรทัดที่ข้อมูลจริงไม่มี

## การทำในเฟรมเวิร์กต่าง ๆ

อ่าน `references/framework-notes.md` สำหรับรายละเอียดรายเฟรมเวิร์ก

แก่นที่ย้ายไปใช้ที่ไหนก็ได้คือ **เขียนตัวสร้าง XML ตัวเดียวใช้ร่วมกัน**
พ่นออกมาเป็นฟังก์ชันประมาณ `buildUrlsetXml()` กับ `buildSitemapIndexXml()` แล้วให้ทุกไฟล์เรียกตัวเดียวกันนี้
**การตัดสินใจข้อเดียวนี้คือสิ่งที่กันไม่ให้คำสั่ง stylesheet การประกาศ namespace และรูปแท็ก
ค่อย ๆ เพี้ยนไปคนละแบบระหว่างไฟล์เมื่อโค้ดโตขึ้น**

## checklist ตอนย้ายระบบ

- [ ] ไล่ว่ามีประเภทเนื้อหาอะไรและภาษาอะไรบ้าง แล้วเลือกแกนแยก (ประเภทอย่างเดียว ภาษาอย่างเดียว หรือทั้งคู่)
- [ ] ตั้งเพดาน URL ต่อไฟล์ของเว็บนี้ให้ต่ำกว่าเพดานโปรโตคอลมาก ๆ แล้ววางแผนชื่อไฟล์ที่แบ่งหน้าไว้ก่อนที่ประเภทไหนจะเข้าใกล้เพดาน
- [ ] เขียนตัวสร้าง XML ตัวเดียวที่ครอบทั้งรูป index และรูป urlset
- [ ] ยืนยันว่าเครื่องมือสร้าง sitemap ที่เฟรมเวิร์กมีให้ พ่น node ราก `<sitemapindex>` และแนบคำสั่ง stylesheet ได้ไหม ถ้าอย่างใดอย่างหนึ่งทำไม่ได้ ให้เขียน XML ดิบตอบเอง
- [ ] ทำ stylesheet ไฟล์เดียวที่แยกทางตามชื่อ node ราก แล้วเสิร์ฟด้วย content type `text/xsl` ที่ระบุชัด
- [ ] รักษา hreflang ให้อ้างกันครบทั้งวงหลังแยกไฟล์ โดยเรียกตัวคำนวณเดิมมาใช้ซ้ำ
- [ ] ถ้าเว็บมีวิดีโอ ให้พ่นช่องที่บังคับครบ และประกาศ namespace วิดีโอเฉพาะไฟล์ที่มีรายการวิดีโอจริง
- [ ] ให้ `robots.txt` ชี้ไปที่ตัว index อย่างเดียว
- [ ] ตรวจ XML ดิบด้วยการยิง HTTP ธรรมดา
- [ ] เทียบรายการ URL ของเก่ากับผลรวมของใหม่ก่อนลบอะไร
- [ ] ทดสอบการแบ่งหน้าซ้ำ ด้วยการจงใจทำให้ประเภทหนึ่งโตเกินเพดาน

## เขียนไฟล์ส่งมอบ

ชื่อไฟล์ต้องเป็นแบบนี้

```
work/{domain}/(00-baseline|01-current)/{domain}_sitemap-architecture_{YYYY-MM-DD}.md
```

1. **สภาพปัจจุบัน** ตอนนี้มี sitemap แบบไหน กี่ไฟล์ กี่ URL อะไรที่ตรวจไม่ได้
2. **รูปทรงที่เลือก** พร้อมเหตุผลจากสี่ข้อในหัวข้อแรก และเพดานต่อไฟล์ที่ตั้งไว้สำหรับเว็บนี้
3. **โครงไฟล์ที่เสนอ** เขียนเป็นผังโฟลเดอร์
4. **ตัวอย่าง XML** ของ index และของไฟล์ย่อย ที่ใช้ค่าจริงของเว็บนี้
5. **กับดักที่เว็บนี้ติดอยู่** จากรายการกับดักความถูกต้อง พร้อมวิธีแก้รายข้อ
6. **checklist ตอนย้ายระบบ** เป็นช่องติ๊ก
7. **ส่งต่อให้สกิลไหน**

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## ขอบเขต ใครดูอะไร

**สกิลนี้ดู** โครงไฟล์ รูปของ XML ตัว stylesheet และการตัดสินใจว่าจะแยกไฟล์หรือยังไม่ต้อง

| เรื่อง | ใครดู |
|---|---|
| ตรวจ sitemap ที่มีอยู่แล้วบนเว็บจริงว่ามีปัญหาอะไร | `technical-audit-lite` |
| ไฟล์ `robots.txt` ที่จะเอาขึ้นเว็บ และการเข้าถึงของบอท | `aiso-crawlers-lite` |
| ข้อกำหนดของตัววิดีโอเอง ทั้งภาพปกและข้อที่ทำให้ถูกตัดสิทธิ์ | `seo-video-lite` |
| สร้าง sitemap ชุดใหม่หลังย้ายเว็บ | มาจาก `seo-migration-lite` |

**ลำดับในสายงาน** `technical-audit-lite` เป็นคนบอกว่า sitemap ปัจจุบันมีปัญหา แล้วส่งงานรื้อโครงมาที่นี่
`seo-migration-lite` ส่งงานสร้างชุดใหม่มาที่นี่หลังย้ายเว็บ และเมื่อทำเสร็จให้กลับไปให้
`technical-audit-lite` ตรวจว่าของใหม่ทำงานจริง

## กฎ

- **ถ้าดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย ถ้าเขียนผิดผู้ใช้จะสรุปกลับด้าน
- **ทำได้บางส่วนต้องส่งส่วนนั้นเสมอ** ห้ามส่งตารางที่ทุกช่องว่าง และห้ามปฏิเสธทั้งงานเพราะขาดข้อมูลบางอย่าง ให้ติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม · การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์
- **ห้ามใส่หน้าที่ noindex หรือหน้าที่ canonical ชี้ไปที่อื่น ลงใน sitemap** เป็นสัญญาณขัดกัน
- **ห้ามแยกไฟล์เพราะดูดีกว่า** ต้องตอบสี่ข้อในหัวข้อแรกได้ก่อนว่าแยกแล้วได้อะไร
- **ห้ามลบ sitemap เดิมก่อนเทียบรายการ URL ครบ**
- **ห้ามสรุปว่า sitemap ใช้ได้จากการเปิดดูในเบราว์เซอร์อย่างเดียว** ต้องยิง HTTP ดู XML ดิบ
- **ห้ามแก้ไฟล์บนเว็บจริง** สกิลนี้ออกแบบ เขียนตัวอย่าง และเขียนรายงาน คนเป็นผู้เอาขึ้นเว็บ
- ถ้าข้อมูลไม่พอให้เขียนตรง ๆ ว่าไม่พอ และบอกว่าต้องใช้อะไรเพิ่ม
