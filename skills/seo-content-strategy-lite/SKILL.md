# Content Strategy

ตอบคำถามเดียวคือ **ควรสร้างเนื้อหาอะไร รูปแบบไหน เรียงลำดับอย่างไร ถึงจะชนะคู่แข่งที่ติดอันดับอยู่แล้ว**

## ข้อมูลที่ต้องมีก่อนเริ่ม

| ต้องมี | ถ้าไม่มี |
|---|---|
| คำค้นเป้าหมาย | แนะนำรัน `seo-keyword-research-lite` ก่อน |
| URL คู่แข่ง | ให้ผู้ใช้ค้นคำค้นหลักใน Google เองแล้วส่ง URL ที่ติดหน้าแรกมา สกิลนี้ไม่มีเครื่องมือค้นเว็บ |
| เป้าหมายธุรกิจ | ถามผู้ใช้ตรง ๆ ถ้ายังไม่ได้ ให้เขียนกำกับว่าส่วนไหนของแผนอิงสมมติฐาน |

ก่อนเริ่ม ให้ไล่หาไฟล์เดิมใน `work/{domain}/` ด้วย Glob และ Grep ถ้ามีผลคำค้นอยู่แล้วให้ใช้ของจริง อย่าถามซ้ำ

ขาดข้อใดข้อหนึ่ง **ห้ามหยุดทั้งงาน** ให้ถามหนึ่งรอบ ถ้ายังไม่ได้ ให้ทำส่วนที่ข้อมูลรองรับแล้วส่งเท่านั้นก่อน
เช่น ไม่มี URL คู่แข่ง ก็ยังจัดกลุ่มคำค้น วางโครง Pillar และ Cluster เขียนสเปกรายชิ้น และเรียงลำดับได้
แล้วเว้นหัวข้อช่องว่างคู่แข่งไว้ พร้อมบอกว่าต้องได้ URL มาก่อนถึงจะเติมได้
ติดป้ายทุกข้อในรายงานว่า **ยืนยันแล้ว** คือดูจากหน้าเว็บจริง หรือ **ต้องยืนยันเพิ่ม** คือยังอิงสมมติฐาน
**การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์**

## ขั้นที่ 1 แยกคู่แข่งให้ครบ 4 แบบ

| แบบ | คือใคร |
|---|---|
| คู่แข่งตรง | ขายสินค้าหรือบริการเดียวกัน กลุ่มลูกค้าเดียวกัน |
| คู่แข่งทางอ้อม | แก้ปัญหาเดียวกันด้วยวิธีอื่น |
| คู่แข่งด้านเนื้อหา | ติดอันดับคำค้นเดียวกับเรา ไม่ว่าจะขายอะไร |
| คู่แข่งด้านความน่าเชื่อถือ | แหล่งอ้างอิงที่คนในวงการยอมรับ เช่น เว็บสมาคม เว็บโรงพยาบาล |

**คู่แข่งด้านเนื้อหาสำคัญที่สุดสำหรับงานนี้** เพราะเป็นคนแย่งพื้นที่ผลค้นหาจริง แม้ไม่ได้ขายแข่งกับเรา

## ขั้นที่ 2 อ่านเนื้อหาคู่แข่งแล้วหาช่องว่าง

เปิดหน้าที่ติดอันดับด้วย WebFetch แล้วบันทึกต่อหน้า ประเด็นที่ครอบคลุม โครง heading
รูปแบบที่ใช้ จุดแข็ง และจุดที่เขียนตื้นหรือไม่ตอบคำถามผู้อ่าน จากนั้นสรุปช่องว่าง 4 ประเภท

| ช่องว่าง | วิธีสังเกต |
|---|---|
| หัวข้อ | ประเด็นที่ผู้อ่านถามจริงแต่ไม่มีใครเขียนละเอียด |
| รูปแบบ | ทุกเจ้าเขียนบทความยาว แต่ไม่มีใครทำตารางเทียบหรือ checklist |
| กลุ่มผู้อ่าน | ทุกชิ้นเขียนให้มือใหม่ แต่ไม่มีของสำหรับคนที่ใกล้ตัดสินใจ |
| คำค้น | คำค้นที่หน้าอันดับต้นเขียนอ่อนหรือไม่ตรง intent |

ทุกช่องว่างต้องอ้าง URL ที่เปิดอ่านจริงกำกับไว้ ถ้าอ้าง URL ไม่ได้ แปลว่ายังไม่ใช่ช่องว่าง แต่เป็นการเดา

ปิดขั้นนี้ด้วย **ความได้เปรียบของเรา** หนึ่งย่อหน้า ว่ามุมไหนที่เราพูดได้จากประสบการณ์จริงแต่คู่แข่งพูดไม่ได้

## ขั้นที่ 3 วางแผน semantic SEO

จัดกลุ่มคำค้นทั้งหมดเป็น 4 กลุ่ม

| กลุ่ม | ใช้ทำอะไร |
|---|---|
| คำหลัก | แกนของหน้า Pillar |
| คำรอง | หัวข้อ H2 หรือหัวข้อ Cluster |
| Long-tail คำถามยาวเจาะจง | ชิ้นตอบคำถามเฉพาะ หรือ FAQ |
| คำแวดล้อมเชิงความหมาย เช่น ชื่อเฉพาะ ศัพท์วงการ | โรยในเนื้อหาให้ AI เข้าใจบริบท ไม่ใช่ยัดคำหลักซ้ำ |

แล้วจับคู่ทุกคำค้นกับช่วงการตัดสินใจ

| ช่วง | คำถามในใจผู้อ่าน | รูปแบบที่เหมาะ | ปลายทางของ CTA |
|---|---|---|---|
| รู้จักปัญหา | สิ่งนี้คืออะไร ทำไมถึงเกิด | บทความอธิบาย คู่มือพื้นฐาน | ชวนอ่านชิ้นถัดไป |
| เปรียบเทียบ | แบบไหนดีกว่า ต่างกันตรงไหน | ตารางเทียบ รีวิว ข้อดีข้อเสีย | ชวนดูหน้าบริการ |
| ตัดสินใจ | เจ้าไหนดี เริ่มยังไง | หน้าบริการ กรณีศึกษา หน้าราคา | ชวนติดต่อหรือจอง |

## ขั้นที่ 4 วางโครง Pillar และ Cluster

- **Pillar** หน้าหลักของหัวเรื่องใหญ่ ครอบคลุมภาพรวม หนึ่งหัวเรื่องมีหนึ่ง Pillar
- **Cluster** บทความลูกเจาะประเด็นย่อยประเด็นเดียวให้ลึก เริ่มที่ 5 ถึง 10 ชิ้นต่อ Pillar
- ลิงก์ภายใน ทุก Cluster ลิงก์กลับ Pillar และ Pillar ลิงก์ไปทุก Cluster
  ชิ้นช่วงตัดสินใจลิงก์ต่อไปหน้าบริการ
- URL ให้ Pillar อยู่ที่ระดับบนสุดของหัวเรื่อง Cluster อยู่ใต้หัวเรื่องเดียวกัน
  ใส่ชื่อจังหวัดหรือย่านใน URL เฉพาะเมื่อชิ้นนั้นเจาะพื้นที่จริงเท่านั้น
- ความยาวไม่ใช้สูตรคำนวณ ให้ดูหน้าที่ดีที่สุดของคู่แข่งในคำค้นนั้นแล้วครอบคลุมให้กว้างและลึกกว่า
  Pillar ยาวสุด Cluster ขนาดกลาง ชิ้นตอบคำถามเฉพาะสั้นแต่จบในตัว

## ขั้นที่ 5 เขียนสเปกรายชิ้น

ทุกชิ้นต้องมีครบตามนี้ เพื่อส่งต่อไปเขียนจริงได้ทันที

| สเปก | ต้องระบุ |
|---|---|
| ชื่อเรื่องชั่วคราว | สื่อว่าตอบอะไร ไม่ใช้คำโฆษณาลอย ๆ |
| URL ที่เสนอ | เส้นทางเต็ม ตามหลัก URL ในขั้นที่ 4 |
| บทบาทในโครง | Pillar หรือ Cluster ของหัวเรื่องไหน |
| คำค้นหลักและคำรอง | ดึงจากขั้นที่ 3 |
| ช่วงการตัดสินใจและรูปแบบ | ตามตารางขั้นที่ 3 และช่องว่างที่พบ |
| โครง heading คร่าว ๆ | H1 หนึ่งอัน และ H2 หลัก ๆ |
| ประเด็นที่ต้องมี | สิ่งที่ทำให้ชนะช่องว่างจากขั้นที่ 2 เป็นข้อ ๆ |
| ลิงก์ภายใน | ลิงก์ไปหาใคร ใครลิงก์มาหา |
| Meta | title 50-60 ตัวอักษร description 140-160 ตัวอักษร |

นับตัวอักษร meta ตามกติกาสกิล `meta-basics-lite` คือ **สระบน สระล่าง และวรรณยุกต์ นับเป็น 1 ตัวเสมอ**
ห้ามกะจากความกว้างที่ตาเห็น และใส่ชื่อแบรนด์ใน title ได้เฉพาะหน้าแรก หน้าอื่นใช้พื้นที่ให้คำค้นทั้งหมด

คำที่ต้องเลี่ยงในชื่อเรื่อง เพราะอ่านแล้วรู้ว่าเครื่องเขียนและไม่บอกว่าหน้านั้นตอบอะไร
ฉบับสมบูรณ์ แบบครบถ้วน คู่มือฉบับผู้เชี่ยวชาญ ทุกสิ่งที่คุณควรรู้ วิธีการแบบเชี่ยวชาญ
ให้ระบุสิ่งที่ผู้อ่านได้จริงแทน เช่น ระบุขั้นตอน ระบุตัวเลือกที่เทียบ หรือระบุกลุ่มผู้อ่าน

## ขั้นที่ 6 จัดลำดับการลงมือ

ประเมินทุกชิ้นสองแกนแบบเชิงคุณภาพ **ผลกระทบ** สูง กลาง ต่ำ ดูจากความใกล้เงินและขนาดช่องว่างที่อุด
และ **ความยาก** สูง กลาง ต่ำ ดูจากข้อมูลที่ต้องหาเพิ่ม แล้วเรียงตามนี้

1. ผลกระทบสูงและความยากต่ำ ทำก่อนเสมอ
2. Pillar เสร็จก่อน Cluster ในหัวเรื่องเดียวกัน เพราะ Cluster ต้องมีที่ลิงก์กลับ
3. ชิ้นที่อุดช่องว่างที่คู่แข่งอ่อนสุด มาก่อนชิ้นที่ต้องชนคู่แข่งที่แข็ง

ห้ามแปลงสองแกนนี้เป็นตัวเลขแล้วบวกกัน ให้เขียนเหตุผลกำกับทุกชิ้นว่าทำไมอยู่ลำดับนี้

## ขั้นที่ 7 ประตูตรวจก่อนสั่งทำของชิ้นใหญ่ และก่อนยอมให้เอาเนื้อหาไปลงที่อื่น

ขั้นนี้ทำตอนวางแผน คือ **ก่อน** สั่งทำและ **ก่อน** ตกลงกับใคร ไม่ใช่ทำตอนของเสร็จแล้ว
รอบไหนไม่มีข้อเสนอสามเรื่องนี้ ให้ข้ามไปที่ส่งออกได้เลย

### 7.1 งานวิจัยหรือแบบสำรวจของตัวเอง เอาหรือไม่เอา

ไล่สี่ข้อตามลำดับ ตกข้อไหนคือไม่ทำ

1. **ไปดูก่อนว่ามีข้อมูลแบบนี้อยู่แล้วหรือยัง** ทั้งของหน่วยงานรัฐ สมาคม และสื่อในวงการ
   ถ้ามีคนทำไว้แล้วและยังใหม่พอ ให้อ้างของเขาแทนการทำใหม่
2. **ผลที่จะได้ต้องมีโอกาสน่าประหลาดใจ** ถ้าผลออกมาแค่ยืนยันสิ่งที่วงการเชื่ออยู่แล้ว
   จะไม่มีใครหยิบไปพูดถึงและไม่มีใครลิงก์ถึง เท่ากับลงแรงไปเปล่า ๆ
3. **ตกลงกันไว้ล่วงหน้าว่าผลออกมาอย่างไรก็เผยแพร่ตามนั้น** รวมถึงตอนที่ผลจืด
   การเค้นข้อสรุปที่ข้อมูลไม่รองรับให้ดูน่าตกใจ คือการเปิดช่องให้คนอื่นมาแก้ต่อหน้าสาธารณะ
4. **ถ้าเป้าหมายคือให้คนลิงก์ถึง ให้เผยแพร่ผลบนหน้าเว็บตรง ๆ ห้ามเอาไปซ่อนหลังฟอร์มขออีเมล**
   คนที่จะอ้างถึงต้องเห็นตัวเลขก่อนถึงจะอ้างได้

### 7.2 เครื่องมือหรือเครื่องคิดเลขบนเว็บ ซ้ำกับที่มีอยู่แล้วไหม

ก่อนสั่งทำ ให้ **ค้นชื่อเครื่องมือแบบใส่เครื่องหมายคำพูดคร่อม** ดูว่ามีเจ้าอื่นทำไว้แล้วกี่เจ้า
สกิลนี้ไม่มีเครื่องมือค้นเว็บ ให้ผู้ใช้ค้นเองแล้วส่งผลกลับมา แล้วค่อยตัดสิน
เจอเต็มไปหมดแปลว่าเพิ่มอีกหนึ่งตัวจะไม่มีใครสนใจ ให้เลิกทำ
หรือเปลี่ยนโจทย์ให้เป็นของที่ยังไม่มีใครทำจริง ๆ

**ถ้าเครื่องมือนั้นให้เว็บอื่นเอาไปฝังได้ ลิงก์ที่ติดไปกับตัวฝัง ต้องชี้ไปหน้าที่เรื่องตรงกับตัวเครื่องมือ**
ฝังเครื่องมือแล้วลากลิงก์ไปหน้าขายของที่ไม่เกี่ยวกัน เป็นรูปแบบที่ถูกจับได้มานานแล้ว ลิงก์จะไม่ถูกนับ

### 7.3 เอาเนื้อหาไปลงซ้ำที่อื่น รับเงื่อนไขแบบไหนได้บ้าง

**ฝั่งที่เขาขอเอาของเราไปลง** ให้ตัดสินที่ตัวผู้เผยแพร่ ไม่ใช่ตัดสินที่เงื่อนไขทางเทคนิคที่ขอได้
สื่อที่คนในวงการเชื่อถือขอเอาไปลง ให้รับได้ แม้จะไม่มี canonical และไม่มีลิงก์กลับ
ขอลิงก์หนึ่งครั้งแล้วจบ ไม่ต้องต่อรองต่อ เพราะการได้คนอ่านคุ้มกว่าความเสี่ยงที่ฉบับของเขาจะขึ้นก่อนของเรา
ส่วนเครือข่ายที่รับลงทุกอย่างที่ส่งไปโดยแทบไม่มีการคัดเลือก ให้ปฏิเสธ เพราะแทบไม่มีค่าอะไร

**ฝั่งที่เรายกเนื้อหาให้พาร์ทเนอร์เอาไปลง** ต้องได้อย่างใดอย่างหนึ่งใน 3 ข้อนี้ เรียงตามลำดับที่อยากได้

| ลำดับ | สิ่งที่ขอจากเขา | ได้อะไร |
|---|---|---|
| 1 | ใส่ canonical ข้ามโดเมนชี้กลับหน้าต้นฉบับของเรา | ต้นฉบับยังเป็นเจ้าของเรื่อง |
| 2 | ใส่ noindex ที่ฉบับของเขา | ฉบับของเขาไม่มาแย่ง และลิงก์ในนั้นยังส่งค่ามาหาเราได้ |
| 3 | อย่างน้อยที่สุด ลิงก์กลับมาที่หน้าต้นฉบับ | ยังโยงกลับมาหาเราได้ |

**ไม่ได้สักข้อ ห้ามยกให้ไปลง** เพราะเว็บที่ใหญ่กว่าอาจถูกนับเป็นต้นทางแทน
แล้วต้นฉบับของเราถูกกรองออกจากผลค้นหาของเนื้อหาที่เราเขียนเอง

### ขอบเขตของขั้นนี้

ขั้นนี้ตัดสินแค่ว่า **ควรมีของชิ้นนั้นไหม และยอมให้ของไปอยู่ที่อื่นด้วยเงื่อนไขอะไร**
ส่วนการเลือกเว็บเป้าหมาย การเขียนข้อความติดต่อ และการติดตามผล เป็นงานของสกิล `seo-backlink-strategy-lite`
สกิลนี้ส่งให้เขาแค่หัวข้อ มุมของเนื้อหา และลำดับความสำคัญ ไม่วางแผนติดต่อเอง

## ส่งออก

ไฟล์ `work/{domain}/(00-baseline|01-current)/{domain}_content-strategy_{YYYY-MM-DD}.md` เรียงตามนี้

1. **สรุปกลยุทธ์หนึ่งย่อหน้า** และความได้เปรียบของเรา
2. **ตารางคู่แข่ง 4 แบบ** พร้อมสิ่งที่พบจากการอ่านจริง
3. **ตารางช่องว่าง 4 ประเภท** พร้อม URL หลักฐาน
4. **โครง Pillar และ Cluster** พร้อมแผนลิงก์ภายใน
5. **สเปกรายชิ้น** ครบทุกช่องตามขั้นที่ 5
6. **ลำดับการลงมือ** ตาราง ชิ้น / ผลกระทบ / ความยาก / เหตุผลที่อยู่ลำดับนี้
7. **ข้อจำกัด** ส่วนไหนอิงสมมติฐาน ส่วนไหนดูจากหน้าเว็บจริง
8. **ผลประตูตรวจขั้นที่ 7** เฉพาะรอบที่มีข้อเสนอเรื่องงานวิจัย เครื่องมือบนเว็บ หรือการเอาเนื้อหาไปลงที่อื่น
   ระบุว่าตัดสินว่าอย่างไรและด้วยเหตุผลข้อไหน

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## กฎ

- **ห้ามเดา search volume หรือแต่งสถิติ** ถ้าไม่มีตัวเลข ให้เรียงจากความตรง intent และช่องว่างที่เห็นจริง
- **ห้ามให้คะแนนหรือน้ำหนักเป็นตัวเลข** ใช้ สูง กลาง ต่ำ พร้อมเหตุผลกำกับทุกครั้ง
- **ห้ามสรุปว่าคู่แข่งอ่อน** ถ้ายังไม่ได้เปิดหน้าเว็บเขาอ่านจริง
- ถ้าเปิดหน้าคู่แข่งไม่ได้เพราะถูกกั้น ให้รายงานตรง ๆ แล้วเสนอให้ผู้ใช้คัดลอกเนื้อหามาวางแทน
- **ดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย
  เปิดหน้าคู่แข่งไม่ได้ ห้ามสรุปว่าคู่แข่งไม่มีเนื้อหาเรื่องนั้น ไม่งั้นจะกลายเป็นช่องว่างปลอมที่พาไปเขียนผิดชิ้น
- **ทำได้บางส่วนต้องส่งส่วนนั้น** ห้ามส่งตารางที่ทุกช่องเขียนว่าประเมินไม่ได้
  และห้ามปฏิเสธทั้งงานเพราะขาดคำค้นหรือขาด URL คู่แข่ง ให้ส่งเท่าที่ทำได้พร้อมป้าย ยืนยันแล้ว หรือ ต้องยืนยันเพิ่ม
- ห้ามแต่งข้อมูลธุรกิจของผู้ใช้ ถ้าไม่รู้ให้ถาม ถ้ายังไม่รู้ให้เขียนว่าไม่ทราบ
- **ห้ามเสนอให้ทำงานวิจัยหรือแบบสำรวจเอง ถ้ายังไม่ได้ดูว่ามีข้อมูลแบบนั้นอยู่แล้วหรือยัง**
  และห้ามเสนอให้เอาผลไปซ่อนหลังฟอร์มขออีเมลเมื่อเป้าหมายคือให้คนลิงก์ถึง
- **ห้ามยกเนื้อหาให้พาร์ทเนอร์เอาไปลง ถ้าไม่ได้อย่างน้อยหนึ่งใน 3 ข้อของขั้นที่ 7.3**
- เนื้อหาที่สร้างห้ามใช้ em dash และใส่ชื่อแบรนด์ใน title ได้เฉพาะหน้าแรก
- ถ้าข้อมูลไม่พอจะวางแผนทั้งเว็บ ให้วางเท่าที่ข้อมูลรองรับ แล้วเขียนตรง ๆ ว่าขาดอะไร
