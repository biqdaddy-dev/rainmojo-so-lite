# Local SEO

ทำให้ธุรกิจที่มีหน้าร้านหรือพื้นที่บริการ ถูกพบใน Google Maps และคำค้น "ใกล้ฉัน"
ผลทุกข้อเป็น **ผ่าน / ไม่ผ่าน / ไม่มีข้อมูล**

## ขั้นแรกสุด ดึง HTML ดิบมาก่อน

**ห้ามข้ามขั้นนี้** เพราะ WebFetch คืนเนื้อหาที่แปลงเป็นข้อความแล้ว
ของที่อยู่ใน `<head>` เช่น title, meta description, canonical และ JSON-LD **ถูกตัดทิ้งหมด**
ถ้าตรวจจากผล WebFetch อย่างเดียว จะรายงานว่า **ไม่มี** ทั้งที่มีอยู่จริง ซึ่งเป็นผลลบลวง

```bash
mkdir -p work/{domain}/uploads
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120"
curl -sSL -A "$UA" -m 25 "https://{domain}/" -o work/{domain}/uploads/home.html
```

### ถ้าใช้คำสั่งพวกนี้ไม่ได้

**บาง host ไม่มีเครื่องมือรันคำสั่งให้** เช่น Cowork, Claude Desktop และ GPT desktop
ถ้าเป็นแบบนั้น ให้ทำแบบนี้แทน แล้วงานจะยังเดินต่อได้

1. บอกผู้ใช้ว่า **ขอให้ช่วยเปิดหน้าเว็บแล้วคัดลอกซอร์สมาให้**
   วิธีคือเปิดหน้านั้นในเบราว์เซอร์ กด `Ctrl+U` หรือ `Cmd+Option+U` เพื่อดู source
   แล้วเลือกทั้งหมด คัดลอก มาวางในแชท
2. ถ้าผู้ใช้ทำให้ได้ ให้ทำงานต่อจากซอร์สที่ได้มา ตามขั้นตอนเดิมทุกอย่าง
3. ถ้าผู้ใช้ไม่สะดวก ให้ใช้ WebFetch เท่าที่ได้ แล้ว**เขียนกำกับทุกหัวข้อที่กระทบว่า `ตรวจไม่ได้`**
   ห้ามเขียนว่า `ไม่มี` เพราะสองคำนี้คนละความหมาย และการเขียนผิดจะทำให้ผู้ใช้เข้าใจกลับด้าน

**บน Windows** ถ้ารันแล้วขึ้นว่าไม่รู้จักคำสั่ง ให้ลองใน Git Bash หรือ WSL
ถ้าไม่มีทั้งสองอย่าง ให้ใช้วิธีคัดลอกซอร์สในข้อ 1

ทำแบบเดียวกันกับทุกหน้าที่ต้องตรวจ ตั้งชื่อไฟล์ตามหน้า แล้ว **ใช้ Grep กับไฟล์ที่ดาวน์โหลดมา**

ตัวอย่างคำสั่งที่ใช้บ่อย

```bash
grep -o '<title>[^<]*</title>' work/{domain}/uploads/home.html
grep -o '<meta name="description" content="[^"]*"' work/{domain}/uploads/home.html
grep -o '<link rel="canonical" href="[^"]*"' work/{domain}/uploads/home.html
grep -o '<meta name="robots" content="[^"]*"' work/{domain}/uploads/home.html
sed -n 's/.*<script type="application\/ld+json">\(.*\)<\/script>.*/\1/p' work/{domain}/uploads/home.html
```

**ถ้าดึงหน้าเดิมสองครั้งแล้วได้ค่าไม่ตรงกัน ให้ดึงครั้งที่สาม** แล้วใช้ค่าที่ซ้ำกันสองในสาม
ถ้ายังไม่ตรงอีก ให้บันทึกว่าค่าไม่นิ่ง และห้ามสรุปว่าหน้านั้นผิดกฎ

**ถ้า `curl` ใช้ไม่ได้ในเครื่องผู้ใช้** ให้บอกตรง ๆ แล้วทำเท่าที่ WebFetch ให้ได้
พร้อมเขียนกำกับทุกหัวข้อที่กระทบว่า **ตรวจไม่ได้** ไม่ใช่ **ไม่มี** สองคำนี้คนละความหมาย

## ห้ามเขียนสิ่งที่เว็บลูกค้าไม่ได้พูดไว้

**ทุกข้อความที่บอกว่าธุรกิจนี้มีบริการอะไร ให้อะไรฟรี หรือมีเงื่อนไขอะไร
ต้องค้นเจอคำนั้นในหน้าเว็บจริงก่อน** ห้ามอนุมานจากประเภทธุรกิจ
เช่น เห็นคำว่าเหมาะกับครอบครัว แล้วเขียนต่อเองว่าเด็กเข้าฟรี นั่นคือการแต่งขึ้น

วิธีตรวจคือค้นคำนั้นในไฟล์หน้าเว็บที่เก็บไว้ ถ้าหาไม่เจอให้เขียนว่า
ยังไม่พบข้อมูลนี้บนเว็บ ต้องถามเจ้าของก่อน ไม่ใช่เขียนลงไปเลย

เรื่องนี้ไม่ใช่เรื่องความสวยงามของรายงาน ข้อมูลพวกนี้จะถูกเอาไปกรอกลงโปรไฟล์ธุรกิจจริง
ถ้ากรอกสิ่งที่ร้านไม่ได้ให้ ลูกค้าที่อ่านแล้วเดินทางมาจะเจอเรื่องไม่ตรงปกหน้างาน

**ก่อนเขียนว่าเว็บยังไม่มีหน้าประเภทไหน ให้เปิดรายชื่อ URL ทั้งหมดของรอบนี้ดูก่อน**
ถ้ามีหน้าที่ทำเรื่องนั้นอยู่แล้ว ให้เสนอปรับปรุงของเดิม ไม่ใช่เสนอสร้างใหม่
สร้างหน้าใหม่ทับเรื่องเดิมจะได้สองหน้าแย่งอันดับกันเอง

## ขั้นที่ 1 เก็บข้อมูลธุรกิจ

ถามให้ครบก่อน ชื่อตามจดทะเบียน ประเภทธุรกิจ บริการหลัก ที่อยู่เต็ม เบอร์โทร เวลาทำการ
เขตที่ให้บริการ เว็บ โซเชียล สถานะ GBP ข้อไหนไม่มีให้เขียนตรง ๆ ว่าไม่มี **ห้ามแต่งเอง**
ถ้ามีเว็บให้ดึงหน้าแรก หน้าติดต่อ และ footer มาอ่าน NAP จริง

## กฎที่ต้องรู้ก่อนแตะโปรไฟล์

สามข้อนี้เป็นข้อที่คนทำผิดกันมากที่สุด และข้อแรกทำผิดแล้วเสียโปรไฟล์ทั้งใบ

**1. ชื่อธุรกิจคือช่องคัดลอก ไม่ใช่ช่องเขียน**

ต้องตรงกับชื่อที่ใช้ประกอบกิจการจริง ทั้งบนป้ายหน้าร้าน บนใบเสร็จ และในทะเบียน
**ให้คัดลอกมา ห้ามแต่ง** การเติมคำบริการ ชื่อเมือง สโลแกน หรือคำขยายลงในช่องชื่อ
**ผิดกติกาของแพลตฟอร์ม** และผลที่เกิดจริงคือ **listing ถูกระงับ**
ซึ่งแปลว่ารีวิว รูป และสัญญาณอันดับที่สะสมมาทั้งหมดดับพร้อมกัน
ไม่มีคำค้นคำไหนคุ้มกับความเสี่ยงนั้น **ห้ามแนะนำให้ทำเด็ดขาด**

ถ้าเห็นคู่แข่งยัดคำค้นในชื่อแล้วยังติดอันดับอยู่ **นั่นคือสัญญาณที่ต้องรายงานว่าเขาทำผิดกติกา
ไม่ใช่ต้นแบบให้ทำตาม**

**2. คำอธิบายโปรไฟล์ไม่มีน้ำหนักต่ออันดับโดยตรง**

การยัดคำค้นลงในคำอธิบาย **ไม่ได้ทำให้อันดับดีขึ้นเลย เป็นแรงที่ทิ้งเปล่า**
แล้วยังอ่านเหมือนสแปมสำหรับคนที่เปิดมาอ่าน ซึ่งทำลายสิ่งที่มีผลจริง
คือการที่คนกดโทร กดขอเส้นทาง และกดเข้าเว็บจากโปรไฟล์
**ให้เขียนคำอธิบายเพื่อคนที่หาโปรไฟล์เจอแล้วและกำลังตัดสินใจ** ว่าธุรกิจนี้ทำอะไร ทำให้ใคร
ดีกว่าตัวเลือกอื่นตรงไหน และต้องทำอะไรต่อ

ช่องที่มีน้ำหนักต่ออันดับโดยตรงคือ **หมวดหมู่ ชื่อธุรกิจ สัญญาณจากรีวิว
และระยะห่างจากที่อยู่ที่ยืนยันแล้วถึงคนค้น** ส่วนคำอธิบาย บริการ สินค้า รูป โพสต์ และ Q&A
**ไม่มีน้ำหนักโดยตรง** แต่ทำงานผ่านการที่คนกดต่อ **ให้ปรับสองกลุ่มนี้คนละเป้าหมาย**
กลุ่มแรกปรับเพื่ออันดับ กลุ่มหลังปรับเพื่อคนอ่าน

- **หมวดหมู่** แพลตฟอร์มประกาศเพดานไว้ที่ 10 หมวดต่อโปรไฟล์ นับรวม primary แล้ว
  ให้ใส่เฉพาะหมวดที่ธุรกิจทำจริง หมวดที่ไม่ตรงไม่ได้เพิ่มการมองเห็น แต่ทำให้ความเกี่ยวข้องเจือจาง
- **การประกาศพื้นที่ให้บริการไม่ได้ขยายพื้นที่ที่ติดอันดับ** มันบอกแค่ว่าไปส่งถึงไหน
  การมองเห็นยึดกับที่อยู่ที่ยืนยันแล้วและจางลงเมื่อไกลออกไป ต่อให้วาดพื้นที่บริการกว้างแค่ไหน
  **ห้ามขายพื้นที่บริการที่กว้างขึ้นว่าเป็นวิธีขยายการมองเห็น**
  ทางเดียวที่จะมีตัวตนในอีกเมืองคือมีที่อยู่ที่ยืนยันได้ที่นั่นจริง ๆ กับ listing แยกของเมืองนั้น

**3. Citation เป็นงานพื้นฐานครั้งเดียว ไม่ใช่งานรายเดือน**

ส่ง NAP มาตรฐานผ่านช่องทางรวมหลักหนึ่งรอบ แล้วเดินอีกหนึ่งรอบเพื่อแก้ของที่ผิด
โดยค้นชื่อแบรนด์แล้วไล่แก้หรือลบสิ่งที่โผล่มาผิด ทั้งรายการซ้ำ ที่อยู่เก่า และเบอร์เก่า

**หลังจากนั้นแตะ citation อีกครั้งเดียวคือตอนที่ NAP เปลี่ยนจริง** เช่น ย้ายที่ ทำแบรนด์ใหม่
หรือเปลี่ยนเบอร์ **ไม่มีรอบรายไตรมาส ไม่มีโควตาส่งรายเดือน
และไม่มีการไล่หาไดเรกทอรีใหม่ไปเรื่อย ๆ**

งบและเวลาที่เหลือให้ย้ายไปงานที่ทบต้น คือ **การได้รีวิวและการตอบรีวิว งานพื้นที่บนหน้าเว็บ
และลิงก์ท้องถิ่น** ซึ่งยังขยับอันดับได้จริง
**แผนที่ตั้งรายการ citation ไว้เป็นงานประจำรายเดือน คือแผนที่ผิด ไม่ใช่แผนที่ครอบคลุม**

## ขั้นที่ 2 GBP checklist

ให้ผลรายข้อ พร้อมเหตุผลสั้น ๆ และวิธีแก้เฉพาะข้อที่ไม่ผ่าน

| รายการ | ผ่านเมื่อ |
|---|---|
| ชื่อธุรกิจ | ตรงชื่อที่ใช้ประกอบกิจการจริงทุกตัวอักษร ไม่มีคำบริการ ชื่อเมือง หรือสโลแกนต่อท้าย |
| หมวดหมู่ | primary ตรงธุรกิจหลัก secondary ครอบบริการรอง |
| คำอธิบาย | เขียนให้คนที่เปิดโปรไฟล์มาแล้วตัดสินใจได้ ไม่ใช่ช่องใส่คำค้น |
| ที่อยู่และ service area | ตรงที่ตั้งจริง ระบุพื้นที่ที่ไปถึงจริง ไม่ตีกว้าง |
| เวลาทำการ | เป็นปัจจุบัน รวมวันหยุดพิเศษ |
| attribute และรูปภาพ | ที่จอดรถ การชำระเงิน ภาพหน้าร้าน ภายใน ทีมงาน |
| โพสต์และ Q&A | โพสต์สม่ำเสมอ ตอบคำถามที่ถามบ่อยล่วงหน้า |
| รีวิว | ตอบทุกรีวิวตามกติกาการตอบรีวิวด้านล่าง รีวิวลบยอมรับปัญหาแล้วชวนคุยต่อส่วนตัว |

## ขั้นที่ 3 NAP ต้องตรงกัน

NAP คือ Name, Address, Phone ต้องเขียนเหมือนกันทุกตัวอักษรทุกช่องทาง
เพราะระบบใช้ความตรงกันยืนยันว่าธุรกิจนี้มีจริง

1. **ตั้งรูปแบบมาตรฐานหนึ่งเดียว** ทั้งการสะกดชื่อ การย่อที่อยู่ รูปแบบเบอร์ และ URL
2. ตรวจทีละช่องทาง ทำตาราง ช่องทาง / ชื่อ / ที่อยู่ / เบอร์ / ผล / ต้องแก้อะไร
   ไล่แก้ GBP, Facebook และเว็บตัวเองก่อน แล้วค่อย Bing Places กับไดเรกทอรีท้องถิ่น
3. หา listing ซ้ำ เสนอรวมหรือลบ เพราะของซ้ำทำให้ความน่าเชื่อถือกระจาย

## ขั้นที่ 4 local schema

JSON-LD ประเภท LocalBusiness หรือ subtype ที่ตรงกว่า เช่น Restaurant, Dentist

| field | มาจากไหน |
|---|---|
| name, telephone | ค่ามาตรฐานจากขั้นที่ 3 เบอร์ขึ้นต้น +66 |
| address | PostalAddress แยก streetAddress, addressLocality, postalCode |
| openingHoursSpecification | เวลาทำการชุดเดียวกับ GBP |
| geo | ใส่เมื่อยืนยันพิกัดได้ ไม่มีให้เว้น ห้ามเดา |
| url, sameAs, areaServed | เว็บ ลิงก์ GBP โซเชียล พื้นที่บริการ |

**ห้ามใส่ field ที่ไม่มีข้อมูลจริงรองรับ** เช่น aggregateRating ทั้งที่ไม่มีรีวิว

## ขั้นที่ 5 คำค้นและหน้าตามพื้นที่

วางคำค้น 4 แบบ บริการ + จังหวัด, บริการ + ใกล้ฉัน, บริการ + ย่านหรือ landmark,
คำถาม + พื้นที่

- หน้าแยกต่อสาขาหรือต่อพื้นที่ ใส่ landmark ที่คนแถวนั้นรู้จัก
  **ห้ามคัดลอกแล้วเปลี่ยนแค่ชื่อจังหวัด**
- title 50 ถึง 60 ตัวอักษร description 140 ถึง 160 ตัวอักษร นับตามกติกา `meta-basics-lite`
  คือสระบน สระล่าง และวรรณยุกต์นับเป็น 1 ตัวเสมอ
- **ห้ามใช้สำนวนสำเร็จรูป** เช่น ฉบับผู้เชี่ยวชาญ, ครบวงจร, ครบถ้วน

## กติกาการตอบรีวิว

**เขียนตอบให้คนที่จะมาอ่านทีหลัง ไม่ใช่เขียนให้คนที่รีวิว** เพราะคำตอบหนึ่งอันมีคนอ่านเป็นร้อย
และแต่ละคนกำลังตัดสินว่าธุรกิจนี้รับมือกับปัญหาได้ดีแค่ไหน
คำตอบคือข้อความการตลาด ไม่ใช่การโต้เถียง

- **ห้ามเขียนในที่สาธารณะว่ารีวิวนั้นปลอม** ต่อให้มันปลอมจริง
  ให้ไปแจ้งผ่านช่องทางรายงานของแพลตฟอร์ม ส่วนในคำตอบให้ตอบเฉพาะเนื้อหาที่เขาบอกมา
- **ห้ามเปิดเผยตัวตนคนรีวิวที่ใช้นามแฝง** ห้ามเอ่ยชื่อจริง ห้ามเล่ารายละเอียดว่ามาใช้บริการวันไหน
  และห้ามเขียนทำนองว่ารู้ว่าเป็นใคร มันอ่านเป็นการข่มขู่ และเสี่ยงผิดกฎความเป็นส่วนตัว
- **ห้ามยัดคำค้นในคำตอบ** คำตอบที่อัดชื่อพื้นที่และชื่อบริการอ่านออกทันทีว่าเขียนให้อัลกอริทึม
  แล้วทำลายความรู้สึกของคนที่มาอ่านทีหลัง
- **ห้ามใช้คำตอบสำเร็จรูปซ้ำ ๆ** คำตอบที่เหมือนกันเป๊ะทุกอันบอกคนอ่านว่าไม่มีใครฟังจริง
  ทุกคำตอบต้องอ้างถึงสิ่งที่รีวิวอันนั้นพูดถึงจริง
- **คะแนนเฉลี่ยต้องสูงพอที่คำค้นเชิงคุณภาพจะไม่กรองธุรกิจนี้ทิ้ง** เช่น คำค้นที่มีคำว่า ดีที่สุด
  หรือ ร้านดี ๆ แถวนี้ ถ้าคะแนนต่ำจนโดนกรองออก **งานกู้คะแนนต้องมาก่อน citation
  และก่อนงานตกแต่งโปรไฟล์ทุกอย่าง** เพราะอันดับไม่มีความหมายถ้าคนกรองทิ้งตั้งแต่ยังไม่ทันเห็น

## ห้ามเสนอสิ่งเหล่านี้ในฐานะงานดันอันดับ

ไล่ตรวจแผนที่ร่างเสร็จแล้วกับรายการนี้อีกรอบก่อนส่ง
**เจอข้อไหนคือของเสียที่ต้องแก้ ไม่ใช่เรื่องที่แล้วแต่ดุลพินิจ**

| ห้ามเสนอว่า | เพราะ |
|---|---|
| ระดมให้คนกดขอเส้นทางมาที่ร้าน หรือทำแผนที่ซ้อนกันเป็นชั้น | ไม่ขยับอันดับ local |
| ฝังแผนที่บนหน้าเว็บเพื่อดันอันดับ | ไม่ขยับอันดับ local |
| ใส่พิกัดลงในไฟล์รูป | ไม่ขยับอันดับ local |
| ซื้อโฆษณาเพื่อดันอันดับ organic | คนละระบบกัน ไม่ขยับอันดับ |

**ข้อยกเว้นเดียว** การฝังแผนที่และการซื้อโฆษณา เขียนลงแผนได้ถ้าติดป้ายว่าเป็น
**งานเพื่อการตัดสินใจซื้อ** คือช่วยให้คนที่เจอเราแล้วเดินทางมาถูกหรือซื้อได้ง่ายขึ้น
**ห้ามอยู่ใต้หัวข้อเรื่องอันดับ** ส่วนการระดมกดขอเส้นทางและการใส่พิกัดลงไฟล์รูป
ไม่มีคุณค่าฝั่งการตัดสินใจซื้อด้วย จึงห้ามปรากฏในแผนเลย

## ส่งออก

ไฟล์เดียว ชื่อและตำแหน่ง **เหมือนกันเป๊ะ** กับที่ประกาศใน `agent.json`

```
work/{domain}/(00-baseline|01-current)/{domain}_local-seo_{YYYY-MM-DD}.md
```

เรียงหัวข้อ สรุปหนึ่งย่อหน้า, ตาราง GBP คอลัมน์ รายการ / ผล / เหตุผล / วิธีแก้,
ตาราง NAP รายช่องทาง, JSON-LD พร้อมหมายเหตุ field ที่เว้น, แผนคำค้นและหน้า location,
สิ่งที่ควรทำก่อน 5 ข้อ เรียงตามผลกระทบ

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## กฎ


- **ถ้าดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย ถ้าเขียนผิดผู้ใช้จะสรุปกลับด้าน
- **ทำได้บางส่วนต้องส่งส่วนนั้นเสมอ** ห้ามส่งตารางที่ทุกช่องว่าง และห้ามปฏิเสธทั้งงานเพราะขาดข้อมูลบางอย่าง ให้ติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม · การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์
- **ห้ามให้คะแนนเป็นตัวเลข** ใช้ ผ่าน / ไม่ผ่าน / ไม่มีข้อมูล เท่านั้น
- **ห้ามเดาและห้ามแต่งข้อมูล** ทุกค่าต้องมาจากผู้ใช้หรือหน้าเว็บจริง
- ห้ามสมัครไดเรกทอรีเยอะ ๆ ปั่นจำนวน ห้ามจ้างรีวิว
- **ห้ามยัดคำค้นในชื่อธุรกิจเด็ดขาด** ชื่อธุรกิจคือช่องคัดลอกตามชื่อที่ใช้ประกอบกิจการจริง
  การเติมคำเสี่ยงถูกระงับ listing ทั้งใบ ซึ่งดับรีวิว รูป และสัญญาณอันดับพร้อมกัน
- **ห้ามเขียนคำอธิบายโปรไฟล์เป็นช่องใส่คำค้น** ช่องนี้ไม่มีน้ำหนักต่ออันดับโดยตรง
- **ห้ามตั้ง citation เป็นงานประจำรายเดือน** เป็นงานพื้นฐานครั้งเดียว บวกรอบแก้ของที่ผิดหนึ่งรอบ
- **ห้ามเขียนในคำตอบรีวิวว่ารีวิวนั้นปลอม และห้ามเปิดเผยตัวตนคนรีวิวที่ใช้นามแฝง**
- **ห้ามแก้ GBP หรือ listing ให้** เสนอสิ่งที่ต้องแก้ ผู้ใช้ไปแก้เอง
- เข้าเว็บหรือ listing ไม่ได้ ให้บอกตรง ๆ แล้วขอให้คัดลอกข้อมูลมาวาง
