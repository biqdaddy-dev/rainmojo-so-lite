Every generated file has exactly one home. Audit, keyword and comparison
outputs live under `work/{domain}/` created by `new-workspace-lite`

plugin tree or the caller's working directory. Append one line to the
workspace's `CHANGELOG.md` or `log.md` after every write. Run
`client_workspace.py validate` before handing a client workspace over. Direct
CMS/API operations retain their own safety and verification gates.

# วางแผนลิงก์ภายใน

ตอบคำถามเดียวคือ **หน้าไหนควรลิงก์หาหน้าไหน ด้วยข้อความอะไร และทำอันไหนก่อน**

หน้าที่ถูกลิงก์บ่อยจากหน้าที่เรื่องใกล้กัน จะถูกอ่านว่าเป็นหน้าสำคัญของเรื่องนั้น
**แต่ทุกเส้นต้องช่วยผู้อ่านเดินทางจริงด้วย**

**ต้องมีก่อนเริ่ม** รายการหน้าจาก `sitemap.xml` หรือที่ผู้ใช้ให้ / หน้าเป้าหมายที่อยากดัน /
คำค้นหลักของแต่ละหน้าถ้าเคยรัน `seo-keyword-research-lite` / หน้า conversion
ยังไม่มีรายการหน้า **ให้ลองดึง `sitemap.xml` เองก่อนตามหัวข้อถัดไป** ได้มาบางส่วนก็เดินงานต่อกับส่วนนั้น
ขาดของอย่างอื่น เช่นยังไม่รู้หน้าเป้าหมายหรือคำค้นหลัก **ห้ามหยุดทั้งงาน**
ให้ทำส่วนที่ทำได้ แล้วติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม
หยุดได้กรณีเดียวคือไม่ได้ URL มาเลยแม้แต่หน้าเดียว **ห้ามแต่งชื่อหน้าเอง**

## ขั้นแรกสุด ดึง HTML ดิบมาก่อน

**ห้ามข้ามขั้นนี้** เพราะ WebFetch คืนเนื้อหาที่แปลงเป็นข้อความแล้ว
ของที่อยู่ใน `<head>` เช่น title, meta description, canonical และ JSON-LD **ถูกตัดทิ้งหมด**
ถ้าตรวจจากผล WebFetch อย่างเดียว จะรายงานว่า **ไม่มี** ทั้งที่มีอยู่จริง ซึ่งเป็นผลลบลวง

```bash
mkdir -p work/{domain}/uploads
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120"
curl -sSL -A "$UA" -m 25 "https://{domain}/" -o work/{domain}/uploads/home.html
```

### ถ้าใช้คำสั่งพวกนี้ไม่ได้

**บาง host ไม่มีเครื่องมือรันคำสั่งให้** เช่น Cowork, Claude Desktop และ GPT desktop
ถ้าเป็นแบบนั้น ให้ทำแบบนี้แทน แล้วงานจะยังเดินต่อได้

1. บอกผู้ใช้ว่า **ขอให้ช่วยเปิดหน้าเว็บแล้วคัดลอกซอร์สมาให้**
   วิธีคือเปิดหน้านั้นในเบราว์เซอร์ กด `Ctrl+U` หรือ `Cmd+Option+U` เพื่อดู source
   แล้วเลือกทั้งหมด คัดลอก มาวางในแชท
2. ถ้าผู้ใช้ทำให้ได้ ให้ทำงานต่อจากซอร์สที่ได้มา ตามขั้นตอนเดิมทุกอย่าง
3. ถ้าผู้ใช้ไม่สะดวก ให้ใช้ WebFetch เท่าที่ได้ แล้ว**เขียนกำกับทุกหัวข้อที่กระทบว่า `ตรวจไม่ได้`**
   ห้ามเขียนว่า `ไม่มี` เพราะสองคำนี้คนละความหมาย และการเขียนผิดจะทำให้ผู้ใช้เข้าใจกลับด้าน

**บน Windows** ถ้ารันแล้วขึ้นว่าไม่รู้จักคำสั่ง ให้ลองใน Git Bash หรือ WSL
ถ้าไม่มีทั้งสองอย่าง ให้ใช้วิธีคัดลอกซอร์สในข้อ 1

ทำแบบเดียวกันกับทุกหน้าที่ต้องตรวจ ตั้งชื่อไฟล์ตามหน้า แล้ว **ใช้ Grep กับไฟล์ที่ดาวน์โหลดมา**

ตัวอย่างคำสั่งที่ใช้บ่อย ข้อแรกสำคัญที่สุดกับสกิลนี้ เพราะ WebFetch ตัด `href` ทิ้ง
ลิงก์ในเนื้อหาจึงต้องอ่านจากไฟล์ดิบเท่านั้น

```bash
grep -o '<a [^>]*href="[^"]*"[^>]*>[^<]*</a>' work/{domain}/uploads/home.html
grep -o '<title>[^<]*</title>' work/{domain}/uploads/home.html
grep -o '<meta name="description" content="[^"]*"' work/{domain}/uploads/home.html
grep -o '<link rel="canonical" href="[^"]*"' work/{domain}/uploads/home.html
grep -o '<meta name="robots" content="[^"]*"' work/{domain}/uploads/home.html
sed -n 's/.*<script type="application\/ld+json">\(.*\)<\/script>.*/\1/p' work/{domain}/uploads/home.html
```

**ถ้าดึงหน้าเดิมสองครั้งแล้วได้ค่าไม่ตรงกัน ให้ดึงครั้งที่สาม** แล้วใช้ค่าที่ซ้ำกันสองในสาม
ถ้ายังไม่ตรงอีก ให้บันทึกว่าค่าไม่นิ่ง และห้ามสรุปว่าหน้านั้นผิดกฎ

**ถ้า `curl` ใช้ไม่ได้ในเครื่องผู้ใช้** ให้บอกตรง ๆ แล้วทำเท่าที่ WebFetch ให้ได้
พร้อมเขียนกำกับทุกหัวข้อที่กระทบว่า **ตรวจไม่ได้** ไม่ใช่ **ไม่มี** สองคำนี้คนละความหมาย

## ดูภาพรวมทั้งเว็บก่อน อย่าดูแค่หน้าที่หยิบมา

ถ้าตรวจแค่ 3 ถึง 4 หน้า จะมองไม่เห็นปัญหาที่เกิดซ้ำทั้งเว็บ ซึ่งมักใหญ่กว่าปัญหารายหน้ามาก

```bash
curl -sSL -m 25 "https://{domain}/sitemap.xml" -o work/{domain}/uploads/sitemap.xml
grep -o '<loc>[^<]*</loc>' work/{domain}/uploads/sitemap.xml | sed 's/<[^>]*>//g' | head -60
```

ถ้าไฟล์เป็นดัชนีที่ชี้ไป sitemap ย่อย ให้ตามไปดึงอันที่เกี่ยวข้อง
แล้ว**สุ่มมาอย่างน้อย 10 หน้าที่เป็นหน้าประเภทเดียวกัน** เพื่อดูว่าใช้แม่แบบซ้ำกันหรือเปล่า

ถ้าพบว่าซ้ำกันตั้งแต่ 3 หน้าขึ้นไป ให้รายงานเป็น**ปัญหาระดับเว็บ** แยกจากปัญหารายหน้า
และประเมินคร่าว ๆ ว่ากระทบกี่หน้าจากทั้งหมดกี่หน้า

## ขั้นที่ 1 สำรวจโครงลิงก์ปัจจุบัน

1. เปิดอ่านหน้าตัวแทนแต่ละประเภท หน้าแรก หมวดหมู่ บทความ บริการ conversion
2. **จดเฉพาะลิงก์ในเนื้อหา แยกจากเมนูและ footer** เมนูมีทุกหน้าเหมือนกัน จึงไม่บอกว่าเรื่องไหนเกี่ยวกับเรื่องไหน
3. ตารางคอลัมน์ หน้า / ประเภท / ลิงก์เข้า / ลิงก์ออกในเนื้อหา / หมายเหตุ
4. หา **orphan page** ด้วยวิธีในขั้นที่ 1.5 ซึ่งเป็นการลบเซต ไม่ใช่การนับลิงก์เข้า กลุ่มนี้ได้ลิงก์ก่อนใคร
5. ให้ระดับ **ความลึก** ว่าจากหน้าแรกเดินผ่านกี่ชั้น

| ระดับ | หมายถึง และต้องทำอะไร |
|---|---|
| ตื้น | ถึงตรง ๆ หรือผ่านหน้ากลางชั้นเดียว ดีอยู่แล้ว |
| กลาง | ผ่านสองชั้น รับได้ ถ้าเป็นหน้าเป้าหมายให้ดึงขึ้น |
| ลึก | ผ่านหลายชั้น หรือมาจากหน้าที่แทบไม่มีใครลิงก์ถึง ต้องเพิ่มลิงก์จากหน้าที่ตื้นกว่า |

**บอกเสมอว่าเปิดอ่านจริงกี่หน้าจากทั้งหมดกี่หน้า** ข้อสรุปอิงหน้าตัวอย่างเท่านั้น

### ความลึกกับจำนวนลิงก์ออก เป็นการวัดชิ้นเดียว ต้องรายงานคู่กันเสมอ

**สองข้อนี้ตีกันเอง** เพราะวิธีที่ถูกที่สุดในการลดความลึกคือเอาลิงก์ไปกองไว้บนหน้า hub
ซึ่งเป็นสิ่งเดียวกับที่ทำให้อีกข้อพัง **รายงานที่แสดงข้อเดียวโดยไม่แสดงอีกข้อ เอาไปทำตามอย่างปลอดภัยไม่ได้**

- **เพดานความลึกต้องปรับตามขนาดเว็บ ไม่มีตัวเลขเดียวที่ใช้ได้กับทุกเว็บ**
  เว็บเล็กควรตื้นกว่าเว็บใหญ่ ให้ประกาศไว้ในรายงานว่าตั้งเพดานไว้เท่าไร
  โดยอ้างจากจำนวน URL ทั้งหมดที่นับได้จริง และนับจากหน้าแรก **หรือจาก hub ก็ได้** ไม่ใช่จากหน้าแรกอย่างเดียว
- **ห้ามซื้อความตื้นด้วยการกองลิงก์ใส่หน้า hub**
  **เลยจุดหนึ่งไป ลิงก์ที่เพิ่มเข้ามาแต่ละเส้นแทบไม่ส่งอะไรต่อเลย**
  และสิ่งเล็กน้อยที่ยังส่งอยู่ก็ไปกระจุกอยู่ที่ลิงก์ไม่กี่เส้นที่ถูกตัดสินว่าสำคัญ
  ลิงก์ที่เหลือบนหน้าที่แน่นเกินไปจึงเป็นแค่ของประดับ
  เว็บที่ดูตื้นเพราะเมกะเมนูและหน้ารวมยักษ์ **คือการย้ายปัญหา ไม่ใช่การแก้ปัญหา**
- **รายงานความลึกที่วัดได้ กับจำนวนลิงก์ออกต่อหน้า ไว้บนแถวเดียวกัน**
  นับลิงก์ในเนื้อหากับลิงก์โครงเว็บแยกกันตามหัวข้อ แยกลิงก์ตามส่วนของหน้า **แล้วรายงานผลรวมต่อหน้าด้วย**
  เพราะสิ่งที่มองหน้านั้นเห็นคือผลรวม
- **ติดธงทุกหน้าที่แก้ข้อหนึ่งด้วยการทำอีกข้อพัง** หน้าที่ถูกดึงขึ้นมาให้ตื้นด้วย hub ที่ตอนนี้แบกลิงก์เกินตัว
  **ยังไม่เรียกว่าแก้แล้ว** และ hub ที่ถูกตัดลิงก์ลงจนหน้ากลุ่มหนึ่งจมลึกกว่าเพดาน ก็ยังไม่เรียกว่าแก้แล้วเหมือนกัน
  ทุกหน้าที่ติดธง ต้องเขียนให้ชัดว่าข้อไหนดีขึ้นและข้อไหนแย่ลง
  **ห้ามเสนอการเปลี่ยนแปลงที่แก้ข้างหนึ่งโดยไม่บอกราคาที่อีกข้างต้องจ่าย**
- **ความลึกที่อยู่ในเพดาน และจำนวนลิงก์ที่ยังไม่แน่นเกินไป นับเป็นผ่านทั้งคู่**
  ห้ามเสนอให้รื้อหน้าที่ผ่านทั้งสองข้ออยู่แล้ว

## ขั้นที่ 1.5 orphan หาด้วยการลบเซต ไม่ใช่การนับลิงก์เข้า

**orphan คือ URL ที่มีอยู่ในบัญชีรายชื่อบางอย่าง แต่ไม่โผล่ในผลการไล่เดินลิงก์ที่ครบถ้วน**
หามันด้วยการเอาบัญชีรายชื่อ **ลบ** ผลการไล่เดิน ไม่ใช่ด้วยการนับลิงก์เข้าของหน้าที่ไล่เดินเจอแล้ว

**ห้ามใช้นิยามว่า หน้าที่ไล่เดินเจอแล้วและไม่มีลิงก์เข้าเลย** เด็ดขาด
เพราะโดยโครงสร้างของมัน นิยามนี้ **ไม่มีวันงัดหน้าที่การไล่เดินเข้าไม่ถึงออกมาได้เลย**
ซึ่งหน้ากลุ่มนั้นคือกลุ่มที่เสี่ยงที่สุด ใช้นิยามนี้ต่อไป orphan ตัวที่แย่ที่สุดจะมองไม่เห็นตลอดกาล
ถ้ารายงานรอบก่อนใช้นิยามนี้ **ห้ามเอาตัวเลขสองรอบมาเทียบกัน** เพราะวัดคนละอย่าง

เปรียบเทียบสี่ชุด **แยกกัน ห้ามรวมเป็นตัวเลข orphan ตัวเดียว**

| ชุดที่เอามาลบ | ได้มาจากไหนในรุ่นนี้ | เจอแล้วแปลว่า |
|---|---|---|
| sitemap ลบ ผลไล่เดิน | ดึง `sitemap.xml` เองได้ | เว็บประกาศ URL นี้ให้เครื่องมือค้นหา แต่ตัวเองไม่ลิงก์ถึง **เป็นปัญหาเรื่องลิงก์ อยู่ในมือเราแก้ได้** |
| หน้า landing ใน analytics ลบ ผลไล่เดิน | **ต้องขอ export จากผู้ใช้** | มีคนเข้ามาลงหน้านี้จริง ทั้งที่โครงเว็บของตัวเองเดินไปไม่ถึง ให้จดช่องทางที่เขาเข้ามาไว้ด้วย |
| URL ใน Search Console ลบ ผลไล่เดิน | **ต้องขอ export จากผู้ใช้** | เครื่องมือค้นหาถือ URL ที่โครงเว็บของตัวเองไม่ได้ลิงก์ถึง |
| URL ใน log ของบอท ลบ ผลไล่เดิน | **ต้องขอไฟล์จากผู้ใช้** | เครื่องมือค้นหารู้จัก URL ที่โครงเว็บไม่รู้จัก **เป็นสัญญาณที่แรงที่สุดในสี่ชุด** และเป็นชุดเดียวที่วิธีไล่เดินภายในสร้างเองไม่ได้ |

**ต้องรายงานว่า orphan แต่ละตัวโผล่มาจากชุดไหน เพราะแหล่งที่โผล่มาคือตัวบอกว่าต้องแก้ยังไง**
URL ที่โผล่จากหลายชุด ให้ลงครบทุกชุดที่โผล่

ขั้นตอน

1. **ประกาศความครอบคลุมของการไล่เดินก่อนเปรียบเทียบ** ว่าเปิดอ่านจริงกี่ URL จากกี่ URL ที่อยู่ในขอบเขต
   **การไล่เดินที่ไม่ครบ จะเปลี่ยนทุก URL ที่ยังไม่ได้เปิด ให้กลายเป็น orphan ปลอม**
2. ทำ URL ทั้งห้าชุดให้อยู่ในรูปเดียวกันก่อนลบกัน คือ scheme, โฮสต์, `/` ท้าย, ตัวพิมพ์ใหญ่เล็ก และพารามิเตอร์ติดตาม
   **รูปที่ไม่ตรงกันจะผลิต orphan ที่ไม่มีอยู่จริงขึ้นมาเอง**
3. ทำทีละชุด เก็บผลไว้สี่ชุด **ห้ามรวมกันก่อนรายงาน**
4. แต่ละ orphan ให้บันทึกแหล่งที่โผล่ หลักฐานจากบัญชีรายชื่อ และหลักฐานว่าไม่โผล่ในการไล่เดิน
5. เอา orphan ที่เหลือเข้าแผนลิงก์ในขั้นที่ 3 ตามปกติ

**ชุดไหนที่ไม่ได้ข้อมูลมา ให้ลงว่า `ตรวจไม่ได้` ทั้งชุด ห้ามลงว่าไม่มี orphan**
และต้องเขียนว่าทำได้กี่ชุดจากสี่ชุด ชุดไหนทำไม่ได้และเพราะอะไร
รายงานจำนวนแยกรายชุด **และจำนวนรวมที่ตัดตัวซ้ำออกแล้ว** ให้เห็นว่าสี่ตัวเลขกับตัวเลขรวมสอดคล้องกันอย่างไร

## ขั้นที่ 1.6 nofollow, sponsored, ugc บนลิงก์ภายใน เป็นข้อบกพร่องเสมอ

บนลิงก์ที่ชี้ไปหน้าในเว็บเดียวกัน **ทั้งสามตัวนี้ไม่มีการใช้งานที่ชอบธรรมเลยสักแบบ**
ให้ไล่ลงรายการ **ทุกครั้งที่เจอ** พร้อมหน้าต้นทางและ URL ปลายทาง
**ห้ามมานั่งตัดสินว่าอันนี้พอรับได้ อันนั้นรับไม่ได้** ลงให้หมด

```bash
grep -o '<a [^>]*rel="[^"]*\(nofollow\|sponsored\|ugc\)[^"]*"[^>]*>' work/{domain}/uploads/home.html
```

อ่านค่า `rel` เป็นรายการคำที่คั่นด้วยช่องว่าง และจับคำโดยไม่สนตัวพิมพ์ใหญ่เล็ก
แล้วคิดต่อว่า **หน้านั้นมีลิงก์ภายในกี่เส้น และติดสามตัวนี้ไปกี่เส้น**
เพราะหน้าที่ติดทุกเส้นเป็นข้อค้นพบคนละระดับกับหน้าที่ติดเส้นเดียว

ต้องเขียนผลสองอย่างนี้ไว้พร้อมรายการเสมอ

1. **หน้าที่ลิงก์ภายในทุกเส้นติดสามตัวนี้ อ่านออกมาว่าเว็บตัวเองไม่รับรองหน้านั้น**
   และอาจไม่ถูกเก็บข้อมูลเลย ให้ยกขึ้นเป็นข้อค้นพบเดี่ยว ไม่ใช่แถวหนึ่งในรายการยาว ๆ
2. **น้ำหนักที่ลิงก์นั้นควรส่งไป ถูกทิ้งไปเฉย ๆ ไม่ได้ถูกแบ่งไปให้ลิงก์เส้นอื่นบนหน้าเดียวกัน**
   การใส่ nofollow ให้ลิงก์ในเมนูที่ชี้หน้าคุณค่าต่ำ **จึงเป็นการทำลายน้ำหนักทิ้ง ไม่ใช่การรวมน้ำหนัก**
   ผลที่ได้กลับด้านกับสิ่งที่ตั้งใจ นี่คือเหตุผลที่ต้องเอาออก ไม่ใช่ปรับจูน

**ทั้งสามตัวไม่ได้ห้ามการเก็บข้อมูลและไม่ได้ห้ามการเข้าดัชนีของหน้าปลายทาง**
**ห้ามแนะนำให้ใช้เพื่อกันหน้าออกจากดัชนี** และถ้าเจอคำแนะนำเดิมที่เขียนไว้แบบนั้น ให้แก้ให้ถูก
ทางที่ถูกมีสองทาง คือ

- อยากให้หน้ายังเปิดได้แต่ไม่อยู่ในดัชนี ให้ใช้ noindex ระดับหน้า **แล้วปล่อยลิงก์ภายในให้เป็นลิงก์ปกติ**
- ไม่อยากเสียน้ำหนักในเมนูให้หน้าคุณค่าต่ำ ให้ **รื้อจนลิงก์นั้นไม่อยู่ตรงนั้น** ไม่ใช่ปล่อยลิงก์ไว้แล้วถอดค่าออก

**หน้าที่ดึง HTML ดิบไม่สำเร็จ ให้ลงว่า `ตรวจไม่ได้` ห้ามลงว่าหน้านั้นไม่มีข้อบกพร่องนี้**
ส่วนลิงก์ที่ชี้ออกไปเว็บอื่น อยู่นอกหัวข้อนี้ เป็นเรื่องของ `seo-backlink-strategy-lite`

## ขั้นที่ 2 จัดกลุ่ม hub และ spoke

**hub** หน้าหลักที่เล่าภาพรวมของหัวข้อ มักเป็นหน้าเป้าหมาย
**spoke** หน้าลูกที่เจาะประเด็นย่อยของหัวข้อเดียวกัน

ตารางคอลัมน์ hub / spoke ในกลุ่ม / คำค้นหลักของกลุ่ม / หน้า conversion ที่กลุ่มควรส่งต่อ
หน้าที่จัดกลุ่มไม่ได้ แยกอีกตาราง พร้อมข้อเสนอว่าควรเข้ากลุ่มไหน รวมกับหน้าอื่น หรือปล่อยไว้

---

## ขั้นที่ 3 ออกแบบแผนลิงก์

| เส้นที่ต้องมี | เหตุผล |
|---|---|
| spoke ไป hub ของกลุ่มตัวเอง | รวมความสำคัญของกลุ่มไปที่ hub |
| hub ไป spoke ทุกหน้าในกลุ่ม | ให้ crawler และคนอ่านเจอหน้าลูกครบ |
| spoke ไป spoke ที่เนื้อหาต่อกันจริง | ได้อ่านต่อเรื่องใกล้กัน |
| หน้าที่คนใกล้ตัดสินใจ ไป conversion | ปิดการเดินทาง |
| หน้าที่ลิงก์เข้าเยอะ ไป orphan และหน้าที่ลึก | ดึงหน้าที่จมขึ้นมา |

ข้ามกลุ่มได้เมื่อสองหน้าเกี่ยวข้องกันจริง **ห้ามโยงมั่วเพื่อเพิ่มเส้น**

| anchor text ทำ | อย่าทำ |
|---|---|
| บอกชัดว่าปลายทางเรื่องอะไร | คลิกที่นี่ อ่านต่อ |
| วลีธรรมชาติ กลืนกับประโยค | ยัดคำค้นเป๊ะ ๆ ซ้ำทุกเส้นที่ชี้หน้าเดียวกัน |
| ผสมคำค้นหลัก คำใกล้เคียง ชื่อเรื่อง | ใช้ anchor เดียวทั้งเว็บจนดูจงใจ |

ไทยใช้วลีสั้นที่คนพูดจริง อย่าแปลตรงตัวจากอังกฤษจนแข็ง
วางลิงก์ตรงจุดที่คนอ่านกำลังสงสัยเรื่องนั้นพอดี ไม่กองท้ายบทความ
ถ้าเกือบทุกย่อหน้ามีลิงก์จนสะดุด ให้ตัดเส้นที่ช่วยน้อยที่สุดออก

ตารางแผนลิงก์ คอลัมน์ ต้นทาง / ปลายทาง / anchor text / ตำแหน่งวาง / ความสำคัญ
ความสำคัญเป็นระดับ สูง กลาง ต่ำ โดย **สูง** คือ orphan page หน้าเป้าหมายที่ลึก และ spoke ที่ยังไม่ลิงก์หา hub

## ขั้นที่ 4 ตรวจ hub และ spoke เชิงคุณภาพ

ทุกข้อบันทึกเป็น ผ่าน หรือ ไม่ผ่าน พร้อมเหตุผลสั้น ๆ

| ข้อตรวจ | ผ่านเมื่อ |
|---|---|
| hub ได้ลิงก์ครบ | spoke ทุกหน้าในกลุ่มลิงก์หา hub ตัวเอง |
| hub ส่งกลับครบ | hub ลิงก์หา spoke ทุกหน้าในกลุ่ม |
| orphan ที่หาเจอได้รับแผนครบ | ทุก orphan จากทุกชุดในขั้นที่ 1.5 มีลิงก์เข้าในแผนอย่างน้อยหนึ่งเส้น · ชุดที่ตรวจไม่ได้ ต้องยังคงเขียนกำกับไว้ ห้ามนับเป็นผ่าน |
| หน้าเป้าหมายไม่ลึก | อยู่ระดับ ตื้น หรือ กลาง **และ** hub ที่ดึงมันขึ้นมา ยังไม่แบกลิงก์ออกจนแน่นเกินไป |
| ไม่มี nofollow, sponsored, ugc บนลิงก์ภายใน | ไม่พบสามตัวนี้บนลิงก์ที่ชี้ในเว็บเดียวกัน |
| anchor หลากหลาย | ไม่มีปลายทางไหนถูกชี้ด้วย anchor เดียวทุกเส้น |
| ลิงก์อยู่ในเนื้อหา | เส้นสำคัญไม่พึ่งเมนูหรือ footer |
| ถึง conversion ได้ | จากทุก hub เดินไปถึงหน้า conversion ได้ |
| ช่วยผู้ใช้จริง | ตอบได้ว่าคนอ่านตรงนั้นอยากไปต่อจริง |

**ข้อไหนไม่ผ่าน กลับไปแก้แผนขั้นที่ 3 ก่อนเขียนไฟล์**

## ขั้นที่ 5 แผนลงมือทำ

ตารางคอลัมน์ ลำดับ / หน้า / ลิงก์ที่ต้องเพิ่มหรือแก้ / เหตุผล / ความสำคัญ
เรียงตามความสำคัญ ไม่ใช่ตามที่แก้ง่ายที่สุด

ไฟล์ผลลัพธ์ชื่อเหมือนกันเป๊ะกับที่ประกาศไว้ใน `agent.json`

```
work/{domain}/(00-baseline|01-current)/{domain}_internal-link-plan_{YYYY-MM-DD}.md
```

เนื้อในเรียงตามขั้นที่ 1 ถึง 5 **รวมขั้นที่ 1.5 และ 1.6 ด้วย** นำด้วยสรุปหนึ่งย่อหน้าที่บอกว่าเปิดอ่านจริงกี่หน้า

ตารางที่ต้องมีในไฟล์อย่างน้อยสามชุด

1. **ตารางความลึกคู่จำนวนลิงก์ออก** คอลัมน์ URL / ความลึกที่วัดได้ / เพดานที่ตั้งไว้และตั้งจากขนาดเว็บเท่าไร /
   ลิงก์ในเนื้อหา / ลิงก์โครงเว็บ / รวมต่อหน้า / ธงว่าแก้ข้างหนึ่งแล้วอีกข้างพัง / หลักฐาน
2. **ตาราง orphan** คอลัมน์ URL / โผล่มาจากชุดไหนบ้าง / หลักฐานจากบัญชีรายชื่อ / หลักฐานว่าไม่โผล่ในการไล่เดิน /
   ทางแก้ที่ชี้ / สถานะ พร้อมบรรทัดจำนวนแยกรายชุดและจำนวนรวมที่ตัดตัวซ้ำแล้ว
3. **ตาราง nofollow, sponsored, ugc บนลิงก์ภายใน** คอลัมน์ หน้าต้นทาง / URL ปลายทาง / คำที่เจอ /
   สัดส่วนของลิงก์ภายในบนหน้านั้นที่ติดคำพวกนี้ / สิ่งที่ต้องเปลี่ยน / หลักฐาน
   **ต้องลงให้ครบทุกครั้งที่เจอ ห้ามสุ่ม และห้ามสรุปเหลือแค่ตัวเลขรวม** เพราะคู่ต้นทางกับปลายทางคือสิ่งที่ทำให้แก้ได้

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## แยกลิงก์ตามส่วนของหน้า ก่อนนับทุกครั้ง

ลิงก์จากเมนู footer breadcrumb และ widget ซ้ำกันทุกหน้า **ถ้านับรวมกับลิงก์ในเนื้อหา
ภาพที่ได้จะเพี้ยนทั้งแผน** เพราะจะดูเหมือนทุกหน้าเชื่อมถึงกันดีทั้งที่เนื้อหาไม่ได้ลิงก์หากันเลย

จากไฟล์ HTML ดิบ ให้แยกก่อนว่าลิงก์อยู่ในส่วนไหน โดยดูจากแท็กครอบ

| ส่วน | ดูจาก | นับเป็น |
|---|---|---|
| เมนูและหัวเว็บ | `<header>` `<nav>` | ลิงก์โครงเว็บ ไม่ใช่ลิงก์เนื้อหา |
| ท้ายเว็บ | `<footer>` | ลิงก์โครงเว็บ |
| เส้นทางหน้า | breadcrumb | ลิงก์โครงเว็บ |
| widget แนะนำบทความ | ชื่อคลาสมักมี related, recent, widget | ลิงก์อัตโนมัติ แยกรายงานต่างหาก |
| **ในเนื้อหาจริง** | `<article>` `<main>` หรือบล็อกเนื้อหาหลัก | **ลิงก์ที่แผนนี้สนใจ** |

รายงานต้องแยกตัวเลขสองชุดเสมอ คือ ลิงก์ในเนื้อหา กับ ลิงก์โครงเว็บ

## กฎ

- **ก่อนสรุปว่าหน้าไหนมีลิงก์ในเนื้อหา 0 เส้น ต้องเปิด HTML ดิบของหน้านั้นยืนยันก่อน**
  ห้ามสรุปจากรายการรวมหรือจากหน้าอื่น เพราะการรายงาน 0 ผิด จะทำให้หน้าที่ลิงก์ครบดีอยู่แล้ว
  ถูกยกเป็นงานเร่งด่วนทั้งที่ไม่ต้องทำอะไร และการ์ดหรือปุ่มในเนื้อหาก็นับเป็นลิงก์ด้วย

- **ห้ามคิดการกระจายความสำคัญเป็นตัวเลขหรือสูตร** ใช้ระดับ สูง กลาง ต่ำ เท่านั้น
- **ห้ามรายงานความลึกโดยไม่รายงานจำนวนลิงก์ออกของหน้านั้นบนแถวเดียวกัน**
  และห้ามรายงานจำนวนลิงก์ออกโดยไม่รายงานความลึก สองข้อนี้ตีกันเอง จึงต้องอ่านคู่กันเสมอ
- **ห้ามนิยาม orphan ว่าเป็นหน้าที่ไล่เดินเจอแล้วและไม่มีลิงก์เข้า** ต้องใช้การลบเซตในขั้นที่ 1.5
  และห้ามรายงานว่าไม่มี orphan ถ้าการไล่เดินยังไม่ครบ ให้ลงว่าตรวจไม่ได้พร้อมบอกความครอบคลุม
- **ห้ามแนะนำ nofollow, sponsored หรือ ugc เป็นวิธีกันหน้าออกจากดัชนี** เพราะไม่ได้ผลตามนั้นเลย
  และน้ำหนักที่ถูกตัดจะหายไปเฉย ๆ ไม่ได้ถูกแบ่งไปให้ลิงก์เส้นอื่น
- **ห้ามแต่งชื่อหน้า จำนวนลิงก์ หรือโครงเว็บที่ไม่ได้เห็นจริง** ทุกข้อต้องบอกได้ว่ามาจากหน้าไหน
- **ห้ามแนะนำ anchor ที่ยัดคำค้นซ้ำทุกเส้น** แม้ผู้ใช้ขอ ให้อธิบายความเสี่ยงแทน
- ห้ามเสนอเส้นที่ไม่ช่วยผู้ใช้ เพียงเพราะอยากส่งความสำคัญให้หน้าเป้าหมาย
- **ห้ามแก้เว็บให้** ส่งมอบแผน ผู้ใช้ไปวางลิงก์เอง
- เข้าเว็บไม่ได้หรือไม่มี sitemap ให้บอกตรง ๆ แล้วขอรายการหน้า ห้ามเดา
- **ได้รายการหน้ามาบางส่วน ต้องส่งแผนของส่วนนั้น** ห้ามจบด้วยตารางที่ทุกช่องเขียนว่าประเมินไม่ได้
  และห้ามปฏิเสธทั้งงานเพราะขาดหน้าเป้าหมายหรือคำค้นหลัก
  ทุกแถวติดป้ายว่า **ยืนยันแล้ว** คือเห็นจากหน้าที่เปิดอ่านจริง หรือ **ต้องยืนยันเพิ่ม**
  **การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์**
- **ดึงหน้าหรือ sitemap ไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`**
  สองคำนี้คนละความหมาย เขียนผิดจะกลายเป็นชี้ว่าหน้านั้นเป็น orphan ทั้งที่ยังไม่ได้ตรวจ
