# Content Gap Analysis

ตอบคำถามเดียว **มีเรื่องอะไรที่คนค้นจริงหรือคู่แข่งตอบไปแล้ว แต่เว็บเรายังไม่มี**

ช่องว่างที่ยืนยันได้ต้องมีสองด้าน คือหลักฐานว่าคนค้น และหลักฐานว่าเราไม่มี มีด้านเดียวคือการเดา

---

## ขั้นแรกสุด ดึง HTML ดิบมาก่อน

**ห้ามข้ามขั้นนี้** เพราะ WebFetch คืนเนื้อหาที่แปลงเป็นข้อความแล้ว
ของที่อยู่ใน `<head>` เช่น title, meta description, canonical และ JSON-LD **ถูกตัดทิ้งหมด**
ถ้าตรวจจากผล WebFetch อย่างเดียว จะรายงานว่า **ไม่มี** ทั้งที่มีอยู่จริง ซึ่งเป็นผลลบลวง

```bash
mkdir -p work/{domain}/uploads
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120"
curl -sSL -A "$UA" -m 25 "https://{domain}/" -o work/{domain}/uploads/home.html
```

### ถ้าใช้คำสั่งพวกนี้ไม่ได้

**บาง host ไม่มีเครื่องมือรันคำสั่งให้** เช่น Cowork, Claude Desktop และ GPT desktop
ถ้าเป็นแบบนั้น ให้ทำแบบนี้แทน แล้วงานจะยังเดินต่อได้

1. บอกผู้ใช้ว่า **ขอให้ช่วยเปิดหน้าเว็บแล้วคัดลอกซอร์สมาให้**
   วิธีคือเปิดหน้านั้นในเบราว์เซอร์ กด `Ctrl+U` หรือ `Cmd+Option+U` เพื่อดู source
   แล้วเลือกทั้งหมด คัดลอก มาวางในแชท
2. ถ้าผู้ใช้ทำให้ได้ ให้ทำงานต่อจากซอร์สที่ได้มา ตามขั้นตอนเดิมทุกอย่าง
3. ถ้าผู้ใช้ไม่สะดวก ให้ใช้ WebFetch เท่าที่ได้ แล้ว**เขียนกำกับทุกหัวข้อที่กระทบว่า `ตรวจไม่ได้`**
   ห้ามเขียนว่า `ไม่มี` เพราะสองคำนี้คนละความหมาย และการเขียนผิดจะทำให้ผู้ใช้เข้าใจกลับด้าน

**บน Windows** ถ้ารันแล้วขึ้นว่าไม่รู้จักคำสั่ง ให้ลองใน Git Bash หรือ WSL
ถ้าไม่มีทั้งสองอย่าง ให้ใช้วิธีคัดลอกซอร์สในข้อ 1

ทำแบบเดียวกันกับทุกหน้าที่ต้องตรวจ ตั้งชื่อไฟล์ตามหน้า แล้ว **ใช้ Grep กับไฟล์ที่ดาวน์โหลดมา**

ตัวอย่างคำสั่งที่ใช้บ่อย

```bash
grep -o '<title>[^<]*</title>' work/{domain}/uploads/home.html
grep -o '<meta name="description" content="[^"]*"' work/{domain}/uploads/home.html
grep -o '<link rel="canonical" href="[^"]*"' work/{domain}/uploads/home.html
grep -o '<meta name="robots" content="[^"]*"' work/{domain}/uploads/home.html
sed -n 's/.*<script type="application\/ld+json">\(.*\)<\/script>.*/\1/p' work/{domain}/uploads/home.html
```

**ถ้าดึงหน้าเดิมสองครั้งแล้วได้ค่าไม่ตรงกัน ให้ดึงครั้งที่สาม** แล้วใช้ค่าที่ซ้ำกันสองในสาม
ถ้ายังไม่ตรงอีก ให้บันทึกว่าค่าไม่นิ่ง และห้ามสรุปว่าหน้านั้นผิดกฎ

**ถ้า `curl` ใช้ไม่ได้ในเครื่องผู้ใช้** ให้บอกตรง ๆ แล้วทำเท่าที่ WebFetch ให้ได้
พร้อมเขียนกำกับทุกหัวข้อที่กระทบว่า **ตรวจไม่ได้** ไม่ใช่ **ไม่มี** สองคำนี้คนละความหมาย

## ข้อมูลที่ต้องมี

| ต้องมี | ได้จากไหน |
|---|---|
| โดเมนเรา ขายอะไร ให้ใคร พื้นที่ไหน | ผู้ใช้บอก หรือ `work/{domain}/site.md` |
| รายการหน้าที่มีอยู่จริงบนเว็บเรา | `sitemap.xml` ผ่าน WebFetch หรือผู้ใช้ส่งลิสต์ URL |
| คำตั้งต้น 3 ถึง 5 คำ | ผู้ใช้บอก หรือผลสกิล `seo-keyword-research-lite` |
| คู่แข่ง 2 ถึง 4 โดเมน | ผู้ใช้บอก หรือผลสกิล `seo-competitor-lite` |
| suggestion จริงจาก Google | ขั้นที่ 2 ห้ามแต่งเอง |

ตลาดไทยเก็บทั้งคำไทยและคำอังกฤษของเรื่องเดียวกัน สองภาษาให้ suggestion และคู่แข่งคนละชุด

## ขั้นที่ 1 บัญชีเนื้อหาที่เรามี

ทำก่อนเสมอ **ข้ามขั้นนี้แล้วจะรายงานว่าขาดทั้งที่มีอยู่แล้ว** ดึง `sitemap.xml` ไม่มีก็ขอลิสต์ URL
แล้วเปิดหน้าสำคัญด้วย WebFetch

| URL | หัวข้อหลักของหน้า | ประเภทหน้า | คำถามที่หน้านี้ตอบได้จริง |
|---|---|---|---|

ช่องขวาสุดสำคัญที่สุด เขียนเป็นคำถามแบบที่คนพิมพ์ค้น ไม่ใช่ชื่อหัวข้อ
หลายหน้าชื่อตรงแต่ไม่ได้ตอบคำถามนั้นจริง นั่นก็เป็นช่องว่างแบบหนึ่ง

## ขั้นที่ 2 เก็บคำจาก Google Suggest

**วิธี A แนะนำ** ให้ผู้ใช้พิมพ์คำตั้งต้นในช่องค้นหา Google โดยยังไม่กด Enter แล้วคัดลอกคำที่เด้งมาวาง
ทำทีละชุดตามตาราง

**วิธี B** ลอง WebFetch `https://suggestqueries.google.com/complete/search?client=firefox&hl=th&gl=th&q={คำตั้งต้น}`
ได้ JSON ก็ใช้คำในนั้น ถูกปฏิเสธหรือได้ค่าว่างให้กลับไปวิธี A **ห้ามเขียนผลจำลองแทน**

| ชุดที่ต่อท้ายคำตั้งต้น | ตัวอย่าง | ช่องว่างที่มักโผล่ |
|---|---|---|
| คำถาม | คืออะไร ทำยังไง ทำไม นานแค่ไหน | หน้าให้ความรู้ FAQ |
| เปรียบเทียบ | vs กับ แบบไหนดี ต่างกันยังไง | หน้าเปรียบเทียบ |
| ตัดสินใจซื้อ | ราคา ค่าใช้จ่าย รีวิว ที่ไหนดี | หน้าบริการ หน้าสินค้า |
| ปัญหา | ไม่ได้ พัง แก้ยังไง ผลข้างเคียง | เนื้อหาแก้ปัญหา |
| พื้นที่ | ใกล้ฉัน กรุงเทพ ชื่อย่านของลูกค้า | หน้า local |
| ไล่ตัวอักษร | ต่อท้ายทีละตัว ก ข ค หรือ a b c | คำที่เราคาดไม่ถึง |

จดเฉพาะคำเต็มที่ Google คืนมาจริง พร้อมชุดที่เจอ คำที่โผล่ซ้ำข้ามหลายชุดคือหัวข้อจริง ไม่ใช่คำหลุด
เจอมากน้อยจดได้เป็นหลักฐาน แต่ **ห้ามแปลงเป็นคะแนนหรือสูตรถ่วงน้ำหนัก**

## ขั้นที่ 3 หัวข้อที่คู่แข่งตอบไปแล้ว

WebFetch โดเมนละอย่างน้อย 3 หน้า หน้าแรก หน้าหมวดบทความหรือบริการ และหน้าที่ติดอันดับจริงถ้ามีข้อมูล
มี `sitemap.xml` ให้ดูโครงหมวดด้วย

| หัวข้อที่เขาตอบ | คู่แข่งรายไหน | ประเภทหน้า | ลึกแค่ไหน |
|---|---|---|---|

ความลึกใช้ **ครบ พอใช้ ผิวเผิน** ดูจากมีขั้นตอนจริงไหม มีตัวเลขหรือเคสจริงไหม จบในหน้าเดียวไหม
บันทึกเป็นหัวข้อ ไม่ใช่ URL เปล่า ๆ ดึงไม่ได้ให้บอกว่าโดเมนไหนดึงไม่ได้ **ห้ามเดาว่าเขามีอะไร**

---

## ขั้นที่ 4 จับคู่หาช่องว่าง

ชนสามชุดเข้าด้วยกัน คำจากขั้นที่ 2 หัวข้อคู่แข่งจากขั้นที่ 3 บัญชีของเราจากขั้นที่ 1

| ประเภทช่องว่าง | หมายถึง | ทำอะไรต่อ |
|---|---|---|
| **ไม่มีเลย** | คนค้น คู่แข่งตอบแล้ว เราไม่มีหน้าไหนแตะ | ทำหน้าใหม่ |
| **มีแต่ไม่ตรงคำถาม** | มีหน้าเรื่องนั้น แต่ไม่ได้ตอบคำถามที่คนค้น | แก้หน้าเดิมให้ตอบตรง |
| **มีแต่ตื้นกว่า** | ตอบแล้วแต่คู่แข่งลงลึกกว่าชัดเจน | เติมส่วนที่ขาด |
| **ซ้ำซ้อน** | เรามีหลายหน้าตอบเรื่องเดียวกัน แย่งกันเอง | รวมหน้า ไม่ใช่เขียนเพิ่ม |
| **ไม่ใช่ช่องว่าง** | คนค้นจริงแต่ไม่เกี่ยวกับที่เราขาย | ตัดทิ้ง เขียนเหตุผลกำกับ |

ตัดสินความสำคัญด้วยสามคำถามตามลำดับ ไม่ใช้ตัวเลขและไม่ตั้งสูตรเอง

1. ตรงกับสิ่งที่ธุรกิจขายหรือรับผิดชอบโดยตรงไหม
2. มีหลักฐานว่าคนค้นจริงไหม เช่นโผล่ใน Suggest หลายชุด หรืออยู่ใน People Also Ask
3. คู่แข่งตอบไปหมดแล้วหรือยังไม่มีใครตอบ

| ความสำคัญ | เข้าเกณฑ์แบบไหน |
|---|---|
| **สูง** | ตรงธุรกิจโดยตรง และมีหลักฐานว่าคนค้นจริงจากหลายชุด |
| **กลาง** | ตรงธุรกิจแต่หลักฐานบาง หรือหลักฐานแน่นแต่เกี่ยวกับธุรกิจอ้อม ๆ |
| **ต่ำ** | เกี่ยวไกล หรือเจอครั้งเดียวไม่ซ้ำที่ไหนเลย |

ตัดสินไม่ได้ให้เขียนว่า **ยังตัดสินไม่ได้** พร้อมบอกว่าขาดข้อมูลอะไร ห้ามเดาระดับให้ครบ ๆ

## ขั้นที่ 5 ตารางผลลัพธ์หลัก

| ช่องว่าง | ประเภท | หลักฐาน | คู่แข่งที่ทำไปแล้ว | ความสำคัญ | สิ่งที่ควรทำ |
|---|---|---|---|---|---|

หลักฐานต้องเป็นของจริงอย่างน้อยหนึ่งอย่าง คำเต็มที่ Google คืนมาพร้อมชุดที่เจอ URL คู่แข่งที่ดึงได้จริง
หรือ URL ของเราที่ตรวจแล้วว่าไม่มีเนื้อหานั้น **ห้ามเว้นช่องหลักฐานว่าง** กรอกไม่ได้ให้ย้ายไปหัวข้อยังไม่ยืนยัน

---

## ขั้นที่ 6 บรีฟช่องว่างระดับสูง

ทำเฉพาะระดับสูง ข้อละไม่เกินครึ่งหน้า

| หัวข้อในบรีฟ | เขียนอะไร |
|---|---|
| คำถามหลัก | คำถามเดียวที่หน้านี้ต้องตอบให้จบ ใช้ถ้อยคำแบบที่คนพิมพ์ค้น |
| ประเภทหน้า | บทความ หน้าบริการ หน้าเปรียบเทียบ หรือ FAQ |
| หัวข้อ H2 ที่ควรมี | 3 ถึง 5 ข้อ มาจากคำที่เก็บได้จริงในขั้นที่ 2 |
| หน้าใหม่หรือหน้าเดิม | **มีหน้าใกล้เคียงอยู่แล้วให้เพิ่มในหน้าเดิม** จะได้ไม่แย่งกันเอง |
| ร่าง title และ description | title 50 ถึง 60 ตัวอักษร description 140 ถึง 160 ตัวอักษร |

การนับตัวอักษรไทยใช้กติกาเดียวกับสกิล `meta-basics-lite` สระบน สระล่างและวรรณยุกต์นับเป็น 1 ตัวเสมอ

## ขั้นที่ 7 ส่งออก

ชื่อไฟล์ตาม pattern นี้ ตรงกับที่ประกาศใน `agent.json` ช่อง `output` เหมือนกันเป๊ะ

```
work/{domain}/(00-baseline|01-current)/{domain}_content-gap_{YYYY-MM-DD}.md
```

1. **สรุปหนึ่งย่อหน้า** ช่องว่างที่ใหญ่ที่สุดและควรลงมือก่อน พร้อมเหตุผล
2. **บัญชีเนื้อหาที่เรามี** ตามขั้นที่ 1
3. **คำที่เก็บได้จาก Google Suggest** แยกตามชุด ระบุว่าเก็บด้วยวิธี A หรือ B
4. **หัวข้อที่คู่แข่งตอบไปแล้ว** ตามขั้นที่ 3
5. **ตารางช่องว่างหลัก** เรียงความสำคัญสูงลงต่ำ
6. **บรีฟช่องว่างระดับสูง** ตามขั้นที่ 6
7. **ยังไม่ยืนยันและข้อจำกัด** คำไหนยังไม่มี suggestion จริง โดเมนไหนดึงไม่ได้

## ขอบเขตกับ `seo-competitor-lite` และการสำรวจของที่มีอยู่แล้วแต่ไม่เคยขึ้นดัชนี

- สกิลนี้เป็นเจ้าของแผน content gap และ keyword gap ไฟล์เดียว การระบุคู่แข่งและการจัดชั้นคู่แข่งเป็นของ `seo-competitor-lite`
  ถ้ามีไฟล์คู่แข่งของรอบเดียวกันอยู่แล้ว ให้อ่านก่อนแล้วใช้เป็น input ห้ามจัดชั้นคู่แข่งใหม่เอง รายงานรวมมีแผน gap ฉบับเดียวคือฉบับนี้
- **ก่อนจัดลำดับช่องว่าง ให้สำรวจของที่ลูกค้ามีอยู่แล้วนอกหน้าเว็บ** จดหมายข่าว โบรชัวร์ บทความที่เคยถอดออก วิดีโอที่ยังไม่เผยแพร่
  โพสต์ที่มีแต่บนโซเชียล เช่น LINE broadcast หรือ Facebook เท่านั้น
- **หน้าที่เผยแพร่แล้วแต่ไม่เคยถูก index ให้นับเหมือนยังไม่เผยแพร่** มันไม่ช่วยความครอบคลุมในผลค้นหา ลงในรายการสำรวจนี้ ไม่ใช่ในความครอบคลุมจริง
- จับคู่ของแต่ละชิ้นกับแผนที่ช่องว่าง ชิ้นที่ครอบคลุมหัวข้อที่ขาด ให้วางแผนเผยแพร่ซ้ำเป็นหน้าที่ index ได้ แทนการผลิตใหม่
  และติดป้ายว่าต้นทุนผลิตเกือบศูนย์ ควรอยู่ในกลุ่ม quick wins เมื่อช่องว่างนั้นสำคัญพอ
- ค่าเทรนด์ของคำค้น (ขึ้น ลง นิ่ง ฤดูกาล) เป็นข้อมูลนำเข้าจากการค้นของผู้ใช้หรือ `seo-keyword-research-lite` ไม่คำนวณที่นี่

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## กฎ

- **ห้ามให้คะแนนช่องว่างเป็นตัวเลข** ใช้ สูง กลาง ต่ำ และ ครบ พอใช้ ผิวเผิน เท่านั้น ห้ามตั้งสูตรถ่วงน้ำหนักเอง
- **ห้ามแต่ง suggestion เอง** Google ไม่คืนคำมาให้เขียนว่ายังไม่มีข้อมูลของคำนั้น
- **ห้ามเดา search volume ความยากของคำ หรือทราฟฟิกคู่แข่ง** มีข้อมูลจากเครื่องมือภายนอกให้อ้างพร้อมที่มาและวันที่
- **ห้ามรายงานช่องว่างโดยยังไม่เปิดดูหน้าเราจริง** หลายครั้งหน้านั้นมีอยู่แล้วแค่ชื่อไม่ตรง
- WebFetch เข้าเว็บคู่แข่งไม่ได้ให้รายงานตรง ๆ **ห้ามเดาว่าเขามีเนื้อหาอะไร**
- **ทุกแถวต้องมีหลักฐานกำกับ** ชี้ได้ว่ามาจากคำไหนหรือ URL ไหน
- ข้อมูลไม่พอตรงไหนให้เขียนว่าไม่พอ อย่ากลบด้วยการเดา
- **ขาดข้อมูลบางชุดแล้วยังทำได้บางส่วน ต้องส่งส่วนที่ทำได้เสมอ** เช่นเก็บ suggestion ไม่ได้เลย
  ก็ยังส่งบัญชีเนื้อหาที่เรามีและหัวข้อที่คู่แข่งตอบไปแล้วได้ ห้ามจบด้วยรายงานเปล่า
  ทุกข้อต้องติดป้ายว่า **ยืนยันแล้ว** หรือ **ต้องยืนยันเพิ่ม**
  **การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์**
- **ดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย
  ใช้กับทุกตารางในรายงาน ไม่ใช่แค่ขั้นดึง HTML ดิบ
