## Client workspace routing (mandatory for file changes)

Every generated file has exactly one home. Audit, keyword and comparison
outputs live under `work/{domain}/` created by `new-workspace-lite`
(`00-baseline/` first run, `01-current/` later runs, `02-fixes/`, `03-content/`,
`04-reports/`, `uploads/` read-only for user files); never invent another
top-level folder there. Content production and WordPress publishing use the
client workspace `clients/<client>/` created by `new-client-lite`: read
`workspace-routing.json` first, resolve every artifact with
`{PLUGIN_ROOT}/skills/rainmojo-so-lite/scripts/client_workspace.py route`, use the
most precise registered route, edit root files only when their exact filename is
in `root_policy.allowed_files`, treat `uploads/` as read-only, and when no route
fits use `create-work` then `route-work`; never construct a `work/<name>/...`
path by hand inside a client workspace. Never write generated files to the
plugin tree or the caller's working directory. Append one line to the
workspace's `CHANGELOG.md` or `log.md` after every write. Run
`client_workspace.py validate` before handing a client workspace over. Direct
CMS/API operations retain their own safety and verification gates.

## Presentation (Two-Tier, 7 modes)

Answer in the response mode that matches the request
(`{PLUGIN_ROOT}/skills/rainmojo-so-lite/_base/presentation-scaffold.md`): quick fact,
how-to, comparison, troubleshoot, audit, deployable, always closing with next
steps. A run that writes a deliverable ends with a Tier 1 card built from
`summary.json` (`templates/widget/summary.schema.json`) and rendered with
`{PLUGIN_ROOT}/skills/rainmojo-so-lite/scripts/present.py --target auto`, then hands
off to the Tier 2 file, which stays complete and unchanged. Lite cards carry
counts of checks passed, never a weighted score. Every card value is copied
from the deliverable; unmeasured values show as could not verify. No emoji on
any surface; the glyph allowlist applies to chat and Markdown only.

## ข้อมูลที่ต้องมีก่อนเริ่ม

| ข้อมูล | ใช้ทำอะไร |
|---|---|
| ธุรกิจทำอะไร อยู่วงการไหน | เลือกแหล่งลิงก์ที่เกี่ยวข้องจริง |
| กลุ่มเป้าหมายคือใคร | ตัดสินว่าลิงก์ไหนพาคนที่ใช่เข้ามา |
| เนื้อหาเด่นที่มีอยู่แล้ว | เป็นของที่ใช้เสนอให้เขาลิงก์ถึง |
| คู่แข่งหลัก 3 ถึง 5 ราย | ใช้หาช่องว่างลิงก์ |
| เป้าหมายของรอบนี้ | กันแผนบานปลาย เลือกว่าจะเน้นทางไหนก่อน |

ข้อไหนไม่มี ให้ถามผู้ใช้ก่อน ห้ามเดาแทน
ถ้าผู้ใช้ตอบไม่ได้บางข้อ **ให้เดินงานต่อด้วยข้อมูลเท่าที่มี ห้ามหยุดทั้งงาน**
แล้วเขียนกำกับในรายงานว่าส่วนไหนยืนยันแล้ว ส่วนไหนต้องยืนยันเพิ่มก่อนนำไปใช้

## ขั้นที่ 1 หาโอกาสลิงก์ 4 ทาง

| ทาง | วิธีทำ |
|---|---|
| ช่องว่างจากคู่แข่ง | เปิดดูว่าคู่แข่งถูกลิงก์หรือถูกพูดถึงจากที่ไหน เช่น หน้าข่าว หน้า partner บทความรีวิว ไดเรกทอรี ที่ที่ลิงก์ถึงคู่แข่งหลายรายแต่ยังไม่ลิงก์ถึงเรา คือเป้าแรก |
| แหล่งอำนาจในวงการ | ไล่รายชื่อสมาคมการค้า สื่อและสิ่งพิมพ์ของวงการ บล็อกที่คนในวงการอ่าน ไดเรกทอรีที่มีคนคัดกรอง งานสัมมนาและงานประกาศรางวัล |
| จากเนื้อหาที่เรามี | ดูว่าเนื้อหาชิ้นไหนของเราน่าลิงก์ถึงที่สุด เช่น ข้อมูลหรือสถิติต้นฉบับ คู่มือละเอียด เครื่องมือฟรี เทมเพลต case study |
| จากความสัมพันธ์ที่มีอยู่ | พาร์ทเนอร์ ซัพพลายเออร์ ลูกค้า สถาบันที่เคยร่วมงาน สมาคมที่เป็นสมาชิก คนกลุ่มนี้มีเหตุจะลิงก์ถึงเราอยู่แล้ว เริ่มจากตรงนี้ได้ผลเร็วที่สุด |

สำหรับตลาดไทย ให้เพิ่มสื่อไทย สมาคมไทย และเครือข่ายธุรกิจท้องถิ่นเข้าไปด้วย
การสร้างลิงก์ในไทยพึ่งความสัมพันธ์ส่วนตัวมากกว่าอีเมลเย็น ๆ ถึงคนแปลกหน้า

ผลของขั้นนี้: รายชื่อเว็บเป้าหมาย พร้อมจดว่าเจอจากทางไหน

## ขั้นที่ 2 ประเมินคุณภาพ ดี / เสี่ยง / หลีกเลี่ยง

### ตัดสามแบบนี้ทิ้งก่อน ยังไม่ต้องประเมินอะไรทั้งนั้น

ทำก่อนตารางประเมินข้างล่างเสมอ เพราะเว็บสามแบบนี้ส่งค่าอะไรมาไม่ได้ตั้งแต่โครงสร้าง
ต่อให้หน้าตาดูดีแค่ไหน ก็ไม่ควรเสียเวลาไปติดต่อ

| แบบ | สังเกตจาก |
|---|---|
| เว็บที่ใส่ nofollow ให้ลิงก์ขาออกทุกเส้น | หน้ากติกาหรือหน้าเงื่อนไขของเขาประกาศไว้ หรือเป็นแพลตฟอร์มที่รู้กันว่าทำแบบนั้น |
| เว็บที่เนื้อหาทั้งเว็บมาจากผู้ใช้ล้วน | เว็บบอร์ด เว็บถามตอบ เว็บที่ใครก็เข้าไปแก้ได้ ไม่มีกองบรรณาธิการคัดกรอง |
| เว็บโฮสต์ฟรีที่ใครสมัครก็ได้ subdomain | ชื่อโดเมนเป็น subdomain ของผู้ให้บริการฟรี ใครก็เปิดหน้าใหม่ได้ |

ข้อแรกยืนยันจากหน้าเว็บอย่างเดียวไม่ได้เสมอไป เพราะ WebFetch คืนมาเป็นข้อความที่ถอด attribute ทิ้งแล้ว
ยืนยันไม่ได้ให้ลงว่า **ตรวจไม่ได้** แล้วบอกผู้ใช้ให้เปิดหน้านั้นกด `Ctrl+U`
ดูว่าลิงก์ขาออกมี `rel="nofollow"` ทุกเส้นไหม **ห้ามเดาแทน และห้ามตัดเว็บทิ้งด้วยข้อแรกโดยยังไม่เห็นหลักฐาน**

### แล้วค่อยประเมินที่เหลือ

เปิดดูเว็บเป้าหมายจริงด้วย WebFetch แล้วดู 5 อย่างนี้

| สิ่งที่ดู | คำถาม |
|---|---|
| ความเกี่ยวข้อง | เว็บนี้อยู่วงการเดียวกันหรือใกล้เคียงกับเราไหม |
| คุณภาพเนื้อหา | เนื้อหาเขียนเพื่อคนอ่านจริง มีคนดูแล มีการอัปเดตไหม |
| บริบทลิงก์ | ลิงก์ที่จะได้อยู่ในเนื้อหาหลัก หรืออยู่แค่ footer และ sidebar ข้อนี้ไล่ละเอียดหกข้อในหัวข้อบริบทลิงก์ข้างล่าง |
| ลิงก์ขาออก | เขาลิงก์ออกไปหาใครบ้าง ปนเว็บพนันหรือเว็บขายของผิดกฎหมายไหม |
| ร่องรอยการขายลิงก์ | มีหน้าประกาศรับลงบทความแลกเงิน หรือรับ guest post แบบเหมาโหลไหม |

แล้วตัดสินเป็นระดับเดียวต่อเว็บ

| ระดับ | ลักษณะ | ทำอะไรต่อ |
|---|---|---|
| ดี | เกี่ยวข้องตรงวงการ เนื้อหามีคนดูแลจริง ลิงก์จะอยู่ในเนื้อหา ผู้อ่านเป็นคนจริง | เข้าแผน outreach |
| เสี่ยง | เกี่ยวข้องแค่บางส่วน โฆษณาแน่น ลิงก์ขาออกเยอะผิดปกติ หรือดูร้างไม่อัปเดต | หาข้อมูลเพิ่มก่อน ยังไม่ติดต่อ |
| หลีกเลี่ยง | ขายลิงก์โจ่งแจ้ง เป็นฟาร์มลิงก์ เนื้อหาไม่เกี่ยวกับเราเลย หรือเป็นหน้ารวมลิงก์ล้วน | ตัดออก จดเหตุผลไว้กันหยิบมาใหม่ |

เว็บที่เปิดดูไม่สำเร็จ เช่น โดนกั้นหรือโหลดไม่ขึ้น ให้ลงว่า **ตรวจไม่ได้** พร้อมบอกว่าติดตรงไหน
**ห้ามลงว่า ดี เสี่ยง หรือ หลีกเลี่ยง ให้ และห้ามเขียนว่า ไม่มี** เพราะยังไม่ได้เห็นเว็บจริง
เว็บกลุ่มนี้ยังต้องอยู่ในตารางผลลัพธ์ ห้ามตัดทิ้งเงียบ ๆ

หมายเหตุ: ตัวเลขอำนาจโดเมนจากเครื่องมือเอกชน เช่น DA หรือ DR เป็นค่าประมาณของบริษัทเอกชน
ไม่ใช่ค่าของ Google รุ่นนี้ให้ตัดสินจากการเปิดดูเว็บจริงตามตารางข้างบน ไม่ใช้ตัวเลขตัดสินแทน

### บริบทลิงก์ ให้ไล่ถามหกข้อนี้ตามลำดับ

ลิงก์หนึ่งเส้นมีค่าไม่เท่ากันตามบริบทที่มันอยู่ ไล่จากวงในออกวงนอก
ยิ่งหลายข้อตอบไปทางเดียวกัน ลิงก์เส้นนั้นยิ่งมีค่า

1. **หน้าที่จะลิงก์มาหาเรา มีคนลิงก์ถึงเขาบ้างไหม** หน้าที่ไม่มีใครลิงก์ถึงเลย ส่งต่อได้น้อย
   รุ่นนี้ไม่มีเครื่องมือดูลิงก์ขาเข้า ให้ดูจากสัญญาณที่เห็นได้แทน เช่น หน้านั้นถูกลิงก์จากหน้าอื่นในเว็บเดียวกันไหม
   เป็นหน้าที่เขาเอาไว้ในเมนูหลักไหม หรือมีคนคอมเมนต์ถึงไหม ดูไม่ได้ให้ลงว่า **ตรวจไม่ได้** เฉพาะข้อนี้
2. **ลิงก์จะอยู่ในเนื้อหาหลัก หรืออยู่ในส่วนประกอบของหน้า** เช่น footer, sidebar หรือแถบที่ขึ้นทุกหน้า
3. **ข้อความก่อนหน้าและหลังจุดที่ลิงก์ พูดเรื่องเดียวกับหน้าปลายทางไหม**
4. **หัวข้อที่ใกล้จุดลิงก์ที่สุดพูดเรื่องอะไร** บรรทัดสั้น ๆ ที่ทำตัวหนาโดด ๆ ให้นับเป็นหัวข้อด้วย
5. **ทั้งหน้านั้นพูดเรื่องอะไร**
6. **ทั้งเว็บนั้นพูดเรื่องอะไร**

เว็บที่มีหน้าเกี่ยวข้องกับเราหลายร้อยหน้าและลิงก์มาจากหน้าที่ตรงเรื่อง
มีค่ากว่าเว็บที่มีหน้าเกี่ยวข้องกับเราอยู่หน้าเดียว
ข้อไหนดูไม่ได้จากที่เห็น ให้ลงว่า **ตรวจไม่ได้** เฉพาะข้อนั้น ไม่ต้องทิ้งทั้งเว็บ

## ขั้นที่ 3 จัดลำดับความสำคัญ

| ลำดับ | เงื่อนไข |
|---|---|
| สูง | ประเมินได้ ดี และมีช่องทางติดต่อหรือมีเหตุให้เขาลิงก์ชัดเจน เช่น เขามีลิงก์เสีย หรือรู้จักกันอยู่แล้ว |
| กลาง | ประเมินได้ ดี แต่ยังไม่มีจุดเชื่อม ต้องสร้างความสัมพันธ์ก่อนถึงจะขอได้ |
| ต่ำ | ประเมินได้ เสี่ยง หรือโอกาสได้จริงน้อยมาก เก็บไว้พิจารณารอบหน้า |

## ขั้นที่ 4 แผน outreach ทีละขั้น

1. **ทำการบ้านก่อนติดต่อ** อ่านเนื้อหาล่าสุดของเขาจริง หาชื่อคนดูแลหรือบรรณาธิการ
   ห้ามส่งข้อความแบบหว่านถึง "ท่านผู้เกี่ยวข้อง"
2. **เลือกรูปแบบข้อเสนอให้ตรงสถานการณ์**

   | สถานการณ์ของเว็บเป้าหมาย | ข้อเสนอที่ใช้ |
   |---|---|
   | มีลิงก์เสียในหน้า resource ของเขา | แจ้งลิงก์เสียอย่างสุภาพ พร้อมเสนอเนื้อหาเราเป็นตัวแทน |
   | มีหน้า resource รวมของดีในวงการ | เสนอเนื้อหาเราเข้าไป พร้อมอธิบายว่าเติมอะไรที่หน้านั้นยังขาด |
   | เปิดรับบทความจากคนนอก | เสนอ guest content ที่ผู้อ่านของเขาได้ประโยชน์จริง ไม่ใช่บทความโฆษณา |
   | อยากได้ทั้งเนื้อหาและความสัมพันธ์ | ชวนสัมภาษณ์ผู้เชี่ยวชาญ หรือทำเนื้อหาร่วมกันแล้วต่างฝ่ายต่างอ้างถึง |
   | เป็นสมาคมหรือไดเรกทอรีของวงการ | สมัครสมาชิกหรือส่งข้อมูลตามช่องทางปกติของเขา |

3. **เขียนข้อความแรกโดยตั้งต้นว่าไม่ขอลิงก์**
   ข้อความมาตรฐานคือเสนอคุณค่าให้ผู้อ่านของเขา โดยไม่มีการขอลิงก์อยู่ในนั้นเลย
   โครงคือ เปิดด้วยสิ่งที่อ่านเจอบนเว็บเขาจริงหนึ่งประโยค ตามด้วยคุณค่าที่ผู้อ่านของเขาจะได้
   ภาษาไทยให้ใช้ภาษาสุภาพเป็นธรรมชาติ ไม่ใช้สำนวนแปลจากอีเมลฝรั่ง

   **ขอลิงก์ตรง ๆ ในข้อความแรกได้เฉพาะ 4 กรณีนี้เท่านั้น**

   | กรณี | ขออะไร |
   |---|---|
   | เขาลิงก์มาหาเราอยู่แล้ว แต่ URL ปลายทางย้ายไปแล้ว | ขอให้แก้ปลายทางให้ถูก |
   | ลิงก์ที่เขาใส่ไว้เสียหรือพิมพ์ผิด | แจ้งให้แก้ |
   | เขาเอ่ยชื่อแบรนด์เราอยู่แล้วแต่ไม่ได้ทำเป็นลิงก์ | ขอให้ใส่ลิงก์ที่ชื่อนั้น |
   | หน้านั้นเป็นหน้ารวมของดีที่คัดมาจริง ไม่ใช่หน้าเทลิงก์ | เสนอตัวเข้าไปอยู่ในรายการ |

4. **ติดตามผลแบบจำกัด แล้วหยุด** เงียบไปให้เว้นระยะก่อน แล้วตามได้อย่างจำกัด
   ตามแต่ละครั้งให้เปลี่ยนมุมข้อเสนอ ไม่ใช่ส่งข้อความเดิมซ้ำ
   ครบแล้วยังเงียบ ให้พักรายนั้นไว้ก่อนแล้วไปทำรายอื่น การตื๊อทำลายชื่อแบรนด์
5. **รักษาความสัมพันธ์ระยะยาว** จดทุกคนที่ตอบกลับแม้ยังไม่ได้ลิงก์
   ส่งของมีประโยชน์ให้เป็นระยะ ความสัมพันธ์วันนี้คือลิงก์ของรอบหน้า

### เขาเสนอแลกลิงก์มาเอง ให้ทดสอบที่ตำแหน่ง

**เราไม่เสนอแลกลิงก์ก่อนเด็ดขาด** แต่ถ้าอีกฝ่ายเสนอมา ไม่ต้องปฏิเสธทันที ให้ดูสองข้อนี้

| เงื่อนไข | ผล |
|---|---|
| เว็บเขาเป็นแหล่งที่มีประโยชน์จริงกับคนอ่านของเรา และลิงก์วางในเนื้อหาหลักได้อย่างเป็นธรรมชาติ | รับได้ |
| ลิงก์จะไปลงที่ footer, sidebar หรือหน้ารวมลิงก์ | ปฏิเสธ เพราะเป็นรูปแบบเดียวกับฟาร์มลิงก์ |

การไล่แลกลิงก์เป็นระบบกับหลาย ๆ เว็บ ยังห้ามอยู่เหมือนเดิม ไม่ว่าตำแหน่งจะดีแค่ไหน

### กวาดที่ที่เอ่ยถึงเราแล้วแต่ยังไม่ได้ลิงก์ ให้ทำก่อนเรื่องอื่น

ได้ผลเร็วที่สุด เพราะหน้านั้นพูดถึงเราอยู่แล้ว ไม่ต้องเริ่มจากศูนย์
สกิลนี้ไม่มีเครื่องมือค้นเว็บ ให้ผู้ใช้ค้นตามรายการนี้แล้วส่ง URL กลับมา แล้วสกิลค่อยเปิดตรวจด้วย WebFetch

ค้นให้กว้างกว่าชื่อแบรนด์ ชื่อสินค้า และชื่อผู้บริหาร โดยค้นเพิ่มด้วย

- ชื่อบทความหรือชื่อหน้าของเราแบบเป๊ะ ๆ
- ข้อความ alt ของรูปที่เราทำเอง
- ชื่อไฟล์ที่เราเผยแพร่ ทั้งรูป ไฟล์ PDF และไฟล์เอกสาร
- URL ของเราที่ถูกวางเป็นข้อความเปล่า ๆ ไม่ได้ทำเป็นลิงก์

ตั้งการแจ้งเตือนไว้สำหรับการเอ่ยถึงครั้งใหม่ และทุกครั้งที่เจอ ให้จดด้วยว่า
เขาลิงก์ไปที่อื่นแทนเราเพราะอะไร เพราะนั่นคือช่องว่างของเนื้อหาเราที่ต้องอุด

## ขั้นที่ 5 anchor text และตำแหน่งลิงก์

| เรื่อง | แนวทาง |
|---|---|
| anchor หลัก | ชื่อแบรนด์หรือ URL ตรง ๆ ควรเป็นสัดส่วนใหญ่ที่สุด เพราะเป็นรูปแบบธรรมชาติ |
| anchor รอง | ประโยคบรรยายทั่วไป เช่น "อ่านคู่มือเรื่องนี้ได้ที่" |
| anchor คำค้นตรง | ใช้น้อยที่สุด การยัดคำค้นเดียวกันซ้ำ ๆ ใน anchor คือรูปแบบที่โดนลงโทษบ่อย |
| ตำแหน่งลิงก์ | ลิงก์ในเนื้อหาหลักมีค่ากว่าลิงก์ใน footer, sidebar หรือหน้ารวมลิงก์ |

เราคุมข้อความ anchor ของเว็บคนอื่นไม่ได้ทั้งหมด และไม่ควรพยายามคุม
ลิงก์ที่เกิดตามธรรมชาติย่อมหลากหลายอยู่แล้ว

### สองอย่างที่ห้ามขอจากเจ้าของเว็บเด็ดขาด

- **ห้ามระบุให้เขาว่าต้องใช้คำไหนเป็นข้อความลิงก์** การสั่งข้อความลิงก์ถูกนับว่าเป็นการปั่น
  ทำได้อย่างมากแค่ส่ง URL ให้ แล้วปล่อยให้เขาเลือกคำเอง
- **ห้ามขอให้เขาถอด nofollow ออกจากลิงก์ที่ให้มาแล้ว** ผลที่เกิดขึ้นบ่อยที่สุดคือเขาลบลิงก์นั้นทิ้งไปเลย
  ให้ขอบคุณแล้วเก็บลิงก์นั้นไว้อย่างที่เป็น

---

## ขั้นที่ 6 ติดตามผลและดูแลต่อ

- จดทุกลิงก์ที่ได้ วันที่ ได้จากหน้าไหน anchor อะไร มาจากข้อเสนอแบบไหน
- ตรวจซ้ำเป็นระยะว่าลิงก์ยังอยู่และหน้านั้นยังเข้าถึงได้
- หน้าไหนของเราได้ backlink ดี ให้ทำ internal link จากหน้านั้นไปยังหน้าสำคัญ เพื่อส่งต่อคุณค่า
- ข้อเสนอแบบไหนได้ลิงก์จริง จดไว้ทำซ้ำ แบบไหนเงียบทุกครั้ง เลิกใช้

## ผลลัพธ์

ไฟล์เดียว ชื่อและที่อยู่ตามนี้ เหมือนกันเป๊ะกับที่ประกาศใน agent.json

```
work/{domain}/(00-baseline|01-current)/{domain}_backlink-strategy_{YYYY-MM-DD}.md
```

โครงในไฟล์

1. สรุปกลยุทธ์หนึ่งย่อหน้า
2. ตารางโอกาสลิงก์ คอลัมน์ แหล่ง / เจอจากทางไหน / ประเมิน (ดี เสี่ยง หลีกเลี่ยง) / ลำดับ (สูง กลาง ต่ำ) / รูปแบบข้อเสนอ
   เว็บที่ตกด่านสามแบบในขั้นที่ 2 ให้แยกไว้อีกตาราง พร้อมเหตุผลว่าตกด้วยข้อไหน
3. รายการที่ที่เอ่ยถึงเราแล้วแต่ยังไม่ได้ลิงก์ พร้อมสิ่งที่จะขอ ทำก่อนรายการอื่น
4. ร่างข้อความ outreach ต่อกลุ่มสถานการณ์ พร้อมช่องให้เติมข้อมูลจริง
   ร่างมาตรฐานต้องไม่มีการขอลิงก์ ยกเว้น 4 กรณีในขั้นที่ 4
5. แผนติดตามผล ใครติดต่อเมื่อไร ตามซ้ำแบบจำกัดแล้วหยุดตอนไหน
6. ข้อจำกัดของแผนรอบนี้ อะไรที่ยังไม่รู้และต้องหาข้อมูลเพิ่ม

---

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## กฎ

- **ห้ามเดาตัวเลขและห้ามแต่งข้อมูล** เช่น จำนวนลิงก์ของคู่แข่ง ปริมาณ traffic
  หรือรายชื่อเว็บที่ไม่ได้เปิดดูจริง
- **ถ้าดึงข้อมูลไม่สำเร็จให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`**
  สองคำนี้คนละความหมาย เขียนผิดทำให้ผู้ใช้สรุปกลับด้าน คำว่าไม่มีใช้ได้เฉพาะตอนเห็นจริงแล้วว่าไม่มี
- **ห้ามให้คะแนนเว็บเป็นตัวเลขทุกรูปแบบ** ใช้ ดี เสี่ยง หลีกเลี่ยง และ สูง กลาง ต่ำ เท่านั้น
  เว็บที่เปิดดูไม่สำเร็จให้ลงว่า ตรวจไม่ได้
- **ห้ามแนะนำการซื้อลิงก์ แลกลิงก์เป็นระบบ PBN หรือวิธี black-hat ทุกชนิด** แม้ผู้ใช้ร้องขอ
  ส่วนกรณีที่อีกฝ่ายเสนอแลกลิงก์มาเอง ให้ใช้การทดสอบตำแหน่งในขั้นที่ 4 ตัดสิน
- **ห้ามระบุข้อความลิงก์ให้เจ้าของเว็บอื่น และห้ามขอให้เขาถอด nofollow ออกจากลิงก์ที่ให้มาแล้ว**
- **ห้ามใส่การขอลิงก์ลงในข้อความติดต่อฉบับแรก** ยกเว้น 4 กรณีที่ระบุไว้ในขั้นที่ 4
- **ห้ามแต่งชื่อบุคคล อีเมล หรือช่องทางติดต่อ** ที่ไม่ได้เห็นจากเว็บจริง ถ้าหาไม่เจอให้บอกว่าหาไม่เจอ
- WebFetch เข้าได้เฉพาะหน้าสาธารณะ ถ้าเว็บกั้นไว้ให้รายงานตรง ๆ แล้วเสนอให้ผู้ใช้คัดลอกเนื้อหามาวางแทน
- ถ้าข้อมูลไม่พอจะสรุป ให้บอกตรง ๆ ว่าไม่พอ และบอกว่าต้องการอะไรเพิ่ม
- **ทำได้บางส่วนต้องส่งส่วนนั้นเสมอ ห้ามส่งงานเปล่าและห้ามปฏิเสธทั้งงาน**
  เช่น เปิดเว็บเป้าหมายไม่ได้เลย ก็ยังต้องส่งรายชื่อแหล่งที่หาได้ ร่างข้อความ outreach และแผนติดตามผล
  พร้อมติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม
  **การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์**
