# Competitor Analysis

ตอบสองคำถาม **ใครแย่งหน้าแรกไปจริง** และ **เขามีอะไรที่เรายังไม่มี**
คู่แข่งที่เจ้าของธุรกิจนึกถึง มักไม่ใช่คนเดียวกับที่ครองหน้าค้นหา

## ขั้นแรกสุด ดึง HTML ดิบมาก่อน

**ห้ามข้ามขั้นนี้** เพราะ WebFetch คืนเนื้อหาที่แปลงเป็นข้อความแล้ว
ของที่อยู่ใน `<head>` เช่น title, meta description, canonical และ JSON-LD **ถูกตัดทิ้งหมด**
ถ้าตรวจจากผล WebFetch อย่างเดียว จะรายงานว่า **ไม่มี** ทั้งที่มีอยู่จริง ซึ่งเป็นผลลบลวง

```bash
mkdir -p work/{domain}/uploads
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120"
curl -sSL -A "$UA" -m 25 "https://{domain}/" -o work/{domain}/uploads/home.html
```

### ถ้าใช้คำสั่งพวกนี้ไม่ได้

**บาง host ไม่มีเครื่องมือรันคำสั่งให้** เช่น Cowork, Claude Desktop และ GPT desktop
ถ้าเป็นแบบนั้น ให้ทำแบบนี้แทน แล้วงานจะยังเดินต่อได้

1. บอกผู้ใช้ว่า **ขอให้ช่วยเปิดหน้าเว็บแล้วคัดลอกซอร์สมาให้**
   วิธีคือเปิดหน้านั้นในเบราว์เซอร์ กด `Ctrl+U` หรือ `Cmd+Option+U` เพื่อดู source
   แล้วเลือกทั้งหมด คัดลอก มาวางในแชท
2. ถ้าผู้ใช้ทำให้ได้ ให้ทำงานต่อจากซอร์สที่ได้มา ตามขั้นตอนเดิมทุกอย่าง
3. ถ้าผู้ใช้ไม่สะดวก ให้ใช้ WebFetch เท่าที่ได้ แล้ว**เขียนกำกับทุกหัวข้อที่กระทบว่า `ตรวจไม่ได้`**
   ห้ามเขียนว่า `ไม่มี` เพราะสองคำนี้คนละความหมาย และการเขียนผิดจะทำให้ผู้ใช้เข้าใจกลับด้าน

**บน Windows** ถ้ารันแล้วขึ้นว่าไม่รู้จักคำสั่ง ให้ลองใน Git Bash หรือ WSL
ถ้าไม่มีทั้งสองอย่าง ให้ใช้วิธีคัดลอกซอร์สในข้อ 1

ทำแบบเดียวกันกับทุกหน้าที่ต้องตรวจ ตั้งชื่อไฟล์ตามหน้า แล้ว **ใช้ Grep กับไฟล์ที่ดาวน์โหลดมา**

ตัวอย่างคำสั่งที่ใช้บ่อย

```bash
grep -o '<title>[^<]*</title>' work/{domain}/uploads/home.html
grep -o '<meta name="description" content="[^"]*"' work/{domain}/uploads/home.html
grep -o '<link rel="canonical" href="[^"]*"' work/{domain}/uploads/home.html
grep -o '<meta name="robots" content="[^"]*"' work/{domain}/uploads/home.html
sed -n 's/.*<script type="application\/ld+json">\(.*\)<\/script>.*/\1/p' work/{domain}/uploads/home.html
```

**ถ้าดึงหน้าเดิมสองครั้งแล้วได้ค่าไม่ตรงกัน ให้ดึงครั้งที่สาม** แล้วใช้ค่าที่ซ้ำกันสองในสาม
ถ้ายังไม่ตรงอีก ให้บันทึกว่าค่าไม่นิ่ง และห้ามสรุปว่าหน้านั้นผิดกฎ

**ถ้า `curl` ใช้ไม่ได้ในเครื่องผู้ใช้** ให้บอกตรง ๆ แล้วทำเท่าที่ WebFetch ให้ได้
พร้อมเขียนกำกับทุกหัวข้อที่กระทบว่า **ตรวจไม่ได้** ไม่ใช่ **ไม่มี** สองคำนี้คนละความหมาย

## ขั้นที่ 1 ระบุคู่แข่งจริง

| ประเภท | หมายถึง | ความสำคัญ |
|---|---|---|
| **ตรง** | ขายแบบเดียวกัน ลูกค้ากลุ่มเดียวกัน | สูง |
| **SERP** | ติดอันดับคำเดียวกับเรา ไม่ว่าทำธุรกิจอะไร | สูง |
| **อ้อม** | แก้ปัญหาเดียวกันด้วยวิธีอื่น | กลาง |
| **ต้นแบบ** | ผู้นำวงการ ไว้ดูเพดานเนื้อหา | ต่ำ |

ให้ผู้ใช้ค้นทีละคำ จดโดเมนที่ติดหน้าแรกครบทุกคำ ใครโผล่เกินครึ่งของคำค้นคือคู่แข่ง SERP หลัก
คู่แข่งตรงที่ผู้ใช้บอกแต่ไม่ติดเลย ให้บันทึกว่าไม่ติด รายที่เพิ่งโผล่และออกของใหม่ถี่ กำกับว่ามาแรง

**ตลาดไทย** ค้นแยกสองภาษา เก็บคู่แข่งสองชุด มีหน้าร้านให้เติมชื่อพื้นที่ท้ายคำ
แบรนด์ต่างชาติมักแปลแข็งไม่ตอบบริบทไทย ตรงนั้นคือช่องของเรา

## ชุดคำสั่งค้นหาที่ใช้สอบคู่แข่ง

สกิลนี้ค้น Google เองไม่ได้ **ให้ประกอบคำค้นตามนี้ แล้วส่งให้ผู้ใช้ไปวางในช่องค้นหา
แล้วเอาผลกลับมา** ไวยากรณ์ข้างล่างเป็นของสาธารณะที่ค้นหาอ่านได้เอง ไม่ใช่ของลับ

| ใช้ทำอะไร | ไวยากรณ์ |
|---|---|
| จำกัดเฉพาะเว็บเดียว | `site:example.com` |
| รวมทุกซับโดเมน | `site:*.example.com` |
| จำกัดเฉพาะนามสกุลไฟล์ | `filetype:pdf` |
| anchor text คำเดียว | `inanchor:word` |
| anchor text หลายคำ | `allinanchor: two words` **ต้องมีเว้นวรรคหลังทวิภาค** ไม่มีเว้นวรรคจะไม่ทำงานแบบหลายคำ |
| กำหนดขอบวันที่ | `before:2026-08-15` และ `after:2026-08-15` ใส่เป็นปีเดือนวัน ปีเดือน หรือปีเปล่าก็ได้ ปีเปล่าจะกลายเป็น 1 มกราคมของปีนั้น ใช้คู่กันเพื่อคร่อมช่วงเวลา |
| ตัดคำออก | `-term` ขีดนำหน้าใช้ได้ทั้งกับคำธรรมดาและกับตัวดำเนินการ |
| อย่างใดอย่างหนึ่ง | `a \| b` หรือ `a OR b` |
| แทนคำที่ไม่รู้ | `*` ใช้เมื่อรายการทางเลือกยาวเกินกว่าจะไล่ครบ |

- **พิมพ์ไวยากรณ์ผิดแม้นิดเดียวคือพัง** ตัวดำเนินการที่พิมพ์หลวม ๆ จะกลายเป็นคำค้นธรรมดาแบบเงียบ ๆ
  แล้วคืนผลที่ดูสมเหตุสมผลแต่ไม่ได้แปลว่าอะไรเลย ซึ่งอันตรายกว่าการขึ้น error
- **ตัวดำเนินการหลายตัวรวมในคำค้นเดียวได้** ถ้าไม่ขัดกันเอง ให้ประกอบเป็นคำค้นเดียว
  ดีกว่าค้นทีละส่วนแล้วมานั่งรวมผลด้วยมือ
- **ชุดที่รองรับเปลี่ยนได้ตามเวลา** ตัวที่เลิกรองรับมักไม่ขึ้น error แต่คืนผลกว้างผิดปกติแทน
  **ผลที่กว้างผิดปกติคืออาการที่ต้องกลับไปยืนยันใหม่ ไม่ใช่ตัวเลขที่เอาไปรายงาน**
- **ทุกตัวเลขที่ได้จากคำค้นเหล่านี้ ต้องแนบคำค้นเป๊ะ ๆ และวันที่ค้น** ค้นไม่ได้ให้เขียน
  `ตรวจไม่ได้` **ห้ามเขียนเป็นศูนย์**

## แบรนด์คู่แข่งกำลังมาหรือกำลังซา

- ค้นชื่อแบรนด์คู่แข่งสองรอบด้วย **คำค้นเดียวกันเป๊ะ** รอบแรกจำกัดช่วงเวลาที่ **ยาวกว่า**
  รอบสองจำกัด **ช่วงล่าสุดที่สั้นกว่า** และต้องใช้วิธีจำกัดช่วงเวลาแบบเดียวกันทั้งสองรอบ
  จะใช้คู่ `before:` กับ `after:` หรือใช้ตัวกรองเวลาบน URL ผลค้นก็ได้ แต่ต้องเป็นวิธีเดียวกัน
- **ความสัมพันธ์ระหว่างสองค่านี้บอกว่าการถูกพูดถึงกำลังเร่งขึ้นหรือกำลังซาลง**
  ให้รายงานเป็นทิศทาง พร้อมค่าทั้งสองและคำค้นที่ใช้วางไว้ข้าง ๆ
- **นับการถูกพูดถึง ไม่ใช่นับลิงก์** เพราะคนส่วนใหญ่พูดถึงแบรนด์โดยไม่ลิงก์และไม่เอ่ยชื่อโดเมน
  การนับลิงก์จึงวัดได้แค่เศษเสี้ยวเล็ก ๆ ที่ไม่เป็นตัวแทนของบทสนทนาจริง
- **จำนวนผลลัพธ์ที่ search engine แสดงเป็นค่าประมาณ ไม่ใช่ค่าที่นับมาจริง**
  **ห้ามเอาสองค่านั้นมาหารกันแล้วเสนอเป็นอัตราส่วนที่วัดมาได้**
- **อายุเว็บกับอายุโดเมนคนละเรื่องกัน** ให้แยกกันดู วันจดทะเบียนบอกอายุของชื่อ
  ส่วนภาพเก็บย้อนหลังที่เก่าที่สุดบอกอายุของเว็บ ถ้าสองค่านี้ห่างกันมาก **ช่องว่างนั้นคือข้อค้นพบ**
  เอาไปอ่านคู่กับโมเมนตัมด้านบน เว็บใหม่ที่ถูกพูดถึงเร่งขึ้น กับโดเมนเก่าที่ถูกพูดถึงซาลง
  เป็นคนละสถานการณ์กันคนละขั้ว ซึ่งตัวเลขอายุค่าเดียวจะกลบทิ้ง
- ฝั่งแบรนด์ของลูกค้าเอง การถูกพูดถึงรายแพลตฟอร์มเป็นของสกิล `aiso-brand-mentions-lite`
  ให้ใช้ผลจากสกิลนั้น **ห้ามออกผลชุดที่สองมาแข่งกันเอง**

## ขั้นที่ 3 ดึงหน้าคู่แข่งมาอ่าน

WebFetch คู่แข่งความสำคัญสูง โดเมนละ 3 หน้า หน้าแรก หน้าบริการหลัก หน้าที่ติดอันดับจริง
มี `sitemap.xml` ให้ดูหมวดหมู่ด้วย แล้วเทียบฝั่งเราเป็น ดี พอใช้ ต้องแก้ ทีละด้าน

| ด้าน | ดูอะไร |
|---|---|
| **เนื้อหา** | หัวข้อที่ครอบคลุม ความลึก รูปแบบหน้า ความถี่ที่ออกของใหม่ |
| **โครงสร้าง** | title, H1 ถึง H2, โครง URL, การแยกหน้าย่อยรายบริการ |
| **ความน่าเชื่อถือ** | ผู้เขียนมีตัวตนไหม แหล่งอ้างอิง รีวิว เคสจริง |
| **เทคนิคที่เห็นได้** | มี schema ไหม เปิดไวไหม อ่านบนมือถือรู้เรื่องไหม |

เทียบ title ให้นับแบบ `meta-basics-lite` สระและวรรณยุกต์นับ 1 ตัวเสมอ
title 50 ถึง 60 ตัวอักษร description 140 ถึง 160 ตัวอักษร

## ห้ามส่งตารางเปล่า

**ข้อนี้สำคัญที่สุดของสกิลนี้** ถ้าส่งตารางที่ทุกช่องเขียนว่า ประเมินไม่ได้ เท่ากับไม่ได้ทำงาน
และผู้ใช้ยังต้องเริ่มจากศูนย์อยู่ดี ซึ่งแย่กว่าไม่ส่งอะไรเลย เพราะเสียเวลาอ่าน

**สกิลนี้ค้นหน้าผลค้นหาเองไม่ได้ก็จริง แต่มี WebFetch ซึ่งพอแล้ว** ให้ทำแบบนี้แทน

1. ถามผู้ใช้ว่ารู้จักคู่แข่งรายไหนบ้าง ถ้าตอบได้ ใช้รายชื่อนั้นเป็นตัวตั้ง
2. ถ้าผู้ใช้ไม่รู้ ให้ดูจากเว็บตัวเองก่อน ว่าอยู่หมวดธุรกิจอะไร ในพื้นที่ไหน แล้วให้ผู้ใช้ค้นคำหลัก 3 คำบน Google
   แล้วส่งชื่อโดเมนที่เห็นกลับมาให้
3. **ต้องได้อย่างน้อย 3 โดเมน** แล้ว WebFetch หน้าแรก หน้าบริการ และหน้าราคาของแต่ละราย
4. ถ้าได้ไม่ถึง 3 ให้บอกตรง ๆ ว่าได้เท่าไร แล้วทำกับเท่าที่ได้ **ห้ามหยุดงาน**

**เรื่องอันดับ SERP** สกิลนี้ยืนยันอันดับจริงไม่ได้ ให้เขียนกำกับไว้ทุกครั้งว่า
`รายชื่อนี้คือคู่แข่งที่ผู้ใช้ระบุหรือที่เห็นร่วมชุดผลลัพธ์ ยังไม่ได้ยืนยันอันดับบน Google`
**การเขียนกำกับแบบนี้คือความซื่อสัตย์ ส่วนการไม่ส่งงานเลยคือการใช้ข้อจำกัดเป็นข้ออ้าง**

## เทียบชนต่อชน

ดึงหน้าประเภทเดียวกันของเรากับของเขามาวางคู่กัน แล้วเทียบทีละหัวข้อ

| หัวข้อที่เทียบ | ดูอะไร |
|---|---|
| โครงหัวข้อ | นับ H2 และ H3 ว่าเขาแตกหัวข้อละเอียดกว่าเราไหม หัวข้อไหนที่เขามีแต่เราไม่มี |
| ราคา | เขาบอกราคาจริงไหม หรือเขียนว่าติดต่อสอบถาม |
| หลักฐาน | มีรีวิว เลขใบอนุญาต ชื่อผู้เชี่ยวชาญ หรือเคสจริงไหม |
| schema | มี JSON-LD ประเภทไหนบ้างที่เราไม่มี |
| การรับประกัน | มีเงื่อนไขคืนเงินหรือรับประกันที่เขียนชัดไหม |

**ทุกช่องต้องมีข้อความจริงจากหน้าเว็บกำกับ** เช่น เขียนว่า พบข้อความ รับประกัน 90 วัน บนหน้าราคา
ห้ามเขียนแค่ว่า ดีกว่า หรือ แย่กว่า โดยไม่มีของจริงประกอบ

## ขั้นที่ 4 ตาราง gap

| หัวข้อหรือคำค้น | คู่แข่งมี ใคร รูปแบบไหน | เรามี | ช่องว่าง | ความสำคัญ | สิ่งที่ควรทำ |
|---|---|---|---|---|---|

ช่องว่าง **ไม่มีเลย / ตื้นกว่า / เทียบเท่า** ความสำคัญ **สูง กลาง ต่ำ** ดูจากตรงกับธุรกิจและความถี่ใน SERP

| คำที่คู่แข่งทำหน้าเฉพาะแต่เราไม่มี | ใครทำ | ประเภทหน้า | ทำหน้าใหม่หรือเพิ่มในหน้าเดิม |
|---|---|---|---|

เขาแยก `/services/a` กับ `/services/b` แต่เรารวมหน้าเดียว คือ gap เชิงโครงสร้าง ตลาดไทยแยกตารางตามภาษา

| คู่แข่ง | จุดแข็งที่เห็นจริง | จุดอ่อนที่เราแทรกได้ | หลักฐาน |
|---|---|---|---|

## ขั้นที่ 5 ส่งออก

ชื่อไฟล์ตาม pattern นี้ ตรงกับ `agent.json` ช่อง `output` เหมือนกันเป๊ะ

```
work/{domain}/(00-baseline|01-current)/{domain}_competitor-analysis_{YYYY-MM-DD}.md
```

เรียงหัวข้อ สรุปหนึ่งย่อหน้าว่าใครต้องจับตาและช่องว่างไหนใหญ่สุด ตารางคู่แข่ง ข้อสังเกต SERP รายคำค้น
สิ่งที่เห็นจากหน้าคู่แข่ง ตาราง gap ทั้งสาม สิ่งที่ควรทำ 5 ข้อเรียงตามผลกระทบ
ปิดท้ายด้วยข้อจำกัด คำไหนยังไม่มีผลจริง เว็บไหนดึงไม่ได้

## การ์ด Tier 1 ของสกิลนี้

จบงานทุกครั้งด้วยการ์ดสรุปตามชั้นแสดงผล (`so-present-lite`): โหมด `audit` `competitors` คือรายชื่อคู่แข่งที่ AI เอ่ยชื่อจริง (name, tagline, score = จำนวนครั้งที่ถูกอ้างในคำถามที่สุ่ม, max = จำนวนคำถาม, `is_client` บนแถวของลูกค้า), `key_risk` คือช่องว่างที่คู่แข่งได้เปรียบชัดที่สุด, `actions` คือ 4 ข้อแรกของแผนวางตำแหน่ง
ทุกค่าบนการ์ดคัดลอกจากไฟล์ผลลัพธ์ที่เพิ่งเขียน ห้ามประเมินเพิ่ม ข้อที่ตรวจไม่ได้ให้ขึ้นว่า ตรวจสอบไม่ได้
รุ่น Lite ไม่มีคะแนน จึงไม่ใส่บล็อก `score` ค่าใน `dimensions` คือจำนวนข้อที่ผ่านต่อจำนวนข้อที่ตรวจ
เรนเดอร์ด้วย `python {PLUGIN_ROOT}/skills/rainmojo-so-lite/scripts/present.py --summary <summary.json> --target auto --host {host}`
แล้วปิดด้วยบรรทัดส่งต่อไปยังไฟล์ผลลัพธ์ฉบับเต็ม ซึ่งต้องครบและไม่ถูกย่อ

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## กฎ


- **ถ้าดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย ถ้าเขียนผิดผู้ใช้จะสรุปกลับด้าน
- **ทำได้บางส่วนต้องส่งส่วนนั้นเสมอ** ห้ามส่งตารางที่ทุกช่องว่าง และห้ามปฏิเสธทั้งงานเพราะขาดข้อมูลบางอย่าง ให้ติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม · การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์
- **ห้ามให้คะแนนคู่แข่งหรือจัดเกรด SERP เป็นตัวเลข** ใช้ สูง กลาง ต่ำ หรือ ดี พอใช้ ต้องแก้
- **ห้ามเดา traffic, DR, backlink, search volume** มีข้อมูลจากเครื่องมือภายนอกให้อ้างพร้อมที่มา
- **ห้ามแต่งรายชื่อคู่แข่งหรือผลค้น** ยังไม่ยืนยันให้กำกับไว้ WebFetch เข้าไม่ได้ให้บอกตรง ๆ
- **ทุกช่องในตารางต้องอ้างหน้าที่ดึงมาจริงหรือผล SERP ที่ผู้ใช้ให้** ห้ามใส่ความรู้สึก
- **ห้ามเขียนข้อสรุปกลวง** ต้องชี้ว่าหน้าไหน คำไหน หลักฐานอะไร ข้อมูลไม่พอให้เขียนว่าไม่พอ
