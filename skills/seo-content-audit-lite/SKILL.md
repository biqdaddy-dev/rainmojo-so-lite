path by hand inside a client workspace. Never write generated files to the
plugin tree or the caller's working directory. Append one line to the
workspace's `CHANGELOG.md` or `log.md` after every write. Run
`client_workspace.py validate` before handing a client workspace over. Direct
CMS/API operations retain their own safety and verification gates.

# seo content audit

ตอบคำถามเดียวคือ **เนื้อหานี้คุณภาพพอและปลอดภัยพอที่จะเผยแพร่หรือไม่ เพราะอะไร**

ผลประเมินทุกอย่างเป็นระดับเชิงคุณภาพ ดี พอใช้ ต้องแก้ และ ผ่าน ไม่ผ่าน ไม่มีคะแนนตัวเลขทุกชนิด
เพราะคะแนนรวมทำให้ข้อวิกฤตหายไปในค่าเฉลี่ย ซึ่งเป็นสิ่งที่อันตรายที่สุดของการตรวจเนื้อหา

## ขั้นแรกสุด ดึง HTML ดิบมาก่อน

**ห้ามข้ามขั้นนี้** เพราะ WebFetch คืนเนื้อหาที่แปลงเป็นข้อความแล้ว
ของที่อยู่ใน `<head>` เช่น title, meta description, canonical และ JSON-LD **ถูกตัดทิ้งหมด**
ถ้าตรวจจากผล WebFetch อย่างเดียว จะรายงานว่า **ไม่มี** ทั้งที่มีอยู่จริง ซึ่งเป็นผลลบลวง

```bash
mkdir -p work/{domain}/uploads
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120"
curl -sSL -A "$UA" -m 25 "https://{domain}/" -o work/{domain}/uploads/home.html
```

### ถ้าใช้คำสั่งพวกนี้ไม่ได้

**บาง host ไม่มีเครื่องมือรันคำสั่งให้** เช่น Cowork, Claude Desktop และ GPT desktop
ถ้าเป็นแบบนั้น ให้ทำแบบนี้แทน แล้วงานจะยังเดินต่อได้

1. บอกผู้ใช้ว่า **ขอให้ช่วยเปิดหน้าเว็บแล้วคัดลอกซอร์สมาให้**
   วิธีคือเปิดหน้านั้นในเบราว์เซอร์ กด `Ctrl+U` หรือ `Cmd+Option+U` เพื่อดู source
   แล้วเลือกทั้งหมด คัดลอก มาวางในแชท
2. ถ้าผู้ใช้ทำให้ได้ ให้ทำงานต่อจากซอร์สที่ได้มา ตามขั้นตอนเดิมทุกอย่าง
3. ถ้าผู้ใช้ไม่สะดวก ให้ใช้ WebFetch เท่าที่ได้ แล้ว**เขียนกำกับทุกหัวข้อที่กระทบว่า `ตรวจไม่ได้`**
   ห้ามเขียนว่า `ไม่มี` เพราะสองคำนี้คนละความหมาย และการเขียนผิดจะทำให้ผู้ใช้เข้าใจกลับด้าน

**บน Windows** ถ้ารันแล้วขึ้นว่าไม่รู้จักคำสั่ง ให้ลองใน Git Bash หรือ WSL
ถ้าไม่มีทั้งสองอย่าง ให้ใช้วิธีคัดลอกซอร์สในข้อ 1

ทำแบบเดียวกันกับทุกหน้าที่ต้องตรวจ ตั้งชื่อไฟล์ตามหน้า แล้ว **ใช้ Grep กับไฟล์ที่ดาวน์โหลดมา**

ตัวอย่างคำสั่งที่ใช้บ่อย

```bash
grep -o '<title>[^<]*</title>' work/{domain}/uploads/home.html
grep -o '<meta name="description" content="[^"]*"' work/{domain}/uploads/home.html
grep -o '<link rel="canonical" href="[^"]*"' work/{domain}/uploads/home.html
grep -o '<meta name="robots" content="[^"]*"' work/{domain}/uploads/home.html
sed -n 's/.*<script type="application\/ld+json">\(.*\)<\/script>.*/\1/p' work/{domain}/uploads/home.html
```

**ถ้าดึงหน้าเดิมสองครั้งแล้วได้ค่าไม่ตรงกัน ให้ดึงครั้งที่สาม** แล้วใช้ค่าที่ซ้ำกันสองในสาม
ถ้ายังไม่ตรงอีก ให้บันทึกว่าค่าไม่นิ่ง และห้ามสรุปว่าหน้านั้นผิดกฎ

**ถ้า `curl` ใช้ไม่ได้ในเครื่องผู้ใช้** ให้บอกตรง ๆ แล้วทำเท่าที่ WebFetch ให้ได้
พร้อมเขียนกำกับทุกหัวข้อที่กระทบว่า **ตรวจไม่ได้** ไม่ใช่ **ไม่มี** สองคำนี้คนละความหมาย

## ข้อมูลที่ต้องมี

| ข้อมูล | จำเป็นไหม | หมายเหตุ |
|---|---|---|
| URL หรือข้อความเนื้อหาเต็ม | จำเป็น | ถ้าได้แค่บางส่วน ให้ประเมินเท่าที่มีและเขียนข้อจำกัดกำกับ |
| หัวข้อและจุดประสงค์ | จำเป็น | ให้ความรู้ ขาย สอน หรือรีวิว |
| กลุ่มผู้อ่านเป้าหมาย | ควรมี | มีผลต่อการตัดสินความเสี่ยง |
| ข้อมูลผู้เขียนและแบรนด์ | ควรมี | ถ้าไม่ให้มา ให้ตรวจจากหน้าเว็บจริง |

ถ้าได้ URL ให้ใช้ WebFetch ดึงเนื้อหา แยกเนื้อหาหลักออกจาก nav, footer, sidebar
และเก็บโครง heading ไว้ใช้ประกอบการประเมิน

## ถ้ารอบนี้ตรวจทั้งเว็บ ไม่ใช่แค่หน้าเดียว ทำสามอย่างนี้ก่อนเข้าขั้นที่ 1

ตรวจหน้าเดียวให้ข้ามหัวข้อนี้ไปที่ขั้นที่ 1 ได้เลย

รายชื่อ URL ที่จะตรวจ ให้เอามาจากอย่างใดอย่างหนึ่งคือ ผู้ใช้ส่งรายการมาเอง
ผลของสกิล `seo-website-overview-lite` ที่มีอยู่แล้วใน `work/{domain}/`
หรือดึง sitemap มานับเองด้วย `curl` ตามคำสั่งในหัวข้อก่อนหน้า
**ไม่มีรายการหน้าที่เชื่อถือได้ ห้ามเดาว่าเว็บมีกี่หน้าหรือมีอะไรบ้าง**
ให้เขียนว่ายังตรวจระดับเว็บไม่ได้เพราะขาดรายชื่อหน้า แล้วทำเฉพาะหน้าที่มีข้อมูลจริงต่อไป

### 1 แยกหน้าออกเป็นสองชั้นก่อนตรวจ

แยกทุก URL ที่จะตรวจเป็น **หน้าให้ความรู้** กับ **หน้าเชิงพาณิชย์** ให้เสร็จ **ก่อน** เริ่มตรวจ
แล้วใช้เกณฑ์คนละชุด ใช้ไม้บรรทัดเดียวกันทั้งสองชั้นจะผิดทั้งคู่
หน้าให้ความรู้จะโดนตัดสินว่าไม่ขายของ ส่วนหน้าเชิงพาณิชย์จะผ่านเพราะยาวพอ ทั้งที่ไม่ได้ต้องยาว

| ชั้น | ตัดสินด้วยอะไร |
|---|---|
| หน้าให้ความรู้ | ครอบคลุมกว้างและลึกแค่ไหน เทียบกับหัวข้อที่คู่แข่งเขียนไว้แล้ว ไม่ใช่เทียบกับสารบัญของเราเอง |
| หน้าเชิงพาณิชย์ | เพิ่มการตรวจเนื้อหาซ้ำ ซึ่งหน้าให้ความรู้ไม่ต้องตรวจ |

**หน้าสินค้าที่ใช้คำบรรยายจากผู้ผลิต ให้ถือว่าซ้ำไว้ก่อน จนกว่าจะพิสูจน์ได้ว่าไม่ซ้ำ**
เพราะร้านทุกเจ้าที่ขายของรุ่นเดียวกันก็คัดลอกข้อความชุดเดียวกันไปวาง
ทางแก้คือเขียนใหม่ หรือเติมของที่ร้านอื่นไม่มี เช่น รีวิวจากผู้ใช้จริง
ทำไม่ไหวทั้งหมดให้เลือกหน้าที่สำคัญที่สุดก่อน แล้วเขียนในรายงานว่าตัดที่ตรงไหน

เนื้อหาเสริมที่เอาไปแปะไว้ใต้สุดของหน้า นอกเส้นทางการอ่าน ให้รายงานว่าเป็น **ปัญหาตำแหน่ง**
ไม่ใช่ **เนื้อหาขาด** เพราะเขียนมาแล้วแต่วางผิดที่

ตารางหัวข้อที่คู่แข่งเขียนไว้เป็นงานของสกิล `seo-content-gap-analysis-lite` สกิลนี้เอาผลของเขามาใช้
ถ้าโตกว่าคู่แข่งทั้งเว็บไม่ไหว ให้เลือกเอาชนะเป็นหัวข้อ ๆ ระบุหัวข้อที่เลือกไว้ในรายงาน
แล้วตรวจเทียบกับเป้าที่แคบลงนั้น

### 2 เนื้อหาบางหรือ thin content ตัดสินด้วยหมวด ไม่ใช่จำนวนคำ

**จำนวนคำไม่ใช่เกณฑ์ตัดสินในทุกขั้นตอน** ใช้ได้อย่างเดียวคือใช้คัดว่าจะไปเปิดอ่านหน้าไหนก่อน

| หมวด | ลักษณะ |
|---|---|
| ผลิตทีละมาก ๆ ด้วยเครื่อง | ปั๊มออกมาเป็นชุด ไม่มีคนดูแลรายหน้า |
| หน้า affiliate ที่เล่าซ้ำ | เอาข้อมูลที่หาอ่านที่ไหนก็ได้มาเรียบเรียงใหม่ ไม่มีอะไรเพิ่ม |
| doorway | ทำขึ้นเพื่อดักคำค้นอย่างเดียว ไม่ได้ทำเพื่อคนอ่าน |
| คัดลอกมาจากที่อื่น | ยกเนื้อหาเว็บอื่นมาทั้งดุ้น |
| ชุดหน้าที่เกือบเหมือนกัน | สลับเอกพจน์พหูพจน์ สลับคำพ้อง หรือเปลี่ยนถ้อยคำนิดเดียวของบริการเดียวกัน |

ชุดหน้าที่เกือบเหมือนกัน **ให้รายงานเป็นหนึ่งชุดพร้อมจำนวนสมาชิก** ห้ามไล่รายงานทีละหน้า
และการสลับชื่อจังหวัด ชื่อสินค้า หรือคำกริยาลงในแม่แบบเดิม ไม่ทำให้หน้านั้นกลายเป็นหน้าที่ไม่ซ้ำ

**กฎกันพลาด** หน้าที่ข้อความน้อยมากก็มีคุณค่าได้ เช่น หน้ารวมรายการที่แต่ละรายการมีคำอธิบายสั้น ๆ
**ห้ามติดธงจากจำนวนคำอย่างเดียว และต้องเปิดอ่านหน้านั้นจริงก่อนจัดหมวดเสมอ**
การจัดหมวดจากตัวเลขที่ได้จากการไล่เก็บข้อมูลโดยไม่ได้เปิดอ่านหน้าจริง ไม่นับเป็นข้อค้นพบ
และห้ามใส่ลงรายงาน

### 3 เนื้อหาไร้ประโยชน์กดทั้งเว็บ ไม่ได้กดเฉพาะหน้านั้น

เนื้อหาที่ทำขึ้นเพื่อไต่อันดับเป็นหลัก ทำให้เว็บถูกลดค่า **ทั้งโดเมน**
แปลว่าหน้าที่ดีอยู่แล้วและไม่เกี่ยวข้องกันเลย ก็ตกไปด้วยเพราะเนื้อหาแย่ที่อยู่คนละส่วนของเว็บ
เรื่องนี้เป็นความเสี่ยงระดับเว็บ ไม่ใช่คะแนนรายหน้า

การตรวจจึงต้อง **นับและชี้ตำแหน่ง** ว่ามีกี่หน้า อยู่ส่วนไหนหรือแม่แบบไหน
แล้วย้อนไปดูวิธีผลิตว่ามีสัญญาณอันตรายไหม คือบรีฟที่สั่งแค่จำนวนคำกับคำค้น
ไม่มีคนที่รู้เรื่องนั้นจริงเป็นผู้เขียน และหัวข้อกระจายไปเรื่อย ๆ ตามกระแส

**ทางแก้คือเอาออก** การใส่ noindex เป็นแค่การประคอง เพราะสัญญาณต้นเหตุยังอยู่ที่เดิม

**กฎที่กลับด้านการวินิจฉัย** ส่วนที่แย่อยู่ส่วนเดียวกดทั้งเว็บได้ แม้จะเป็นสัดส่วนเล็กของหน้าทั้งหมด
ดังนั้นเวลาอันดับตกทั้งเว็บ **ให้ไปตรวจส่วนที่แย่ที่สุด ไม่ใช่ตรวจหน้าที่เห็นว่าตก**
เพราะหน้าที่ตกมักไม่ใช่หน้าที่เป็นต้นเหตุ แล้วรายงานแยกกันให้ชัดว่าส่วนไหนเป็นต้นเหตุ ส่วนไหนเป็นผู้รับผล

แก้แล้วต้องรอหลายเดือนกว่าการกดจะคลาย **บอกเรื่องนี้ให้ผู้ใช้รู้ก่อนเริ่มลงมือ**
อันดับที่ยังไม่ขยับหลังแก้เสร็จใหม่ ๆ ไม่ใช่หลักฐานว่าวินิจฉัยผิด
และไม่ใช่เหตุผลให้เอาเนื้อหาที่ลบถูกแล้วกลับขึ้นมาใหม่ในช่วงที่ยังต้องรอ

## ขั้นที่ 1 จำแนกประเภทเนื้อหาและความซับซ้อนของหัวข้อ

ประเภทเนื้อหากำหนดว่าควรคาดหวัง E-E-A-T แค่ไหน อย่าใช้ไม้บรรทัดเดียวกับทุกหน้า

| ประเภท | ความคาดหวังหลัก |
|---|---|
| บทความให้ความรู้ | ข้อเท็จจริงแม่น อ้างแหล่งได้ |
| หน้าสินค้าและรีวิว | มีร่องรอยการใช้จริง ไม่ใช่เรียบเรียงจากสเปก |
| บล็อกส่วนตัว | ประสบการณ์ตรงสำคัญกว่าคุณวุฒิ |
| เนื้อหาวิชาชีพและธุรกิจ | ผู้เขียนระบุตัวตนและคุณวุฒิได้ |
| ข่าวและเหตุการณ์ | ระบุวันที่และแหล่งข่าวชัด |

จากนั้นระบุความซับซ้อนของหัวข้อ ความรู้ทั่วไป ต้องมีพื้นฐาน เฉพาะทางสูง หรือคำแนะนำวิชาชีพ
ยิ่งซับซ้อน ยิ่งต้องเข้มกับหลักฐานความเชี่ยวชาญ

## ขั้นที่ 2 ตรวจว่าเป็น YMYL หรือไม่

YMYL คือเนื้อหาที่ถ้าผิดแล้วกระทบสุขภาพ เงิน หรือความปลอดภัยของคนอ่าน

| หมวด YMYL | ตัวอย่าง |
|---|---|
| สุขภาพและความปลอดภัย | อาการโรค การใช้ยา อาหารเสริม ความปลอดภัยในกิจกรรมเสี่ยง |
| การเงิน | การลงทุน ภาษี สินเชื่อ ประกัน คริปโต การจัดการหนี้ |
| สังคม กฎหมาย ราชการ | สิทธิทางกฎหมาย การเลือกตั้ง เอกสารและขั้นตอนราชการ |
| อื่นที่กระทบความเป็นอยู่ | การศึกษา การหางาน ที่อยู่อาศัย |

**ถ้าไม่แน่ใจ ให้ถือว่าเป็น YMYL ไว้ก่อน** แล้วใช้เกณฑ์แบบเข้ม

ผลของการเป็น YMYL คือทุกมิติในขั้นที่ 3 ต้องได้ระดับ ดี และ checklist ในขั้นที่ 4
ต้องผ่านครบทุกข้อ จึงจะเขียนได้ว่าพร้อมเผยแพร่

## ขั้นที่ 3 ประเมิน E-E-A-T ทีละมิติ

ประเมินแยก 4 มิติ **ห้ามรวมเป็นเกรดเดียว** แต่ละมิติให้ระดับ ดี พอใช้ ต้องแก้
พร้อมยกหลักฐานจากเนื้อหาจริงประกอบทุกมิติ

| มิติ | สิ่งที่มองหา | ระดับ ดี | ระดับ ต้องแก้ |
|---|---|---|---|
| Experience ประสบการณ์ตรง | เรื่องเล่าจากการทำจริง ตัวอย่างเฉพาะเจาะจง ผลการทดลองใช้เอง | หลักฐานการลงมือจริงหลายจุดและเจาะจง | ไม่มีร่องรอยการใช้จริง เป็นคำแนะนำกลาง ๆ ที่ใครก็เขียนได้ |
| Expertise ความเชี่ยวชาญ | ความถูกต้องเชิงเทคนิค ศัพท์เฉพาะที่ใช้ถูก คุณวุฒิผู้เขียน การอ้างแหล่งที่เชื่อถือได้ | เนื้อหาลึกและแม่น มีผู้เขียนพร้อมคุณวุฒิ | พบข้อมูลผิดหรือตื้น ไม่มีผู้เขียน ไม่อ้างแหล่ง |
| Authoritativeness การยอมรับ | ถูกอ้างโดยแหล่งอื่น การยอมรับในวงการ สังกัดหน่วยงาน เว็บคลุมหัวข้อนี้ต่อเนื่องหลายหน้า | มีการอ้างถึงจากภายนอก และหน้านี้อยู่ในชุดเนื้อหาเดียวกัน | ไม่มีใครอ้างถึง หน้านี้โดดเดี่ยวจากเนื้อหาอื่นของเว็บ |
| Trust ความน่าเชื่อถือ | ข้อเท็จจริงถูกต้อง โปร่งใสว่าใครเขียน มีช่องทางติดต่อ มี disclaimer ที่จำเป็น | สุ่มตรวจแล้วไม่พบผิด มีตัวตนและติดต่อได้ | พบข้อมูลผิด ไม่รู้ว่าใครเขียน ไม่มีช่องทางติดต่อ |

ระดับ พอใช้ คือมีสัญญาณบ้างแต่ไม่ครบ มิติไหนได้ พอใช้ หรือ ต้องแก้
ต้องระบุให้ชัดว่าขาดสัญญาณตัวไหน และเติมอย่างไรจึงจะขึ้นเป็น ดี

### ห่วงโซ่ตัวตนผู้เขียน ต้องต่อกันได้ทั้งเว็บ

มิติ Authoritativeness กับ Trust ขาดทันทีถ้าโยงไม่ได้ว่าคนเขียนคือใคร
ให้ตรวจสามสัญญาณนี้ต่อบทความ ตอบ ผ่าน หรือ ไม่ผ่าน ทีละข้อ

1. ระบุชื่อผู้เขียนไว้ชัดเจนหรือไม่
2. ประวัติผู้เขียนกดเข้าไปอ่านได้จริงหรือไม่
3. มีที่อื่นที่เผยแพร่งานของคนนี้หรืออ้างถึงคนนี้ไหม และกี่ที่

จากนั้นตรวจห่วงโซ่ที่ทำให้สัญญาณทั้งสามเกาะไปที่คนคนเดียวกัน ไม่ใช่กระจายเป็นคนละคน

| ข้อต่อ | ผ่านเมื่อ |
|---|---|
| ชื่อที่ลงท้ายบทความ | สะกดตรงกันทุกตัวอักษร ทั้งทุกบทความในเว็บ และทุกโปรไฟล์นอกเว็บ |
| โปรไฟล์ต่าง ๆ | ลิงก์ถึงกันไปกลับ ไม่ใช่ต่างคนต่างอยู่ |
| หน้าประวัติผู้เขียน | คนที่เขียนประจำต้องมีหน้าของตัวเอง มีคุณวุฒิ และมีลิงก์ออกไปหางานของเขาที่อื่นและหน้าที่ยืนยันคุณวุฒิ |

ห่วงโซ่ขาดตรงไหน **ให้รายงานหนึ่งครั้งในฐานะต้นเหตุ พร้อมยกข้อความที่ไม่ตรงกันมาวางเทียบให้เห็น**
ห้ามแตกเป็นข้อค้นพบหลายสิบข้อรายหน้า เพราะต้นเหตุมีอันเดียว
ส่วนการถูกพูดถึงในระดับแบรนด์ตามแพลตฟอร์มต่าง ๆ เป็นงานของสกิล `aiso-brand-mentions-lite`

## ขั้นที่ 4 checklist ป้องกันความเสียหาย

ไล่ทีละข้อ ทุกข้อตอบ ผ่าน หรือ ไม่ผ่าน พร้อมเหตุผล ห้ามตอบว่าผ่านโดยไม่ได้ตรวจจริง

| ข้อตรวจ | ผ่านเมื่อ | ไม่ผ่านเมื่อ |
|---|---|---|
| ข้อเท็จจริงตรงกับแหล่งที่เชื่อถือได้ | สุ่มตรวจข้ออ้างหลักแล้วตรงกับแหล่งอ้างอิง | พบข้ออ้างที่ขัดกับแหล่งที่เชื่อถือได้ หรือยืนยันไม่ได้เลย |
| ข้อมูลเป็นปัจจุบัน | มีวันที่ และเนื้อหายังถูกต้องในวันนี้ | ล้าสมัยในเรื่องที่เปลี่ยนไปแล้ว เช่น กฎหมาย ราคา เกณฑ์ |
| ไม่มีคำแนะนำที่พาไปเสี่ยงอันตราย | คำแนะนำอยู่ในกรอบที่ผู้เชี่ยวชาญทั่วไปยอมรับ | อาจทำให้เลื่อนการรักษา เสียเงินก้อนใหญ่ เสี่ยงร่างกาย หรือผิดกฎหมาย |
| ไม่เอาเปรียบกลุ่มเปราะบาง | ไม่มีเนื้อหาชี้นำเด็ก ผู้สูงอายุ ผู้ป่วย หรือผู้เดือดร้อนการเงิน | มีการเร่งรัด ขู่ หรือให้ความหวังเกินจริงกับกลุ่มเหล่านี้ |
| สอดคล้องฉันทามติผู้เชี่ยวชาญ | ข้ออ้างหลักไปทางเดียวกับแหล่งวิชาชีพในตารางด้านล่าง | ขัดกับฉันทามติโดยไม่มีหลักฐานหนักแน่นรองรับ |
| มี disclaimer ที่จำเป็น | เนื้อหาเสี่ยงมีคำเตือนและข้อจำกัดกำกับชัด | ให้คำแนะนำเสี่ยงโดยไม่มีคำเตือนใด ๆ |
| แนะนำให้พบผู้เชี่ยวชาญเมื่อควร | เรื่องที่ต้องวินิจฉัยรายบุคคลมีข้อความชวนปรึกษาผู้เชี่ยวชาญ | ทำให้คนอ่านเข้าใจว่าตัดสินใจเองได้โดยไม่ต้องปรึกษาใคร |

แหล่งที่ใช้ตรวจฉันทามติ

| หมวด | แหล่งตรวจสอบ |
|---|---|
| การแพทย์ | วารสารการแพทย์ องค์กรวิชาชีพแพทย์ หน่วยงานสาธารณสุขของรัฐ |
| การเงิน | หน่วยงานกำกับของรัฐ องค์กรวิชาชีพนักวางแผนการเงิน งานวิจัยวิชาการ |
| ความปลอดภัย | หน่วยงานความปลอดภัยของรัฐ มาตรฐานอุตสาหกรรม แนวปฏิบัติกู้ภัย |
| กฎหมาย | ตัวบทกฎหมาย เว็บหน่วยงานราชการ สภาวิชาชีพ |

เนื้อหาต่อไปนี้ต้องเขียนในรายงานว่า **ต้องให้ผู้เชี่ยวชาญตัวจริงตรวจก่อนเผยแพร่**
คำแนะนำการรักษาเฉพาะโรค กลยุทธ์การลงทุนแบบเจาะจง ขั้นตอนทางกฎหมาย
และขั้นตอนกิจกรรมที่อันตรายต่อร่างกาย

## ขั้นที่ 5 ตรวจความเป็นธรรมชาติของเนื้อหา

มองหารูปแบบที่มักเจอในเนื้อหาสำเร็จรูป แล้วรายงานความเสี่ยงเป็น สูง กลาง ต่ำ
พร้อมยกประโยคจริงจากหน้าประกอบทุกครั้ง

| สิ่งที่ตรวจ | ตัวอย่างสัญญาณ |
|---|---|
| วลีสำเร็จรูปภาษาไทย | คู่มือฉบับผู้เชี่ยวชาญ, ฉบับสมบูรณ์, แบบครบถ้วน, ทุกสิ่งที่คุณควรรู้, การวิเคราะห์ระดับลึก |
| โครงเรียบเกินจริง | ทุกหัวข้อยาวเท่ากัน สรุปซ้ำความเดิม ประโยคเปลี่ยนผ่านแบบกลไก |
| ไร้เสียงคนเขียน | ไม่มีมุมมองส่วนตัว ไม่มีตัวอย่างเจาะจง ไม่มีบริบทท้องถิ่น |
| สัญญาณธรรมชาติ ฝั่งดี | เล่าประสบการณ์ตรง ยอมรับข้อจำกัดและทางเลือกที่ต้องแลก มีข้อมูลหรือมุมมองที่หาที่อื่นไม่ได้ |

**ห้ามฟันธงว่า AI เขียน** ให้รายงานว่าพบรูปแบบที่มักเจอในเนื้อหาที่ผลิตด้วย AI
เพราะคนก็เขียนแบบนี้ได้ ประเด็นจริงคือเนื้อหาแบบนี้ขาดคุณค่าเฉพาะตัว ไม่ใช่ว่าใครเขียน

### ข้อพลาดที่พบบ่อยกว่า คือการตกประเด็น ไม่ใช่ข้อมูลผิด

ร่างที่ให้เครื่องช่วยเขียน พลาดแบบผิดชัด ๆ น้อยกว่าพลาดแบบเงียบ ๆ
คือมีข้อมูลที่คนทำงานสายนั้นถือว่าต้องมี แล้วร่างนั้นไม่พูดถึงเลย
**ให้ตรวจความครบของประเด็นเทียบกับบรีฟก่อน แล้วค่อยไล่ตรวจข้ออ้างทีละข้อ** ไม่ใช่กลับกัน
ไม่มีบรีฟให้ถามผู้ใช้ว่าหน้านี้ต้องตอบอะไรบ้าง ถ้ายังไม่ได้ ให้เขียนกำกับว่ายังตรวจความครบไม่ได้

อีกสองอย่างที่ขาดโดยปริยายทุกครั้ง และต้องให้คนเติมก่อนเผยแพร่เสมอ
คือประสบการณ์ตรงของเจ้าของเรื่อง และเหตุผลเฉพาะที่ลูกค้าควรเลือกเจ้านี้ ไม่ใช่เจ้าอื่น

เจอย่อหน้าที่แทบจะตรงคำต่อคำกับแหล่งภายนอก **ให้เขียนใหม่ ไม่ใช่แค่ใส่ที่มา**
เพราะเป็นทั้งปัญหาเนื้อหาซ้ำและปัญหาสิทธิ์ ซึ่งการอ้างอิงอย่างเดียวไม่ได้แก้ทั้งสองอย่าง

## ขั้นที่ 6 สรุปผลและเขียนรายงาน

จัดทุกประเด็นที่พบเป็น 4 ระดับความเร่งด่วน

| ระดับ | หมายถึง |
|---|---|
| วิกฤต | เสี่ยงทำร้ายคนอ่านหรือผิดข้อเท็จจริงเรื่องใหญ่ ห้ามเผยแพร่จนกว่าจะแก้ |
| สูง | กระทบความน่าเชื่อถือชัดเจน ควรแก้ก่อนเผยแพร่ |
| กลาง | ควรแก้ในรอบปรับปรุงถัดไป |
| ต่ำ | แก้เมื่อมีเวลา |

ไฟล์ผลลัพธ์ตั้งชื่อตาม pattern นี้

```
work/{domain}/(00-baseline|01-current)/{domain}_content-audit_{YYYY-MM-DD}.md
```

โครงรายงานเรียงตามนี้

1. **สรุปหนึ่งย่อหน้า** พร้อมคำตัดสิน พร้อมเผยแพร่ แก้ก่อนเผยแพร่ หรือ ห้ามเผยแพร่จนกว่าจะแก้
2. **ตารางจำแนก** ประเภทเนื้อหา ความซับซ้อน สถานะ YMYL และหมวด
3. **ตาราง E-E-A-T** มิติ / ระดับ / หลักฐานที่พบ / สิ่งที่ขาด / วิธีเติม
4. **ตาราง checklist ป้องกันความเสียหาย** ข้อตรวจ / ผ่านหรือไม่ผ่าน / เหตุผล / ตำแหน่งในเนื้อหา / วิธีแก้
5. **ความเป็นธรรมชาติของเนื้อหา** ระดับความเสี่ยง พร้อมประโยคตัวอย่างจากหน้าจริง
6. **แผนแก้** เรียงจาก วิกฤต ไป ต่ำ ระบุว่าใครแก้ได้เอง และข้อไหนต้องส่งผู้เชี่ยวชาญ
7. **ข้อจำกัดของการประเมินครั้งนี้** เขียนตรง ๆ ว่าอะไรตรวจไม่ได้จากข้อมูลเท่าที่มี
8. **เฉพาะรอบที่ตรวจทั้งเว็บ** เพิ่มสามตารางนี้ต่อท้าย จำนวนหน้าแยกตามชั้นให้ความรู้กับเชิงพาณิชย์,
   หน้าที่เข้าข่ายเนื้อหาบางแยกตามหมวด โดยชุดหน้าที่เกือบเหมือนกันนับเป็นหนึ่งแถว,
   และผลตรวจห่วงโซ่ตัวตนผู้เขียน ถ้าเว็บมีอาการตกทั้งเว็บ ให้ระบุส่วนที่เป็นต้นเหตุกับส่วนที่รับผลแยกกัน

## การ์ด Tier 1 ของสกิลนี้

จบงานทุกครั้งด้วยการ์ดสรุปตามชั้นแสดงผล (`so-present-lite`): โหมด `audit` `dimensions` คือ E-E-A-T และ YMYL แต่ละมิติ value = จำนวนหน้าที่ได้ระดับ ดี, max = จำนวนหน้าที่ตรวจ, `key_risk` คือข้อค้นพบด้านความน่าเชื่อถือหรืออันตรายที่กระทบหน้ามากที่สุด, `roles` คือมุมมองผู้บริหาร นักพัฒนา และคนเขียน ของข้อค้นพบเดียวกัน, `actions` ไม่เกิน 4 ข้อ
ทุกค่าบนการ์ดคัดลอกจากไฟล์ผลลัพธ์ที่เพิ่งเขียน ห้ามประเมินเพิ่ม ข้อที่ตรวจไม่ได้ให้ขึ้นว่า ตรวจสอบไม่ได้
รุ่น Lite ไม่มีคะแนน จึงไม่ใส่บล็อก `score` ค่าใน `dimensions` คือจำนวนข้อที่ผ่านต่อจำนวนข้อที่ตรวจ
เรนเดอร์ด้วย `python {PLUGIN_ROOT}/skills/rainmojo-so-lite/scripts/present.py --summary <summary.json> --target auto --host {host}`
แล้วปิดด้วยบรรทัดส่งต่อไปยังไฟล์ผลลัพธ์ฉบับเต็ม ซึ่งต้องครบและไม่ถูกย่อ

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## กฎ


- **ถ้าดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย ถ้าเขียนผิดผู้ใช้จะสรุปกลับด้าน
- **ทำได้บางส่วนต้องส่งส่วนนั้นเสมอ** ห้ามส่งตารางที่ทุกช่องว่าง และห้ามปฏิเสธทั้งงานเพราะขาดข้อมูลบางอย่าง ให้ติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม · การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์
- **ห้ามให้คะแนนเป็นตัวเลขทุกชนิด** ไม่มีคะแนนเต็ม ไม่มีเปอร์เซ็นต์ ไม่มีเกณฑ์ผ่านเป็นตัวเลข
  รายงานเป็นระดับ ดี พอใช้ ต้องแก้ และ ผ่าน ไม่ผ่าน เท่านั้น
- **ห้ามใช้จำนวนคำเป็นเกณฑ์ตัดสินว่าหน้าไหนบาง** ให้ตัดสินด้วยหมวดตามหัวข้อก่อนขั้นที่ 1
  และต้องเปิดอ่านหน้านั้นจริงก่อนจัดหมวดเสมอ
- **ห้ามเดาข้อเท็จจริงและห้ามแต่งแหล่งอ้างอิง** ถ้ายืนยันไม่ได้ให้เขียนว่ายืนยันไม่ได้
- **ห้ามสรุปว่าเนื้อหาปลอดภัย** ถ้ายังไล่ checklist ขั้นที่ 4 ไม่ครบทุกข้อ
- ทุกข้อที่ไม่ผ่าน ต้องมีเหตุผล ตำแหน่งในเนื้อหา และวิธีแก้ ห้ามรายงานลอย ๆ
- ถ้าไม่แน่ใจว่าเป็น YMYL ให้ถือว่าเป็น YMYL
- สกิลนี้ไม่ใช่ผู้เชี่ยวชาญการแพทย์ กฎหมาย หรือการเงิน หน้าที่คือชี้ว่าเนื้อหาไหน
  ต้องส่งให้ผู้เชี่ยวชาญตัวจริงตรวจ ไม่ใช่ตัดสินแทน
- ถ้าเนื้อหาสั้นหรือข้อมูลไม่พอ ให้ประเมินเท่าที่มีและระบุข้อจำกัดตรง ๆ ในรายงาน
