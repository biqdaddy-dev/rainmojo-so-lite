# ทำวิดีโอให้ถูกเก็บเข้าดัชนี

**งานวิดีโอพังแบบเงียบ ๆ** หน้าเว็บเล่นวิดีโอให้คนดูได้สมบูรณ์แบบ แต่ระบบเก็บดัชนีมองไม่เห็นเลยก็ได้
สกิลนี้จึงเริ่มจากการตรวจว่ามีอะไรทำให้ถูกตัดสิทธิ์อยู่หรือเปล่า ก่อนจะไปแตะเรื่องอื่น

## ขั้นที่ 0 ด่านคุ้มค่าก่อนเริ่ม

**ก่อนลงแรงทั้งหมด ให้ยืนยันก่อนว่าคำค้นเป้าหมายมีวิดีโอโผล่ในผลค้นจริง**
วิธีตรวจคือค้นคำนั้นเองในหน้าผลค้นจริง แล้วดูว่ามีบล็อกวิดีโอหรือคลิปโผล่ขึ้นมาไหม
ให้ดูหลายคำในกลุ่มเดียวกัน ไม่ใช่คำเดียว คำค้นเป้าหมายเอามาจาก `seo-keyword-research-lite` ได้

- **มีวิดีโอในผลค้น** เดินต่อ
- **ไม่มีเลย** ให้บอกผู้ใช้ตรง ๆ ว่า **การทำวิดีโอเพื่ออันดับของคำกลุ่มนี้ยังไม่คุ้ม**
  วิดีโออาจยังคุ้มด้วยเหตุผลอื่น เช่นใช้ปิดการขายบนหน้าเว็บ แต่นั่นไม่ใช่งานของสกิลนี้
- **ตรวจไม่ได้** ให้เขียนว่า `ตรวจไม่ได้` ไม่ใช่เขียนว่าไม่มี

## ขั้นที่ 1 ตรวจข้อที่ทำให้ถูกตัดสิทธิ์

**ทำก่อนงานปรับแต่งทุกอย่าง** ติดข้อใดข้อหนึ่งแปลว่าวิดีโอเข้าดัชนีไม่ได้
ต่อให้ข้อมูลประกอบดีแค่ไหนก็ตาม ต้องแก้หรือเปลี่ยนวิธีส่งวิดีโอก่อน

| # | ข้อที่ทำให้ถูกตัดสิทธิ์ | ตรวจยังไง |
|---|---|---|
| 1 | ต้องล็อกอิน ต้องจ่ายเงิน หรือกั้นตามประเทศ ทั้งหน้าหรือตัววิดีโอ | ดึงทั้งสองอย่างแบบไม่ล็อกอิน และจากนอกประเทศเป้าหมาย |
| 2 | มีป๊อปอัปคลุมตัวเล่นตอนเปิดหน้า | เปิดหน้าแบบไม่มีแคช แล้วดูว่ามีอะไรต้องกดก่อนเล่นไหม |
| 3 | ตัวเล่นโหลดทีหลังหรือถูก JavaScript ใส่เข้ามาหลังผู้ใช้กด | ดู HTML ดิบที่เซิร์ฟเวอร์ส่งมา ต้องมีวิดีโออยู่โดยไม่ต้องให้คนกดอะไร |
| 4 | URL ของไฟล์วิดีโอบน CDN หมุนเปลี่ยนหรือหมดอายุ | ดึง URL วิดีโอสองครั้งห่างกันหลายชั่วโมง ต้องเป็นตัวเดิมและยังตอบ |
| 5 | มีตัวห่อสำหรับติดตามคร่อม URL ไฟล์อยู่ | URL เนื้อหาที่ประกาศไว้ต้องวิ่งไปถึงไฟล์สื่อจริง ไม่ใช่ตัวส่งต่อ |
| 6 | ไฟล์อยู่ในรูปแบบที่ระบบอ่านไม่ได้ | ยืนยันว่าเป็นคอนเทนเนอร์มาตรฐานที่ระบบเก็บดัชนีรองรับ |
| 7 | robots บล็อกไฟล์วิดีโอหรือโฟลเดอร์ภาพปก | ดูกฎใน robots ทั้ง path ของไฟล์สื่อและ path ของภาพปก |

**บางข้อตรวจให้จบในรอบเดียวไม่ได้** ข้อ 1 ส่วนที่ต้องดูจากนอกประเทศ และข้อ 4 ที่ต้องดึงซ้ำห่างกันหลายชั่วโมง
อยู่นอกสิ่งที่ทำได้ในการทำงานรอบเดียว **ให้ลงว่า `ตรวจไม่ได้` แล้วเขียนวิธีตรวจให้ผู้ใช้ไปทำเอง
ห้ามลงว่าผ่าน และห้ามเดาผล**

**ทั้งสองที่ต้องตอบได้** เว็บที่วางหน้ากับที่วางไฟล์วิดีโอถูกดึงแยกกัน ต้องยืนยันว่าตอบได้ทั้งคู่
หน้าเว็บสมบูรณ์แบบแต่ชี้ไปที่วิดีโอที่ดึงไม่ได้ ถือว่าไม่ผ่าน และสลับกันก็ไม่ผ่านเหมือนกัน

**ถ้าคุมตัวเล่นเองได้ ให้ใช้แท็ก `<video>` ของ HTML** เป็นตัวที่ระบบอ่านได้แน่นอนที่สุด
และแอตทริบิวต์ `poster` ของมันนับเป็นการประกาศภาพปกบนหน้าไปในตัว ได้เงื่อนไขในขั้นที่ 3 มาฟรีหนึ่งข้อ

บันทึกผลด่านนี้เป็นผ่านหรือไม่ผ่านรายข้อลงในไฟล์ส่งมอบ **ข้อไหนไม่ผ่าน วิธีแก้เป็นส่วนหนึ่งของงานนี้
และห้ามเดินไปทำเรื่องข้อมูลประกอบต่อบนหน้าที่ยังไม่ผ่าน**

## ขั้นที่ 2 หนึ่งวิดีโอต่อหนึ่งหน้า

เงื่อนไขของหน้าที่จะมีสิทธิ์ได้ผลค้นแบบมีภาพประกอบ

1. **หนึ่งวิดีโอต่อหนึ่งหน้า** หน้าที่มีวิดีโอหลายตัวแย่งกันเอง และเสียสิทธิ์นั้นไป
   ให้แยกหน้าให้วิดีโอละหน้า
2. **title tag ของหน้าตรงกับชื่อวิดีโอ** หน้ากับวิดีโอต้องอ้างเรื่องเดียวกันด้วยคำเดียวกัน
3. **H1 อยู่เหนือตัวเล่น** หัวข้อเป็นตัวเกริ่นนำวิดีโอ ไม่ใช่กลับกัน
4. **คำอธิบายหรือ transcript อยู่ใต้ตัวเล่น** เป็นข้อความที่คนเขียนเอง ไม่ซ้ำที่อื่น
   ข้อความที่เครื่องสร้างล้วนหรือก๊อปมาไม่นับ
5. **เอาไปฝังที่อื่นได้ ไม่เป็นไร** หน้าต้นทางกับหน้าบนแพลตฟอร์มติดอันดับแยกกัน
   การเอาไปเผยแพร่ซ้ำไม่ได้แย่งอันดับหน้าต้นทาง

## ขั้นที่ 3 สัญญาเรื่องภาพปก

**ภาพปกเป็นของบังคับ** วิดีโอที่ไม่ได้ประกาศภาพปกไม่มีสิทธิ์ขึ้นบนพื้นที่วิดีโอเลย เงื่อนไขคือ

- ประกาศภาพปกใน **video sitemap** และ**อย่างน้อยหนึ่งวิธีบนหน้าเว็บ**
  วิธีบนหน้าเว็บมีสามทาง คือ structured data, meta ที่ประกาศภาพปกโดยตรง
  หรือแอตทริบิวต์ `poster` ของแท็ก `<video>`
- **structured data เป็นวิธีที่ควรใช้ที่สุด** เพราะช่องภาพปกของมันรับ URL เป็นชุดได้
  ประกาศครั้งเดียวแล้วเสนอได้ทั้งหลายขนาดและหลายอัตราส่วน
- **ขนาดต่ำสุดที่รับคือ 60x30 พิกเซล** ต่ำกว่านี้ถูกปฏิเสธ
- **ห้ามขยายภาพเล็กให้ใหญ่** ต้องเป็นพิกเซลจริง ภาพเล็กที่ถูกยืดจะไม่ผ่าน

สกิลนี้บอกว่าต้องมีช่องอะไรและขนาดเท่าไร ส่วนงานผลิตและจัดไฟล์ภาพให้ใช้ `seo-image-optimizer-lite`
markup ที่บรรจุข้อมูลพวกนี้ให้ `aiso-schema-lite` หรือ `seo-schema-lite` เป็นคนสร้าง
และโครง sitemap ที่ประกาศมันให้ `sitemap-architecture-lite` เป็นคนวาง

## ขั้นที่ 4 จะฝากแพลตฟอร์มหรือโฮสต์เอง

**ค่าตั้งต้นคือฝากแพลตฟอร์ม** เพราะได้หน้า watch ที่ถูกเก็บดัชนีอยู่แล้วมาด้วย
มีเครื่องมือทำภาพปกและทำซับให้ในตัว และไม่มีค่าส่งข้อมูลจากเว็บตัวเอง
**ให้เลือกทางนี้ เว้นแต่มีเหตุผลทางธุรกิจที่พูดออกมาได้ว่าทำไมถึงไม่เลือก**

**โฮสต์เองเป็นข้อยกเว้น และมีด่านกั้น** วิดีโอที่โฮสต์เองต้องผ่านทุกข้อในขั้นที่ 1 ก่อน
การตัดสินใจนั้นจึงจะยืนได้ ถ้าระบบของลูกค้ารับประกันไม่ได้ว่าจะมี URL วิดีโอสาธารณะที่นิ่ง
โฟลเดอร์ภาพปกที่ไม่ถูกบล็อก และตัวเล่นที่มากับ HTML ตั้งแต่ฝั่งเซิร์ฟเวอร์
**ให้กลับไปใช้ฝากแพลตฟอร์ม** เหตุผลที่ฟังขึ้นสำหรับการโฮสต์เอง มีสองข้อ
คือต้องการเก็บเวลาดูและการปิดการขายไว้บนหน้าเว็บตัวเอง
กับเนื้อหาที่นโยบายของแพลตฟอร์มไม่รับ

## ขั้นที่ 5 ขีดจำกัดช่องข้อมูลบนแพลตฟอร์ม

ตัวเลขในตารางนี้เป็นขีดจำกัดที่แพลตฟอร์มประกาศไว้เอง ไม่ใช่ค่าที่เราตั้งขึ้น

| ช่อง | ขีดจำกัด | กฎ |
|---|---|---|
| ชื่อวิดีโอ | 100 ตัวอักษร | เอาคำค้นไว้ต้น ขีดจำกัดนี้ตัดจริง |
| คำอธิบาย | 5,000 ตัวอักษร | เห็นแค่ช่วงต้นไม่กี่บรรทัดก่อนถูกตัดด้วยปุ่มแสดงเพิ่มเติม ประโยคเปิดกับลิงก์หลักต้องอยู่ตรงนั้น ที่เหลือคือเนื้อที่ให้ระบบอ่าน |
| เวลาที่ระบุในคำอธิบาย | ไม่ระบุ | รายการเวลาในคำอธิบายจะกลายเป็น chapter ให้ตรงกับตาราง key moment ในขั้นที่ 7 |
| แฮชแท็ก | ใช้ประมาณ 4-6 อันพอ | **เกินเพดานที่แพลตฟอร์มกำหนดเมื่อไร แฮชแท็กทั้งหมดบนวิดีโอนั้นถูกทิ้งทั้งชุด ไม่ใช่ทิ้งเฉพาะส่วนเกิน** ห้ามใส่เผื่อ |
| ช่อง tag | ใส่เฉพาะคำที่คนสะกดผิด | ช่องนี้มีไว้ดักคำที่คนพิมพ์ผิดหรือสะกดต่างของแบรนด์และหัวข้อ ไม่ใช่ช่องใส่คีย์เวิร์ด |

## ขั้นที่ 6 การผลิตข้อความตามเวลา

**ของสามอย่างนี้คนละอย่างกัน อย่าเรียกปนกัน**

- **subtitle** คือบทพูดที่ถอดออกมา ส่วนใหญ่ทำให้คนที่ไม่ได้พูดภาษาในเสียง
- **caption** คือ subtitle บวกคำบรรยายเสียงที่ไม่ใช่คำพูด เช่นเสียงดนตรี เสียงประกอบ
  และการเปลี่ยนคนพูด สำหรับคนที่ไม่ได้ยินเสียง **ถ้ามีงบทำได้อย่างเดียว ให้ทำ caption
  เพราะครอบคลุมทั้งสองกลุ่ม**
- **transcript** คือข้อความเต็มบนหน้าเว็บ กติกาคือระบุว่าใครพูด เว้นวรรคตามหัวข้อที่เปลี่ยน
  และให้คนตรวจแก้อีกรอบ ตัวมันทำหน้าที่เป็นข้อความใต้ตัวเล่นในขั้นที่ 2 ไปด้วย

กฎการผลิต

1. เลือกรูปแบบไฟล์ที่แพลตฟอร์มปลายทางรับได้เองโดยตรง แล้ว**แปลงจากไฟล์ต้นฉบับเดียว**
   ไม่ใช่ไปนั่งแก้สำเนาของแต่ละแพลตฟอร์มแยกกัน
2. **ระบบสร้างซับอัตโนมัติทำงานเฉพาะกับวิดีโอที่สั้นกว่าหนึ่งชั่วโมง**
   วิดีโอที่ยาวกว่านั้นจะไม่ได้ซับอัตโนมัติเลย ให้ตั้งงบทำซับด้วยคนไว้ตั้งแต่ต้น
3. การให้ระบบจับบทที่มีอยู่แล้วเข้ากับเสียง จะเพี้ยนตามคุณภาพเสียง เสียงพูดทับกัน และการพูดปนภาษา
   **ต้องกดดูจริงตรวจว่าตรงจังหวะก่อนเผยแพร่ทุกครั้ง**
4. **บันทึกไฟล์ข้อความตามเวลาเป็น UTF-8 ทุกไฟล์** ซับภาษาไทยและภาษาที่ไม่ใช่ละติน
   จะเพี้ยนเงียบ ๆ ถ้าใช้การเข้ารหัสแบบเก่า **ซับที่เพี้ยนแย่กว่าไม่มีซับ**
   ให้ตรวจการเข้ารหัสที่ระดับไฟล์ ไม่ใช่กวาดตาดูในโปรแกรมแก้ไข

## ขั้นที่ 7 ตาราง key moment

ทำตารางสองคอลัมน์ คือเวลากับป้ายชื่อ ให้กับวิดีโอทุกตัว
**ให้ใส่มาเกินไว้** คือลงทุกจุดที่เปลี่ยนหัวข้อจริง เพราะพื้นที่แสดงผลหยิบไปแสดงแค่บางส่วน
และเราคุมไม่ได้ว่าเขาจะหยิบอันไหน ป้ายชื่อเป็นวลีสั้น ๆ ที่ตรงกับสิ่งที่คนค้นอยากกดข้ามไปดู
เอาตารางเดียวกันนี้ไปใส่เป็นรายการเวลาในคำอธิบายตามขั้นที่ 5 ด้วย chapter กับ key moment จะได้ตรงกัน

## ขั้นที่ 8 ตัวช่วยให้คนดูต่อ

- **end screen** แพลตฟอร์มกำหนดว่าวิดีโอต้องยาวอย่างน้อย 25 วินาทีถึงจะใส่ end screen ได้
  และ end screen กินพื้นที่ช่วง 5 ถึง 20 วินาทีสุดท้าย **ให้เขียนบทช่วงท้ายนั้นเป็นส่วนปิดท้าย
  ไม่ใช่เนื้อหาสำคัญ** เพราะมันจะถูกทับ
- **พารามิเตอร์ playlist** ใส่ไว้ในลิงก์วิดีโอที่ส่งออกไป คนกดแล้วจะได้เริ่มเป็นชุด ไม่ใช่ดูจบตัวเดียว
- **รายงานแยกตามความยาว** วิดีโอสั้นรายงานเป็นเปอร์เซ็นต์ที่ดู วิดีโอยาวรายงานเป็นนาทีรวมที่ถูกดู
  **ห้ามเอาสองเส้นนี้ขึ้นกราฟเดียวกัน** เพราะสเกลคนละแบบ จะทำให้ฝั่งใดฝั่งหนึ่งดูอ่อนเกินจริง

## ขั้นที่ 9 การวัดผล

- **นิยาม engaged view ให้ใช้ตามที่แพลตฟอร์มโฆษณาประกาศไว้เอง**
  ซึ่งมีทั้งเกณฑ์เวลาดูขั้นต่ำและกรอบวันที่ conversion ต้องเกิดขึ้น
  ให้เปิดเอกสารของแพลตฟอร์มแล้วใช้ค่านั้น **ห้ามตั้งเกณฑ์เอง และห้ามเอาไปรวมเป็นตัวเลขเดียว
  กับ conversion ที่มาจากการคลิก** เพราะคนละนิยาม
- **แยกกลุ่มช่องทาง** ให้มีช่องทางวิดีโอแบบไม่จ่ายเงินกับแบบจ่ายเงินแยกกัน
  traffic จากแพลตฟอร์มจะได้ไม่ไปกองรวมอยู่ในถุง referral
- **ใส่พารามิเตอร์แคมเปญในทุกลิงก์** ทั้งลิงก์ในคำอธิบาย ในการ์ด และใน end screen
  **ลิงก์ที่ไม่ใส่พารามิเตอร์คือรูรั่วของการวัดผล ไม่ใช่ทางเลือกที่เป็นกลาง**

## ขั้นที่ 10 checklist จัดหน้าช่อง

**ช่องเป็นพื้นที่ค้นหาในตัวมันเอง ไม่ใช่โฟลเดอร์เก็บไฟล์ที่อัปโหลดไว้**
จัดตาม checklist นี้ แล้วบันทึกผ่านหรือไม่ผ่านรายข้อลงไฟล์ส่งมอบ

| # | หัวข้อ | กฎ |
|---|---|---|
| 1 | playlist | จัดตามกลุ่มหัวข้อ และถือว่าแต่ละ playlist เป็นของที่ถูกค้นได้ คือมีชื่อที่มีคำค้น มีคำอธิบายจริง และเรียงลำดับการดูอย่างตั้งใจ **ไม่ใช่เรียงตามวันที่อัป** |
| 2 | ส่วนต่าง ๆ ของหน้าช่อง | จัดหน้าช่องรอบ playlist และซีรีส์ที่แข็งที่สุด คนที่เพิ่งเข้ามาจะได้เห็นคลังของ ไม่ใช่กองไฟล์ที่เพิ่งอัป |
| 3 | แยกคนที่ติดตามแล้วกับยังไม่ติดตาม | คนยังไม่ติดตามให้เห็นคลิปแนะนำช่องสั้น ๆ ที่บอกว่าช่องนี้ทำเพื่อใครและทำไมต้องกดติดตาม ส่วนคนที่ติดตามแล้วให้เห็นเนื้อหาอีกชุด |
| 4 | ชื่อช่อง | ตรงกับชื่อแบรนด์ที่ใช้บนเว็บและบนโปรไฟล์อื่นทุกที่ **แบบตรงตัวอักษร** เพื่อให้ระบบเชื่อมได้ว่าเป็นเจ้าเดียวกัน |
| 5 | ไอคอนและภาพหัวช่อง | ไอคอนต้องอ่านออกตอนย่อเป็นรูปโปรไฟล์เล็ก ๆ ภาพหัวช่องต้องบอกว่าเราขายคุณค่าอะไร และรอดจากการถูกครอบตัดในทุกขนาดจอ |
| 6 | คำอธิบายช่อง | เอาคำหลักของหัวข้อไว้ต้น เพราะโผล่ในผลค้นแค่ช่วงต้น |
| 7 | ผูกกับเว็บไซต์ | กรอกลิงก์เว็บทางการในหน้าช่อง และลิงก์กลับจากเว็บมาที่ช่องพร้อมชวนกดติดตาม ทั้งสองฝั่งจะได้ยืนยันกันเอง |

## ขั้นที่ 11 ตรวจซ้ำหลังเผยแพร่

**เผยแพร่แล้วยังไม่จบ จบเมื่อถูกเก็บเข้าดัชนี** ปิดงานทุกครั้งด้วยวงรอบนี้

1. **ยืนยันว่าระบบเห็น** หลังเผยแพร่ ให้ดูรายงานการเก็บดัชนีวิดีโอใน Search Console รายหน้า
   **ตัววิดีโอต้องขึ้นว่าถูกพบและถูกเก็บเข้าดัชนี ไม่ใช่แค่หน้าเว็บถูกเก็บ**
2. **เทียบอาการกลับไปที่ขั้นที่ 1** วิดีโอที่ถูกบล็อกหรือไม่ถูกเก็บ ทุกกรณีตรงกับข้อใดข้อหนึ่งในด่านขั้นที่ 1
   ให้ไล่จากเหตุผลในรายงานกลับไปหาข้อนั้น แก้ แล้วขอให้เก็บดัชนีใหม่
3. **แก้แล้วต้องตรวจใหม่ทุกครั้ง** การแก้ที่ไม่ได้เปิดรายงานดูซ้ำ ถือว่ายังไม่ได้ยืนยัน
   ให้วนจนกว่ารายงานจะขึ้นว่าเก็บเข้าดัชนีแล้ว
4. **ให้ผลการวัดเป็นคนตัดสินเรื่องที่ฝาก** ถ้าวิดีโอที่โฮสต์เองไม่เข้าดัชนีสักที
   ขณะที่ตัวที่ฝากแพลตฟอร์มเข้าได้ **ให้กลับไปใช้ฝากแพลตฟอร์มตามขั้นที่ 4**
   เรื่องที่ฝากไว้ที่ไหนตัดสินด้วยผลที่วัดได้ ไม่ใช่ด้วยการเถียงกัน

## ขั้นที่ 12 เขียนไฟล์ส่งมอบ

ชื่อไฟล์ต้องเป็นแบบนี้

```
work/{domain}/(00-baseline|01-current)/{domain}_seo-video_{YYYY-MM-DD}.md
```

1. **ผลด่านคุ้มค่าในขั้นที่ 0** คำไหนมีวิดีโอในผลค้นบ้าง
2. **ผลด่านตัดสิทธิ์ในขั้นที่ 1** ผ่านหรือไม่ผ่านรายข้อ พร้อมวิธีแก้ข้อที่ไม่ผ่าน
3. **ตารางหน้าและวิดีโอ** หน้าไหนมีวิดีโออะไร ผิดกฎหนึ่งวิดีโอต่อหนึ่งหน้าตรงไหน
4. **ข้อมูลที่ต้องกรอก** ชื่อ คำอธิบาย ตาราง key moment เขียนให้พร้อมวางได้เลย
5. **รายการงานผลิต** ซับ transcript ภาพปก พร้อมบอกว่าใครทำและต้องใช้อะไร
6. **checklist หน้าช่อง** ผ่านหรือไม่ผ่านรายข้อ
7. **สิ่งที่ต้องตรวจซ้ำหลังเผยแพร่** และส่งต่อให้สกิลไหน

## การวางไฟล์ผลลัพธ์

สกิลนี้อยู่ในชุดที่ใช้โครงโฟลเดอร์ของสกิล `new-workspace-lite`

1. ผลลัพธ์ทุกไฟล์อยู่ใต้ `work/{domain}/`
2. ถ้า `work/{domain}/00-baseline/` ยังไม่มีไฟล์หัวข้อเดียวกัน ให้เขียนลง `00-baseline/` ถ้ามีแล้ว ให้เขียนลง `01-current/`
3. เขียนเสร็จ ให้เพิ่มบรรทัดลงตารางใน `work/{domain}/CHANGELOG.md` ว่าวันที่ รันสกิลอะไร ได้ไฟล์อะไร
4. ถ้ายังไม่มี `work/{domain}/` ให้แนะนำผู้ใช้รันสกิล `new-workspace-lite` ก่อน ห้ามสร้างโครงเองแบบอื่น

## ขอบเขต ใครดูอะไร

**สกิลนี้ดู** ด่านตัดสิทธิ์ เงื่อนไขระดับหน้า เงื่อนไขของภาพปก การเลือกที่ฝากวิดีโอ
ข้อมูลบนแพลตฟอร์ม การผลิตซับและ transcript ตาราง key moment ตัวช่วยให้คนดูต่อ
นิยามการวัดผล การจัดหน้าช่อง และวงรอบตรวจซ้ำหลังเผยแพร่

| เรื่อง | ใครดู |
|---|---|
| สร้าง JSON-LD ที่บรรจุข้อมูลวิดีโอ | `aiso-schema-lite` หรือ `seo-schema-lite` |
| โครงและรูปแบบของ video sitemap | `sitemap-architecture-lite` |
| ตรวจว่า sitemap บนเว็บจริงใช้งานได้ไหม | `technical-audit-lite` |
| จัดไฟล์ภาพปกให้ขนาดและน้ำหนักถูก | `seo-image-optimizer-lite` |
| หาคำค้นเป้าหมายมาใช้ในขั้นที่ 0 | `seo-keyword-research-lite` |

**ลำดับในสายงาน** ทำหลังจากยืนยันแล้วว่าคำค้นเป้าหมายมีวิดีโอในผลค้น
ระหว่างทางส่งข้อกำหนด markup ให้สกิล schema และส่งสเปกภาพให้ `seo-image-optimizer-lite`
แล้วปิดงานด้วยวงรอบตรวจซ้ำในขั้นที่ 11

## กฎ

- **ถ้าดึงข้อมูลไม่สำเร็จ ให้เขียนว่า `ตรวจไม่ได้` ห้ามเขียนว่า `ไม่มี`** สองคำนี้คนละความหมาย ถ้าเขียนผิดผู้ใช้จะสรุปกลับด้าน
- **ทำได้บางส่วนต้องส่งส่วนนั้นเสมอ** ห้ามส่งตารางที่ทุกช่องว่าง และห้ามปฏิเสธทั้งงานเพราะขาดข้อมูลบางอย่าง ให้ติดป้ายว่าข้อไหนยืนยันแล้ว ข้อไหนต้องยืนยันเพิ่ม · การใช้ข้อจำกัดเป็นข้ออ้างไม่ส่งงาน ไม่ใช่ความซื่อสัตย์
- **ห้ามให้คะแนนวิดีโอเป็นตัวเลขหรือเกรด** ใช้ ผ่าน ควรดู มีปัญหา ตรวจไม่ได้
- **ห้ามเดาตัวเลขยอดดู เวลาที่คนดู หรือส่วนแบ่งอันดับ** ไม่มีข้อมูลจากรายงานจริงให้เขียนว่ายังไม่ได้วัด
- **ห้ามข้ามด่านในขั้นที่ 1 ไปทำงานข้อมูลประกอบ** หน้าที่ยังติดข้อตัดสิทธิ์ ทำเท่าไรก็ไม่ขึ้น
- **ห้ามสรุปว่าเผยแพร่แล้วคืองานเสร็จ** ต้องเห็นรายงานว่าเก็บเข้าดัชนีแล้วจึงปิดงาน
- **ห้ามเขียนไฟล์ซับด้วยการเข้ารหัสอื่นนอกจาก UTF-8** และห้ามส่งซับที่ยังไม่ได้กดดูจริง
- **ห้ามแก้ไฟล์บนเว็บจริงหรืออัปโหลดขึ้นแพลตฟอร์มเอง** สกิลนี้เตรียมของและเขียนรายงานเท่านั้น
- ถ้าข้อมูลไม่พอให้เขียนตรง ๆ ว่าไม่พอ และบอกว่าต้องใช้อะไรเพิ่ม
